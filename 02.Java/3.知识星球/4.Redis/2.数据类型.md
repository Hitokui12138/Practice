## Redis数据类型
1. 5 种基础数据类型：String（字符串）、List（列表）、Set（集合）、Hash（散列）、Zset（有序集合）。
2. 3 种特殊数据类型：HyperLogLog（基数统计）、Bitmap （位图）、Geospatial (地理位置)。
### 1. String (动态字符串)
1. 增改, SET key value
2. 查, GET key
3. 删, DEL key, 这个命令是通用的
4. 其他
    1. 是否存在, EXISTS key
    2. 字符串长度, STRLEN key
    3. 计数器, (常用)
        - INCR key
        - DECR key
    4. 过期时间
        1. 设置过期时间
            - EXPIRE key 60
            - SETEX key 60 value
        2. 查看过期时间, TTL key
5. 有什么用?
    1. 缓存Session,Token, 序列化后的对象
        - 对象的结构简单, 且频繁读写时, 使用String存储
    2. 需要计数的场景
    3. 不推荐: 分布式锁, 有更好的方法
### 2. List (双向链表)
1. 增, LPUSH/RPUSH key v1 v2 v3...
2. 改, LSET k index v
3. 查, LRANGE key start end, 0表示队首, -1表示队尾
4. 删, LPOP/RPOP key
5. 链表长度, LLEN key
6. 有什么用?
    1. 信息流: 最新文章, 最新动态
    2. 不推荐: 消息队列
7. 延伸问题
    - 为什么用跳表?
### 3. Hash (Map<String, String>)
- Map名为key, 键值对为 field-value
1. 增, 
    1. HMSET key f1 v1 f2 v2 ...
    2. HSETEX key f v , 当且仅当指定f不存在时才会插入
2. 改, HSET k f v 
3. 查
    1. HGET k f
    2. HMGET key field1 field2 ...
    3. HGETALL key
4. 删, HDEL key field1 field2 ...
5. 其他
    1. 查询字段是否存在, HEXISTS key field
    2. 字段数量, HLEN key
6. 应用
    - 存储对象数据
        - 要求频繁操作对象的部分字段或节省内存, 比如购物车的商品需要频繁修改
### 4. SET (无序, 不重复)
1. 增, SADD key member1 member2 ...
2. 改, 没有?
3. 查, 
    - SMEMBERS key, 只能查所有
    - SRANDMEMBER key count, 随机查, 不删除
4. 删, SPOP key count, 随机查, 会删除
5. 其他
    1. 是否存在, SISMEMBER key m
    2. Set元素数量(常用), SCARD key
6. 交集, SINTER key1 key2 ...
7. 并集, SUNION key1 key2 ...
8. 差集, SDIFF key1 key2 ...
9. 应用场景
    1. 需要存放`不重复`且`精确`的数据
        1. 点赞数
        2. 像是网站UV统计这样可以不那么精确的情况, 可以使用HyperLogLog
    2. 需要计算 交集, 并集, 差集的场景
        1. 共同好友, 共同关注(交集)
        2. 可能认识, 音乐推荐(差集)
    3. 需要随机获取/删除一个数据元素的场景
        1. 抽奖系统, SPOP, 会删除成员
        2. 随机点名, SRANDMEMBER, 不删除成员

### 5. SORTED SET(排行榜)
- 给每个成员加一个分数用于排序
1. 增, ZADD key score1 m1 s2 m2
    1. ZADD k NX s m , 仅添加新元素
2. 改, ZADD key s3 m3
    1. ZADD k INCR 10 m , 给某个元素加分
3. 查, 只能查所有 
    1. ZRANGE key start end, 分数从低到高
    2. ZREVRANGE key start end, 分数从高到低
    3. ZREVRANK key member, 获得排名(分数从高到低)
4. 删, 没有删?
5. 交集, 并集, 差集
    1. ZINTERSTORE
    2. ZUNIONSTORE
    3. ZDIFF
6. 应用场景
    1. 排行榜
        - 礼物榜, 微信步数排行榜, 话题热度排行榜
    2. 带有优先级的任务队列

### 6. BitMap 位图 (存储状态信息 0/1)
- Bitmap 存储的是连续的二进制数字（0 和 1）, 只需要一个 bit 位来表示某个元素对应的值或者状态, 8 个 bit 可以组成一个 byte
-  Bitmap 看作是一个存储二进制数字（0 和 1）的数组，数组中每个元素的下标叫做 offset（偏移量）
1. 增, SETBIT key 7 1 (位从0开始)
    - 00000001, 位可以往后无限拓展, 但是超出第一个字节后, 会创建新的字节
    1. 若再SETBIT key 8 1
    - 00000001 00000001, 因为8是第二个字节的最低位 
2. 改, SETBIT key 8 1
3. 查, GETBIT mykey 7
4. 删, 就是设为0
5. 统计1的数量, BITCOUNT key
6. 应用场景
    1. 用户签到情况/活跃 31天哪些天签到了,
    2. 用户行为统计, 是否点赞过某个视频
