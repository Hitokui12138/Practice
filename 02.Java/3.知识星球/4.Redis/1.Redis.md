# Redis
- Redis的本质: `空间换时间` 这一经典性能优化策略的运用
- 用更多的存储空间来存储一些可能重复使用或计算的数据，从而减少数据的重新获取或计算的时间。
1. 类似的实现
    1. 索引
        - 将某些列或字段按照一定的排序规则组织成一个单独的数据结构
    2. CDN(内容分发网络)
        - 静态资源分发到多个边缘节点以实现就近访问
## 本地缓存 与 分布式缓存
1. 本地缓存方案
    1. JDK自带的 HashMap, ConcurrentHashMap
        - 一个稍微完善一点的缓存框架至少要提供：`过期时间`、`淘汰机制`、`命中率统计`这三点
    2. Ehcache, Guava Cache, Spring Cache, Caffeine
2. 分布式缓存 Distributed Cache
    - 分布式缓存脱离于应用独立存在，多个应用可直接的共同使用同一个分布式缓存服务
    1. 缺点
        - 系统复杂性增加, 系统开发成本往往会增加
    2. 官方推荐生产环境使用 Linux 部署 Redis。
3. 为什么选择Redis而不是本地缓存
    1. 数据一致性
    2. 可以独立部署, 内存空间可拓展
    3. 可以持久化, 数据不易丢失
    4. 提供RedisCLI 管理工具
    5. 支持多种数据结构和功能
## Redis为什么这么快?
1. 纯内存操作
    - 操作内存的访问速度是纳秒级别，而传统数据库频繁读写磁盘的速度是毫秒级别
2. 单线程事件循环配合 I/O 多路复用技术
    - 让单个线程可以同时处理多个网络连接上的 I/O 事件（如读写），避免了多线程模型中的上下文切换和锁竞争问题
3. 优化的内部数据结构 
    - Redis 提供多种数据类型（如 String, List, Hash, Set, Sorted Set 等），其内部实现采用高度优化的编码方式（如 ziplist, quicklist, skiplist, hashtable 等）。
4. 简洁高效的通信协议 (Simple Protocol - RESP)
    - Redis 使用的是自己设计的 RESP (REdis Serialization Protocol) 协议。这个协议实现简单、解析性能好，并且是二进制安全的

## Redis能做什么
0. 缓存数据
1. 分布式锁
    - https://javaguide.cn/distributed-system/distributed-lock.html
2. 限流
    - Redis + Lua 脚本的方式来实现限流
3. 消息队列, 延时队列(不推荐)

## Redis持久化机制
1. 快照（snapshotting，RDB）
2. 只追加文件（append-only file, AOF）
3. RDB 和 AOF 的混合持久化(Redis 4.0 新增)
