## 1. 概念
### 1.1 进程, 线程, 协程
1. `进程`(车间), 系统`运行程序的基本单位`
    - CPU 密集用多进程
    - 进程是程序的一次执行过程，JVM就是一个进程
2. `线程`(工人), 一个进程包含多个线程, 是`CPU调度的最小单元`
    - 适合IO 密集型任务, `在同一时间需要完成多项任务时`就需要用到线程
    - 多个线程共享进程的堆和方法区资源
    - 每个线程有自己的程序计数器、虚拟机栈和本地方法栈
3. `协程`(任务清单)
    - 适合超高并发
    - 一个工人（线程）可以拿着多个任务清单
    - 执行与否, 顺序, 均由工人控制, 进程 / 线程由操作系统内核调度，协程由用户代码调度（更灵活）。
### 1.2 并行, 并发
- 描述执行多个任务的方式
1. `并行` Parallelism, 多个任务真正`同时执行`(真同时)
    - `必须多核 CPU`, 比如多核计算密集型任务
    - 提高任务执行速度
2. `并发` Concurrency, 多个任务`交替执行`(假同时)
    - `单核 CPU` 即可实现, 比如单线程处理多 IO 请求
    - 提高资源`利用率`
### 1.3 同步,异步
- 描述任务的执行方式和结果获取方式
1. `同步` Synchronous
    - 调用方 必须`等待` 被调用方 完成任务，期间不能做其他事。
2. `异步` Asynchronous
    - 调用方 发起任务后, 不用等待, 可以继续做别的事, 任务完成后通过`回调/事件`获取结果
### 1.4 阻塞（Blocking）vs 非阻塞（Non-blocking）
- 描述程序在等待某个操作完成时的状态, 挂起/非挂起
1. `阻塞` Blocking
    - 一个线程执行时, 其他线程拿不到锁，必须`等待`
    - 阻塞式的解决方案：synchronized，lock
2. `非阻塞` Non-blocking
    - 一个线程执行时, 其他线程拿不到锁, 可以先去做别的
    - 非阻塞式的解决方案：原子变量
3. 同步 / 异步 ≠ 阻塞 / 非阻塞
    1. 同步可以是阻塞（如普通 time.sleep），也可以是非阻塞（如轮询检查任务状态）；
    2. 异步通常是非阻塞的（如 asyncio.sleep）。

## 3. synchronized (隐式锁内置锁，对象锁)
- 优点: 语法简洁、无需手动释放
- 同一时刻至多只有一个线程能持有`对象锁`，其它线程获取这个对象锁时会阻塞
### 3.1 synchronized 使用
- 同步锁是 “思想 / 概念”，synchronized 是 Java 中实现这种思想的具体工具
1. synchronized关键字
    - 同一时间只有一个线程执行这段代码
    1. synchronized可以修饰什么
        1. 同步代码块, `synchronized (同步锁){...}`
        2. 同步方法, `synchronized void func(){...}`
        3. 静态同步方法, `static synchronized void func(){...}`
    1. 哪些代码应该放入同步代码块?哪些不应该
        1. 不要将整个while循环放入同步代码块
        2. 可以将处理函数放入
2. 什么能作为同步锁
    - 同步监听对象/同步锁/同步监听器/互斥锁 都是同步锁
    - 同步代码块想用哪个都可以
    1. 对象类型
        1. new Student()
        2. new Object()
        3. this, 同步方法用的是这个
    2. 类 类型
        1. Student.class, 静态同步方法用的是这个
        2. Object.class
### 3.4 synchronized的等待唤醒机制
- wait(), notify(), notifyAll()
1. Thread.sleep() 与 object.wait()的区别
    1. Thread.sleep(), 静态方法, 让当前线程休眠指定时间，`不会释放锁`
        - 时间到自动唤醒, 唤醒后直接进入 RUNNABLE（就绪）状态
    2. this.wait(), 让线程进入`等待状态`，必须在`同步代码块中`调用，且会`释放锁`
        - `synchronized (this){ this.wait(); }`
        - 可被 notify()/notifyAll() 唤醒；2. 超时自动唤醒; 需重新竞争锁
2. notify() `唤醒的是在锁上wait()的线程`
    - 在main()方法中调用 task.notify()方法唤醒`单个线程`
        - 即使有多个线程, 也`只能唤醒一个线程`
    - 和wait()一样, 也需要写在同步代码块中
        - 上面的this表示`task实例`, 因此这里用task调用notify()
        - `synchronized (task){ task.notify(); }`
3. notifyAll()
    - 唤醒所有等待的线程
    - - `synchronized (task){ task.notify(); }`
### 3.5 生产者消费者模型 (wait() notify()应用)
1. 生产者线程 ,消费者线程
    1. 数据类Data
    2. 生产者Producer implement Runnable
        ```java
        @Override
        public void run(){
            while(true){
                synchronized(data){
                    // 1. 若数据为null， 生产数据
                    // 2. 调用notify()方法
                    data.notify();
                    // 3. 当前线程等待
                    data.wait();
                }
            }
        }
        ```
    3. 消费者 Consumer implement Runnable
        - 里面也是一样的
2. 原理总结
    1. 生产者生产数据时, 消费者`等待`
        - 编写一个数据类，然后以`data实例`作为同步锁
    2. 生产者生产完毕, 唤醒消费者进行消费, 随后生产者等待
        - `synchronized (data){ 生产; data.notify(); 然后data.wait()}`
    3. 消费者消费完毕后, 唤醒生产者线程, 如此反复
        - `synchronized (data){ 消费; data.notify(); 然后data.wait()}`
### 3.3 死锁
1. 概念
    - 多个线程`互相持有对方需要的锁`，且`都不肯释放自己的锁`，导致所有线程都陷入`永久阻塞`的状态。
2. 实现死锁的条件
    1. 两个线程分别持有不同的锁 
        - 两个类分别有两个静态同步方法(同步锁为 ClassA.class, ClassB.class)
    2. 两个持有不同锁的线程争夺对方的锁
        - 两个静态方法中(各自持有自己的锁)分别调用对方(争夺对方的锁)


## 4. ReentrantLock (显式锁)
- 也是用于线程同步, 比synchronized更灵活, 用于复杂场景
0. 隐式锁与显式锁的区别
    - 可以`手动地`获取锁和释放锁
1. 顶层接口 Lock, 定义了6种方法
    1. 获取锁
        1. lock()，阻塞式获取锁
        2. boolean trylock()，非阻塞式获取锁
        3. trylock(long time, TimeUnit unit)
        4. lockInterruptibly(), 获取可中断等待的锁
    2. 释放锁
        4. unlock()
    4. 条件 (主要用于 wait, notify)
        6. newCondition()
2. Lock的常见子类 (这些都是可重入锁)
    1. `ReentrantLock`, 可重入锁
    2. `ReentrantReadWriteLock.ReadLock`, 读锁
    3. `ReentrantReadWriteLock.WriteLock`, 写锁
### 4.1 ReetantLock 的使用
1. 基本使用
    1. 在Task类中定义成员变量
        - `private Lock lock = new ReetrantLock()`
    2. 在run()方法中 
        ```java
        @Override
        public void run(){
                lock.lock(); //1. 阻塞式获取锁
                try{...} //2. 执行想同步的方法
                lock.unlock(); //3. 释放锁 
        }
        ```
    3. 新建两个线程， 分别执行run()方法
### 4.2 阻塞式与非阻塞式
#### 4.2.1 阻塞式获取锁
- 只有一个锁，当一个线程执行时, 其他线程`等待`获取锁
    - 当线程拿不到锁时，只要是等待，就是阻塞
- 上面就是阻塞式，阻塞式的解决方案：synchronized，lock
#### 4.2.2 非阻塞式获取锁
- 一个线程执行时, 其他线程拿不到锁, 可以`先去做别的`
- 非阻塞式的解决方案：原子变量
- 核心是 `boolean tryLock()`
1. 具体用法与lock()不同
    ```java
    @Override
    public void run(){
            if(lock.tryLock()){
                // 锁可用时
                try{
                    // 同步代码
                }finally{
                    lock.unlock(); //释放锁
                }
            } else {
                // 锁不可用时
            }
    }
    ```
2. 两个线程同时运行
    - 一个执行了同步代码， 另一个因为没拿到锁，`没有执行同步代码`
2. 因此提供一个重载方法， `lock.trylock(3, TimeUnit.SECONDS)`
    - 可以指定让线程等待一段时间, 若期间内能拿到锁则返回true
    - 还是拿不到锁就返回false
### 4.4 中断等待锁的过程
1. 可中断 与 不可中断
    1. synchronized 和 lock()， 属于等待过程`不可被中断`
        - 可以调用thread.interupt()方法， 但是不会中断
        - `拿到锁之后`， 报错 InteruptedException
    2. lockInterruptibly(), 属于可中断锁
        ```java
        try{
            lock.lockInterruptibly();
        } catch (InterruptedException e){
            //中断后的处理
        }
        //同步代码， finally解锁
        ```
### 4.3 Lock的等待唤醒机制

2. 如何使用 await()

    2. lock.lock()

3. 如何使用 signal()
    1. 在main()方法中
        1. 上面的代码

        3. condition.signal() 唤醒单个线程

### 4.4 Condition的应用 生产者消费者
#### 4.4.1 定义Data类
1. 成员变量
    1. Lock lock = new ReentranitLock();
    2. Condition producerC = lock.newCondition();
    3. Condition consumerC = lock.newCondition();
2. setMessage()
    1. lock.lock()
    2. while(this.msg != null)
        1. producerC.await(), 有数据则让生产者等待
    3. 否则设置msg, 然后 consumerC.signalAll() 唤醒所有消费者
    4. finally lock.unlock()
3. getMessage()
    1. lock.lock()
    2. while(this.msg == null)
        1. consumerC.await(), 没有数据则让消费者等待
    3. 否则 producerC.signalAll() 唤醒所有消费者, 然后返回数据
    4. finally 还需要数据重制, 然后 lock.unlock()
#### 4.4.2 定义生产者
1. 直接while(true) 无限生产
2. 里面调用data.setMessage()即可
#### 4.4.3 定义消费者
1. 直接while(true) 无限消费
2. 里面调用data.getMessage()即可
### 4.5 读锁, 写锁
- 顶层接口是 `ReadWriteLock`读写锁
1. 读锁 (共享锁)， 用于读入数据
    - 同一时刻, `每个线程都能拿到锁`
    - 然后分别释放锁
2. 写锁 (独占锁)， 用于写入数据
    - 同一时刻, `只有一个线程能拿到锁`
#### 4.5.1 读锁 (共享锁)
1. 使用
    1. 定义读写锁
        - `ReadWriteLock rwLock = new ReentrantReadWriteLock(true);`
    2. 用rwLock取得读锁
        - `Lock readLock = this.rwLock.readLock()`
    3. 后面用法就一样了
2. 执行效果
    - 多个线程`不会相互阻塞`, 因为读锁是共享锁, 多个线程都能拿到锁
#### 4.5.2 写锁 (独占锁)
1. 使用
    1. 定义读写锁
        - `ReadWriteLock rwLock = new ReentrantReadWriteLock(true);`
    2. 用rwLock取得读锁
        - `Lock writeLock = this.rwLock.writeLock()`
    3. 后面用法就一样了
2. 执行效果
    - 多个线程`会相互阻塞`, 因为写是独占锁, 多个线程依次拿到锁
#### 4.5.3 读写锁的应用(用于实现高并发容器)
1. 高并发容器
    - 键值对(HashMap), 读写锁, 存, 取
2. 写入数据, 同时只有一个线程
    1. get方法(读操作)
        1. r.lock()
        2. return m.get(key)
        3. finally r.unlock()
3. 读取数据, 同时多个线程获取数据
    1. set方法(写操作)
        1. w.lock()
        2. return m.put(k, v)
        3. finally w.unlock()
### 4.6 对比synchronized(隐式锁)和Lock(显示锁)
1. 类型
    - 关键字; 接口
2. 使用格式
    - 三种; 固定一种
3. 释放锁的方式
    - 隐式的, 自动获取释放锁
    - 显示的, 手动获取释放锁
4. 连续释放锁的方式(嵌套)
    1. synchronized, LockA嵌套LockB嵌套LockC
        - 释放的时候先释放LockC
    2. Lock, 可以自由获取和释放
### 4.6 其他概念
1. 可重入锁, 不可重入锁
    - 即是否可以`重复进入同步作用域`， 重复使用的意思
    1. 可重入锁
        1. synchronized
        2. Lock的子类都是可重入锁
    2. 不可重入锁需要自己实现
2. 公平锁, 非公平锁
    - 这里指的是对于每个线程来说, 获取锁的机会是否均等
    1. 公平锁
        1. new ReentrantLock(true)
        2. new ReentrantReadWriteLock(true)
    2. 非公平锁
        1. synchronized
            - 基本都是第一个线程拿到锁, Tread-0
        2. new ReentrantLock(false) , 或者不传
        3. new ReentrantReadWriteLock(false), 或者不传
    3. lock.isFair(), 判断是不是公平锁
3. 等待唤醒工具类 LockSupport
    - 互斥锁
4. 读写锁升级版 StampedLock


## 5. ThreadLocal 线程本地变量
- 功能是操作存储在`当前线程中`的`专属的变量副本`
1. ThreadLocal的定位
    - 为每个线程创建`独立的变量副本`，线程只能访问`自己的副本`，不同线程之间`互不干扰`。
    - `每个线程专属的储物柜,用完记得 “锁门（remove）”`
2. ThreadLocal与Thread的关系
    - Thread负责存储数据
    - ThreadLocal负责操作数据
3. `class ThreadLocal<T>{...}`
    1. 4个方法
        1. withInitial(Supplier<? extends S> supplier)
            - 创建ThreadLocal实例， 不过也有构造器可以用
        2. get(), 获取 ThreadLocal`在当前线程中保存的`变量副本
            - 数据不是保存在ThreadLocal里面
        3. set(), 设置
        4. remove(), 用完记得删除
    2. 一个属性(重要)
        1. static class `ThreadLocalMap`{...}
            - 这个`内部类`主要用于维护线程的本地变量, 定制化的 HashMap
            - 线程内部有 ThreadLocalMap，key 是不同 ThreadLocal 对象，value 各自独立存储，`一条线程可以放无数个 ThreadLocal`
### 5.1 ThreadLocal具体用法
1. 创建ThreadLocal
    - ThreadLocal<String> tl = new TreadLocal<>();
    - 单个 ThreadLocal<String> 对象，当前线程只能存` 1 个 `String 值
    1. 如果想存多个数据
        1. 创建多个 ThreadLocal 变量
        2. 或者ThreadLocal<Map<String, Object>> tl， 变相保存多个数据
2. 重写Thread的run()方法
    - 设置ThreadLocal在`当前线程中`保存的`数据副本`
    - 例如 thread0 中设置 tl.set("Thread0")
    - thread1 尝试 tl.get()
3. 这个数据是不可能在其他线程中获得的
    - 只能在当前线程 tl.get()
    - thread1 获取的结果为 null
4. 最后删除数据副本 tl.remove()
    - 重要! 否则可能发生内存泄露
### 5.2 线程间 如何共享ThreadLocal
- 使用`InheritableThreadLocal`(可继承的线程本地变量)
1. 这里的继承, 不是线程B继承线程A
    - 实际上是 `在线程A中创建线程B`, 这样线程B就能共享线程A的InheritableThreadLocal了
### 5.3 线程池之间 如何共享ThreadLocal?
- 阿里出品了一个库: `TransmittableThreadLocal` extends InheritableThreadLocal

## 6. volatile 关键字 `JMM`
- 用来解决`内存可见性`问题
- 是Java 提供的轻量级同步机制，核心作用是：保证变量的 “可见性” 和 “有序性”，但不保证原子性。 
1. 什么是`内存可见性`问题
    1. 两个线程
        - `static boolean isStop = false` 
        - 一个线程while(!isStop){...}
        - 另一个线程过一秒后修改 isStop为true
    2. 问题
        - 第一个线程并不知道isStop的值改变了,因此不会停下来
    3. 总结
        1. `内存可见`,多个线程共享值时, 一个线程修改, 另一个线程能及时拿到最新的值
        2. `内存不可见`,另一个线程无法及时得到最新的值
    4. Java内存不可见原理
        1. 内存分为 `主内存`, 各个线程自己的`工作内存`
        2. 两个线程一开始会把isStop缓存到`工作内存`中
        3. 其中一个线程修改后, 会改变`主内存`, 但是并没有主动告诉另一个线程
2. volatile 修饰一个变量
    - `static volatile boolean isStop = false`,即可
    - 这个关键字可以解决内存可见性问题

## 7. JUC 原子类
- 一个或多个操作是不可中断的, 要么全部成功, 要么全部失败
1. i++ 是原子操作吗?
    - 多线程测试发现 i++ 并不是原子操作
    1. 其实有三步, 每一步都有可能被其他线程修改
        1. stpe1: 从主内存读取变量i
        2. step2: 执行i++
        3. step3: 将变量i写入主内存
2. `volatile int i` 能解决这个问题吗?
    - 不能, 原子性要求 “操作不可被中断”，而 volatile 仅保证单变量读写的可见性 / 有序性，无法约束多步复合操作的完整性
    1. volatile能确保`单次读写的正确性`
        1. step1, 读取的一定是主内存最新值
        2. step3, 修改后立即反映到主内存
        3. 这三步的顺序一定争取
    2. volatile的边界:
        - 无法阻止其他线程在这三步之间插入操作
3. `synchroined (this){i++}` 能解决这个问题吗?
    - 可以
4. 还可以用`原子类`来确保原子性
    - `AtomicInteger i = new AtomicInteger(0)`
    - 然后i++改成`i.getAndIncrement()`
5. 原子类
    - 一共12个, 但常用的很少
    1. XX类型原子类
        1. AtomicBoolean
        2. AtomicInteger
    2. XX 数组 类型原子类
        - AtomicIntegerArray


## 8.JUC 工具类(Java 同步器)
### 1. CountDownLatch ，模拟高并发场景， 秒杀场景，并行计算
1. `CountDownLatch`，倒计时门闩（让子线程等待）
    - 多个线程运行到`门闩`的地方，自动停下，等待倒计时
    - 倒计时到0时，门闩解除，线程从等待中被唤醒，继续执行
    ```java
    class Task implements Runnable{
        // 需要在task中定义成员变量
        private final CountDownLatch countDownLatch;
        void run(){
            //就位
            countDownLatch.await(); //在此等待
        }
    }

    // 模拟高并发场景
    mian(){
        // 设置倒计时为1
        CountDownLatch countDownLatch = new CountDownLatch(1);
        // 定义多个线程
        for(...){
            Task task = new Task(countDownLatch);
            Thread t = new Thread(task);
            t.start();// 启动线程，所有线程都会在门闩处等待
        }
        //做点别的
        countDownLatch.countDown(); //手动让倒计时减1
    }
    ```
2. 如果想模拟秒杀一件商品的场景
    ```java
    class Task implements Runnable{
        // 在task类中定义静态boolean类型标记
        private static boolean flg = false;
    }

    main(){
        // 定义静态同步方法
        private static synchronized void onlyOne(){
            if(!flg){
                sout("抢到了")；
                flg = true；
            }
        }
    }
    ```
3. 并行计算（让主线程等待）
    - 一个下载任务， 多个子线程负责下载， 一个主线程负责合并
    - 主线程会等待， 直到所有子线程下载完成
    1. 可以把CountDownLatch的计数器设置为线程数量，没完成一个就减1
    ```java
        class Task implements Runnable{
        // 需要在task中定义成员变量
        private final CountDownLatch countDownLatch;
        void run(){
            //下载任务
            countDownLatch.countDown(); //下载完成后计数器-1
        }
    }

    mian(){
        for(){
            //创建线程执行任务
        }
        countDownLatch.await(); //让主线程等待
        // 执行合并任务
    }
    ```

### 2. CyclicBarrier, 循环屏障
- 可以定义`多个屏障`，线程`多次等待`
- 10名玩家点击匹配后， 才进入选英雄界面； 10名玩家选好英雄后， 才进入游戏加载； 10名玩家全部完成加载后，游戏才开始
- 缺点： 参与者数量不可更改 -》 Phaser 可更改
1. 两种构造器
    1. CyclicBarrier(int parties, Runnable barrierAction)
        - barrierAction, 这是一个任务， 谁最后到达谁执行这个任务
    2. CyclicBarrier(int parties)
2. 游戏的例子
    ```java
    // 可以多次等待
    void run(){
        // 1. 开始匹配, 匹配成功
        cyclicBarrier.await(); //等待其玩家
        
        // 2. 开始选英雄， 选好英雄 
        cyclicBarrier.await(); //等待其玩家
    }

    main(){
        CyclicBarrier cyclicBarrier = new CyclicBarrier(10, new Runnable(){
            @Override
            run(){
                sout("最后一位玩家：" + Thread.currentThread().getName());
            }
        })
        //创建线程执行任务
    }
    ```

### 4. Semaphore,信号量， 许可证
- 通过给线程发放许可证， 来`限制同一时刻`访问资源的线程数量
- 类似于 办事窗口 数量
1. 构造
    1. int permits， 许可证/窗口 数量
    2. boolean fair， 可选参数
        - 公平： 等待时间长的，优先发放许可证
        - 不公平： 相反
2. 使用
    ```java
    void run(){
        try{
            semaphore.acquire(); //尝试获取许可证
        } finally{
            semaphore.release(); //释放许可证
        }
    }
    ```
