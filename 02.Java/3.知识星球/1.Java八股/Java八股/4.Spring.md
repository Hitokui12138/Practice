1. Spring事务的传播行为有哪些？你在“下单扣库存+核销券+落订单快照”里用哪种？为何？
    1. Spring 事务传播行为定义了「一个有事务的方法调用另一个方法时，事务如何传递」，核心常用的有 5 种
        1. REQUIRED（默认，加入 / 新建事务）：如果当前有事务，就加入该事务；没有就新建事务（最常用）；
        2. REQUIRES_NEW（新建独立事务）：不管当前有没有事务，都新建独立事务，原事务暂停，新事务执行完再恢复；
            - 优惠券核销是用户权益相关操作，需独立保障
    2. 为什么同类内部调用事务不生效
        - Spring 事务是基于动态代理实现的，同类方法内部调用（比如createOrder()调用本类的deductStock()），会直接走方法栈调用，不会经过代理类，导致@Transactional注解失效。
        1. 方案 1：拆分到不同类（推荐，最符合规范）
            1. 把需要事务的方法拆分到独立的 Service 类，通过 @Autowired 注入调用，触发代理逻辑。
        2. 优势：代码解耦，符合微服务单一职责，是生产环境首选；
