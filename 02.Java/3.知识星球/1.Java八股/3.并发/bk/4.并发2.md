# 线程池 (池化技术)
- 阿里Java规范禁止手动创建线程
1. 为什么使用线程池
    1. 没有线程池的时候
        1. 创建任务, Runnable
        2. 创建线程, Thread(task)
        3. 启动线程, thread.start()
    2. 问题:
        1. 一个线程只能执行一个任务, 多个任务的时候, 只能创建更多线程
        2. 线程执行完毕后, 立即销毁
            - `不能复用`, 创建销毁线程很`消耗资源`
2. 线程池如何工作?
    1. 可以创建多个任务, task1,2,3
    2. 创建线程池, 这里测试 只有一个线程的线程池`newSingleThreadExecutor`
    3. 提供并执行任务, 可以多次提交
        - threadPool.execute(task1);
        - threadPool.execute(task2);
    4. 记住要关闭线程池
        - `threadPool.shutdown()`
3. 线程池的优点
    1. 降低资源消耗:
        - 通过重复利用已创建的线程, 降低反复创建/销毁的资源消耗
    2. 提高响应速度: 
        - 提交任务时, 任务无须等待线程创建即可立即执行
    3. 提高线程的可管理性
        - 线程池可以统一进行分配, 调优, 监控
## 1. 线程池的使用
### 1.0 Executors的使用（不推荐）
1. ExecutorService pool = Executors.newFixdThreadPool(5);
    - 固定大小的线程池，任务多时造成任务堆积，从而OOM
2. Executors.newSingleThreadExecutor()
        - 允许的请求队列长度为固定值`Integer.MAX_VALUE`
        - 和上面一样, 可能堆积大量请求导致OOM
    3. CachedThreadPool
        - 允许的创建线程数量为`Integer.MAX_VALUE`
        - 可能创建大量线程导致OOM
### 1.1 ThreadPoolExecutor 核心类
- 阿里java规范规定线程池`不得用Excutors创建`, 应该使用`ThreadPoolExecutor`方式
- `ExecutorService pool = new ThreadPoolExecutor(很多参数)`
1. 构造方法的参数 (这里介绍参数最多的那个)
    1. 常用4个
        1. corePoolSize ,核心线程数
            - 只要线程池不关闭, 这些核心线程就`不会销毁`
        2. maximumPoolSize ,最大线程数
            - 非核心线程空闲时可能`会被销毁`
        3. keepAliveTime ,空闲线程存活时间
            - 如果一段时间线程没工作就会被销毁
            - 如果设为`0`, 则不销毁空闲线程
        4. unit ,时间单位, 比如`TimeUnit.SECONDS`
    5. workQueue ,任务队列
        - 提交给线程池的`多项任务`将被存在这里, 需要指定队列
            - `new LinkedBlockingQueue<>()`
            - `new ArrayBlockingQueue<>()`
    6. threadFacotry ,线程工厂, 可以指定线程如何生产
        - 这是一个接口, 需要实现`newThread()`方法
            - 比如在这里设置各个线程启动名称, 是否为后台线程, 方便查看日志
            - 也可以用默认的方法
    7. handler ,任务拒绝策略, 什么情况线程池拒绝任务
        - 在线程池拒绝任务加入的时候, 对该任务所采取的策略
        1. 什么时候会拒绝任务?(同时满足下面四个条件)
            1. 线程池已满
            2. 无法继续扩容
            3. 所有线程都在执行任务, 没有空闲线程
            4. 任务队列已满
        2. 四种策略
            1. DiscardPolicy, 什么都不做, 直接丢弃该任务
            2. CallerRunsPolicy, 使用调用者的线程, 直接执行该任务
                - 不是线程池执行的
            3. AbortPolicy, `默认策略`, 抛出任务被拒绝的异常
            4. DiscardOldestPolicy, 丢弃处于任务队列头部的任务, 添加被拒绝的任务
2. 推荐使用`原生方式`创建线程池
    - 不得用`Excutors`创建
    1. 定义线程工厂类 `implements ThreadFactory`
        1. 重写`newThread()`方法
            - 可以加一个计数器`AtomicInteger`来给线程命名用
            - `i.getAndIncreament()`
    2. 编写任务 `implemnets Runnable`
    3. 创建任务 task1,2,3
    4. 创建线程池
        ```java
        ThreadPoolExecutor threadPool = new ThreadPoolExecutor(
            10,
            25,
            10L,
            TimeUnit.SECONDS,
            new LinkedBlockingQueue<>(),
            new CustomThreadFactory(), //自定义线程工厂
            new ThreadPoolExecutor.AbortPolicy() //默认策略
        )
        ```
    5. 提交任务
        - threadPool.execute(task1), //无返回结果
        - threadPool.submit(task2)， //有返回结果Future
    6. `重要`,一定要`手动关闭线程池`
        - threadPool.shutdown()

### 1.3 相关方法
#### 1.3.1 sumbit()与Future
1. `execute()`和`sumbit()`的区别
    1. `threadPool.execute(runnable)` 只能提交 `无返回值的` Runnbale任务
    2. `threadPool.submit(r/c)`  既支持Runnable, 又支持Callable
        1. Future<?> submit(Runnable)
            - 这里的Future是用来观察任务是否取消, 是否运行完毕的
            - 这个`?`就理解为Object类型就好
                - Object result = future.get() //null
        2. Future<T> submit(Runnable, T)
            - 这个T就是返回结果, 可以是“任务完成”之类的String
        3. Future<T> submit(Callable<T>)
            - 正常的结果存入 future.get() 的方法
2. Future接口提供的方法
    1. Future get()
    2. Future get(long, Time.Unit), 若超时,则抛出异常
    3. boolean cancel(boolean), 传入true的时候取消任务
    4. isCancelled()    
    5. isDone(), 
3. 关于`get()`方法, `阻塞式`与`定时式`获取任务
    1. get(), `阻塞式`获取任务执行结果, 用的多
        - 获取任务结果的线程会`一直等待`任务执行完毕
    2. get(long, Time.Unit), 指定时间内阻塞, 超时则抛出异常
        - 防止无休止的阻塞
4. 关于`boolean cancel(boolean)`方法
    1. 返回值与参数
        1. 若参数为TRUE
        - 会调用线程的t.interrupt()方法
        2. 若参数为FASLE
            - 什么也不会执行
        3. 返回结果
            - 取消成功返回TRUE, 否则返回FALSE
    2. 任务执行的三个时间点
        - submit~加入任务队列: 任务未执行阶段
        - 加入线程池~任务完成: 任务正在执行
        - 任务完成
        1. 取消未执行的任务
            - 直接取消, 引发任务取消异常
        2. 取消已完成的任务
            - 任务取消失败, 返回false, 不会引发异常
        3. 取消正在执行的任务
            1. 参数为False的情况: 引发取消异常, 但任务会继续执行完
            2. 参数为True的情况: 取消成功, 引发取消异常
                - 但任务不一定会响应t.interrupt()指令

#### 1.3.2 shutdown() 与shutdownNow()
- 一般是放在 finally{}块中执行, `如果不关闭线程池, 程序就不会结束`
1. `void shutdown()`
    1. 之后再添加新任务会报异常
    2. `任务队列中`尚未执行的任务`不会抛弃`, 而是会继续执行, 直到所有任务都结束, 线程池才会彻底关闭
2. `List<Runnable> shutdownNow()` 立即关闭线程池
    1. 而且还会返回`任务队列`的未执行的任务
    2. 但正在`线程中`执行的任务就没了
### 1.4 线程池的生命周期
1. 生命周期
    1. RUNNING, 可以接收新任务, 可以处理任务队列中的任务
    2. SHUIDOWN, 不再接收新任务, 可以处理任务队列中的任务
        - shutdown()
    3. STOP, 不接收新任务, 不处理任务队列, 并且中断正在处理的任务
        - shutdownNow()
    4. TIDYING, 所有的任务均已终止, 线程池中线程数量为0
        - 正在关闭的状态
    5. TERMINATED, 线程池彻底关闭
#### 1.4.1 线程池执行任务的流程
1. 提交任务
    1. execute(r)
    2. submit(r/c)
2. 执行任务
    - 用的都是`ThreadPoolExecutor`类中的execute()方法
    - submit不过是r转变成了有返回值的c
    1. execute()内部
        1. 判断核心线程数是否已满
            - 不满就直接用核心线程执行, 执行完就结束了
        2. 判断任务队列是否已满
            1. 先考虑将任务放入任务队列
                1. 成功则添加,然后等待被执行
            2. 任务满了, 没有可用的空闲线程, 那么考虑添加一个非核心线程    
        3. 判断线程池的线程是否已满
            1. 若没满,就添加线程执行任务
            2. 若满了, 就按Policy处理(拒绝任务)

### 2. ForkJoin框架
- 常用于计算量大， 数据量大的任务
- 把一个大任务`分割(Fork)`成多个小任务， 然后再`合并(Join)`结果的方法
1. 术语
    1. `ForkJoinPool` ， 也是一个线程池
    2. `ForkJoinTask`, 相当于Future，从这里拿结果
    3. `RecursiveTask`， 相当于Callable， 有返回值的任务
    4. `RecursiveAction`， 相当于Runnable， 无返回值的任务
2. 从1+2+。。。+99+100的例子
    - 可以分割成10个 1加到10， 11加到20.。。多个任务， 用中间值来实现
    ```java
    class SumTask extends RecursiveTask<Integer>{
        private int start; //起始值
        private int end; //结束值
        private int temp = 10; //临界值, 一组10个数字

        @Override
        protected Integer compute(){
            if((end - start) < temp){ //小于临界值说明任务无法再分割，开始计算
                // 累加方法, 返回sum
            } else {
                // 1. 取得中间值
                int mid = （start + end）/ 2;
                // 2. 开头到中间
                Task t1 = new Task(start, mid);
                // 3. 中间到结尾
                Task t2 = new Task(mid + 1, end);
                // 4. 向线程池中加入任务
                t1.fork();
                t2.fork();
                // 5. 合并计算结果
                return t1.join() + t2.join();
            }
        }
    }

    main(){
        SumTask task = new SumTask(1, 100);
        // 1. 创建ForkJoin线程池
        ForkJoinPool pool = new ForkJoinPool();
        // 2. 提交任务
        ForkJoinTask<Integer> future = pool.submit(task);
        // 3. 获取结果
        try{
            Integer result = future.get();
        } fiannly {
            pool.shutdown()
        }
        
    }
    ```

## 7.1 CAS技术
- Compare And Swap，比较并交换
- 这个`技术`能解决线程执行期间被其他线程影响的问题
1. CAS操作包含三个值
    1. 内存值
    2. 预期原值
    3. 新值
2. 如何使用
    1. 定义这个方法
        1. public static boolean compareAndSwap(三个参数)
            1. int oldValue, 内存值
            2. int expectedValue, 预期原值
            3. int newValue, 新值
            4. boolean返回值表示: 若设置成功则返回false
        2. 比较什么? 交换什么?
            1. if(内存值 == 预期原值) 内存值 = 新值, 返回true
            2. if(内存值 != 预期原值) 什么也不做, 返回false
    2. 在main()中使用
        1. 在线程中的run()方法中
            1. 一开始就 int oldValue = i
            2. 之前i+1的地方改成
                - reuslt = compareAndSwap(i, oldvalue, i+1)
            3. 若result为false, 则说明收到了其他线程的影响
3. 这个原理在原子类内部用的很多
4. CAS的`ABA问题`
    - 一个值一开始是A, 后来变成B, 然后又变成A
    - CAS会认为这值没变, 但实际上是变化了的
    - 解决思路是在变量前面追加上版本号或者时间戳。JDK 1.5 以后的`AtomicStampedReference` 类就是用来解决 ABA 问题的
