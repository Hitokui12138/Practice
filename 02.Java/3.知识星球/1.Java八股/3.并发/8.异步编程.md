# 异步编程
- 一个接口可能需要同时获取多种不同的数据，然后再汇总返回
- 例如： 用户请求获取订单信息，可能需要同时获取用户信息、商品详情、物流信息、商品推荐等数据
1. 此时考虑到这些任务之间有大部分都是 `无前后顺序关联` 的，可以 `并行执行`
2. 对于有前后调用关系的任务，可以进行`任务编排`

## 1. 原生Future （Java5）
1. 手动封装FutureTask
    ```java
    // 1. 手动FutureTask包装
    Callable<Integer> task = () -> 100;
    FutureTask<Integer> ft = new FutureTask<>(task);//把Callable包装成Runnable
    new Thread(ft).start();
    Integer num = ft.get();
    ```
2. 线程池自动封装FutureTask
    - 线程池 submit 也支持 Runnable
    ```java
    // 传入Callable，线程池自动包装成FutureTask，返回Future凭证
    Future<String> future = pool.submit(() -> {
        Thread.sleep(1000);
        return "执行结果";
    });

    // 主线程做其他事, 但future.get()是阻塞式的
    String res = future.get(); // 阻塞拿Callable的返回值
    ```
3. Callable， Future， FutureTask
    - Callable： 负责写带返回值的异步任务
    - Future： 是用来取这个任务结果的凭证；
    - FutureTask： 把Callable转为Runnable， 因为线程只支持Runnable

4. Future支持的方法
    ```java
    // 1. 尝试取消任务， 成功取消返回 true，否则返回 false
    boolean cancel(boolean mayInterruptIfRunning);
    // 2. 判断任务是否被取消
    boolean isCancelled();
    // 3. 判断任务是否已经执行完成
    boolean isDone();
    // 4. 阻塞式获取任务执行结果
    V get();
    // 5.指定时间内没有返回计算结果就抛出 TimeOutException 异常
    V get(long timeout, TimeUnit unit);
    ```

5. Future 缺陷	CompletableFuture 解决方案
    1. get () 阻塞，无回调	thenApply/thenAccept 非阻塞自动回调
    2. 无法串联异步任务	thenCompose 串行依赖
    3. 不能合并多个任务	thenCombine / allOf / anyOf
    4. 不能手动设置结果	complete() / completeExceptionally()
    5. 异常只能 get 时捕获	exceptionally /whenComplete 独立异常分支
    6. 无法控制回调线程	xxxAsync 系列，可自定义线程池
    7. 无超时快捷 API	orTimeout、completeOnTimeout
    



## 2. CompletableFuture（Java8）
- FutureTask和CompletableFuture都是Future实现类， 不要用FutureTask
- CompletableFuture 是一套完整异步工作流，支持自动回调、任务编排、手动控制、异常分流
- `CompletableFuture<T> implements Future<T>, CompletionStage<T>`
### 2.1 创建CompletableFuture
1. new关键字(无视这个方法)
    - 空壳，不会自动跑任务， 由外部回调函数`主动填充结果`。
    ```java
    // 1. 创建一个CompletableFuture， 
    CompletableFuture<String> future = new CompletableFuture<>();
    // 2. 主线程注册一个回调来接受结果， 任务执行完毕后自动执行（非阻塞）
    future.whenComplete((result, ex) -> {
        if(ex != null){
            // 异常处理
        }else{
            // 正常处理
        }
    })
    // 3. 新建一个线程执行任务
    new Thread(() -> {
        try{
            // 为了能够触发回调， 需要主动填入结果
            future.complete("接口返回的数据：用户信息");
            // complete() 方法只能调用一次
        }catch (e){
            // 为了能够触发回调， 需要主动填入异常
            future.completeExceptionally(e);
        }
    }).start();
    // 4. 主线程可以做别的事
    ```
    2. 由于CompletableFuture实现了Future， 因此get(), isDone()也能用

2. 静态工厂方法：`runAsync()`、`supplyAsync()`
    - supplyAsync 内部自动创建 CompletableFuture、自动开线程执行任务， 不需要complete()主动填入结果， 用return就行
    1. 区别
        1. runAsync(Runnable， Executor)
            - 没有返回值， 不关心返回结果时用这个
        2. supplyAsync(Supplier<U>, Executor)
            - U是返回值类型
    2. Executor是自定义线程池，是可选的
        - 默认用的是ForkJoin线程池， 但还是推荐自定义线程池
    3. 无需新建线程，直接在方法中就可以定义任务
        ```java
        // 1. 不需要手动使用complete包装结果
        CompletableFuture<String> cf1 = 
            CompletableFuture.supplyAsync(() -> {
            try {
                // 耗时逻辑直接写在lambda内部
                return "接口返回的数据：用户信息";
            } catch (InterruptedException e) {
                // 抛出异常会自动走异常分支
                throw new RuntimeException("线程中断", e);
            }
        }).whenComplete((result, ex) -> {})
        // 2. 可以在这后面链式调用处理方法

        main(){
            //主线程做别的事
            cf1.join(); //获取异步执行结果
        }

        ```
### 2.2 处理异步结算的结果的方法（这些方法都不会阻塞主线程）
- thenApply、thenAccept、thenCompose 这类方法不会改变调用它的 CompletableFuture 本身，而是生成一个全新的 CompletableFuture 作为返回值。
1. 需要取得结果进行处理的
    0. `whenComplete`(BiConsumer<? super T, ? super Throwable>)
        - whenComplete((result, ex) -> {...})
        - 详细看下面
    1. `thenApply`(Function)
        - .thenApply(s -> s + "world!");
2. 需要从回调函数中获取返回结果的
    1. `thenAccept`(Consumer<? super T>)
        - .thenAccept(System.out::println)
    2. `thenRun`(Runnable)
        - .thenRun(...), 这个方法无法取得异步执行的结果

### 2.3 异常处理的方法
1. exceptionally(Function<Throwable, ? extends T> fn)
    - exceptionally(ex -> {...})
    - 正常流程是`不会`走这个方法的, 仅做异常兜底（把异常转为正常结果）
2. whenComplete((result, ex) -> {...})
    - 成功、异常都会执行
        - 成功：第一个参数是结果，第二个异常为 null
        - 失败：第一个结果为 null，第二个是异常对象
    - 参数是Consumer， 因此无法修改原来的结果，一般作为日志打印、资源释放使用
3. handle(BiFunction<? super T, Throwable, ? extends U> fn)
    - 成功、异常都会执行, 和whenComplete一样
    - 参数是Function， 可以对结果可加工、可转换类型， 再返回
4. 执行顺序
    - 任务完成后，先执行 handle/whenComplete，再 exceptionally。

### 2.4 任务编排
1. 串行编排
    - 也可以理解为Completable嵌套， 不过提供了更易用的方法
    1. thenCompose()
        - 将前一个任务的返回结果作为下一个任务的输入参数，从而形成一个依赖关系， 同步执行
        ```java
        CompletableFuture.supplyAsync(() -> "hello!") // task1
            .thenCompose( s -> CompletableFuture.supplyAsync(
                () -> s + "world!"));
        // s是task1的结果， 代入到task2中
        ```
    2. thenApply(), thenAccept(), thenRun()也属于串行编排
    3. 补充： thenApply() 和 thenCompose()的区别
        1. thenApply()返回普通对象， 如果函数返回CompletableFuture，结果会变成 `CompletableFuture<CompletableFuture<R>>`
            - 同步转换、简单计算， `当map用`
        2. thenCompose() 能自动展平，输出 CompletableFuture<R>
            - 异步嵌套，链式调用`下一个异步任务`
    3. thenApplyAsync() /thenComposeAsync(), 带上Async的区别
        1. 不带 Async：使用上一步任务执行的线程；
            - 简单逻辑， 回调无阻塞 IO， 不增加新线程开销
        2. 带 Async：重新提交任务到线程池，开启新线程执行回调。
            - 适合回调内有阻塞 IO（数据库、RPC）；
            - 这个方法需要自定义线程池：thenApplyAsync(func, myExecutor)
2. 双任务并行执行
    1. thenCombine()
        ```java
        CompletableFuture<Integer> cf1 = CompletableFuture.supplyAsync(() -> 10);
        CompletableFuture<Integer> cf2 = CompletableFuture.supplyAsync(() -> 20);
        // 两个都完成后求和
        cf1.thenCombine(cf2, (a, b) -> a + b);
        ```
3. 等待多个 CompletableFuture 完成
    1. 等待所有任务完成 
        -  CompletableFuture<Void> headerFuture=CompletableFuture.allOf(task1,.....,task6);
        - 然后调用 headerFuture.join()
            1. join()与get()差不多，都是阻塞
                1. join（）用于allOf 之后汇总结果场景，更简洁
                2. get(超时, unit)， join没有这个方法
    2. 等待任意 anyOf()

### ComletableFuture 与 RabbitMQ 技术选型
1. 同步批量接口，需要等待所有文件处理完成，返回汇总结果
    - 使用 ComletableFuture + 自定义线程池
    - RabbitMQ没有汇总所有结果的能力，强行用 MQ 还要做状态轮询，架构过度复杂
2. 离线异步任务，不需要实时等待结果，允许后台慢慢处理
    - 使用 RabbitMQ + 数据库状态表
