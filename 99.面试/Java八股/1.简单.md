1. Java面向对象的特征
    1. 封装
        1. 类,方法: 隐藏具体实现, 可以在不影响使用的前提下修改内部实现
        2. 属性: 只能通过定义好的方法访问数据, 限制对属性的不合理操作
        - 增加代码复用性(封装好的类可以重复使用)
    2. 继承
        1. 即父类和子类, 从已有的类派生出新的类
        2. 子类是特殊的父类, 可以定义新的属性和方法
        - 增强代码复用性
    3. 多态 (指两个类的一种联系)
        0. 多态分为`编译时多态`和`运行时多态`:
            1. 编译时多态主要指方法的重载
            2. 运行时多态指程序中定义的对象引用所指向的具体类型在运行期间才确定
        1. 形成`多态`的条件
            1. 两个类存在继承关系
            2. 存在方法的重写
            3. 父类的引用指向子类对象
        ```java
        Animal A = new Dog();
        A.speak(); //bark
        ```
        2. 增加了代码的可移植性, 灵活性(因为具体实现可以随便更改)
2. ArrayList和LinkedList
    1. 都实现了List接口
    2. 区别
        1. ArrayList底层是`数组`实现的, 一组数据, 带上index01234
        2. LinkedList是以链表的数据结构实现的, 每个数据都有前一个元素和后一个元素
            - 每个节点除了数据之外, 还有指向下一个节点的指针
    3. 插入数据和删除数据用LinkedList(修改两个指针即可)
    4. 遍历访问数据用ArrayList(用index)

4. 接口和抽象类的区别
    1. 相同点:
        1. 都不可以实例化
        2. 都可以作为引用类型使用
        3. 一个类如果想继承抽象类或者实现接口, 需要实现里面所有方法
    2. 不同点
        1. 抽象类
            1. 可以有构造器, 抽象方法或者具体方法, 可以有静态方法
            2. 成员变量必须为public
            3. 一个类只能继承一个抽象类
        2. 接口
            1. 不能有构造期, 全是抽象方法, 不能有静态方法
            2. 成员可以用四种修饰 public, private default, protected
                - 但接口类中的变量`实际上`都是常量
            3. 可以实现多个接口
    3. 什么时候用?
        1. 抽象类
            - 描述一个抽象的概念, 比如动物Animal, 建议用抽象类来实现
            - 狗`是`动物
        2. 接口
            - 描述一种特征,能力, 比如Comparabale, 建议用接口实现
            - 这两个List`可以`进行比较
6. 异常处理机制
    1. 通过五个关键字来实现, try, catch, finally, throw, throws
    2. Throwable是顶层基类（包括Error和Exception），Exception代表程序可处理的预期异常（如文件未找到），是程序设计中的可恢复问题，与之相对的是Error（不可恢复的严重错误，如内存溢出）
7. 重写和重载
    1. 重写 (编译时的多态)
        1. 发生在父类和子类之间, 方法签名需要相同的两个方法可以有不同的实现方法
        2. 特殊
            1. 父类权限要小于子类(父:private, 子:public)
            2. 父类返回值类型大于子类(父: Object, 子:其他)
    2. 重载 (运行时的多态)
        1. 发生在同一个类中, 方法名需要相同, 参数和方法实现可以不同
8. String, StringBuffer, StringBuilder区别
    1. String
        1. 不可变, 定义后,如果想更改的话,实际上是创建了一个新的String(新地址)
    2. StringBuffer (JDK1.0)
        1. 可变, 线程安全
    3. StringBuilder (JDK1.5)
        1. 可变, 底层是数组, 有一个value[]和一个count
        2. 效率高, 但是没有被synchronize修饰, 是线程不安全的
        3. 扩容问题: 
            - 放不下后,会指向一个新的更长的value[]

11. BigDecimal
    1. 陷阱1: 必须使用String, 或者valueOf()
        - new BigDecimal(0.1), 此0.1实则为0.100003
    2. 陷阱2: 比较时必须使用CompareTo(), 可以忽略精度差异
        - 1.0 equals() 1.00 结果为false
    3. 陷阱3: 除法运算必须制定保留位数和舍入模式
        - 1 / 3 会导致内存溢出
    4. 不可变性: BigDecimal所有运算返回的都是新的, 必须接收返回值
