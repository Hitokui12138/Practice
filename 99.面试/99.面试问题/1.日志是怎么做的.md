# 面试
1. 我们项目的日志主要分为`系统日志`和`操作日志`
    1. `系统日志`主要是用来开发排查的, 主要记录一些类和方法的执行情况, 数据库操作等信息用于故障时快速定位.
        - 直接使用依靠 SLF4J+Logback 输出到本地日志文件，记录方法执行、SQL、异常堆栈，用于线上故障排查；项目封装LogUtil工具类简化日志打印。
    2. `操作日志`主要是记录业务信息, 比如某个时间点创建了订单,某个时间点订单状态发生变化等等
        - 利用AOP 环绕通知拦截 Controller/Service 方法, 由切面统一采集参数、返回值、异常、操作人，实现日志与业务解耦。
2. 实现方式
    1. 具体实现
        1. 自定义`@OperateLog`注解 (仅作用在方法)
            - 里面定义 success(), fail(), operator()等等参数
        2. 定义切面类 LogRecordAspect
            - @Aspect+@Component注册 Bean；
            - @Around("@annotation(注解变量)"), 环绕通知
            1. result = joinPoint.proceed(); 执行业务方法
            2. 打印业务日志
                1. 成功模版
                2. 失败模版
        3. 有需要的话可以封装日志实体，入库或ES
    2. 里面具体的参数可以用`SpEL` 读取方法入参

# 问题
1. 操作日志如何和系统日志区分开
    - 可以配置Log的配置文件, 把有关操作相关的Log单独放在一个日志文件里
    - 比如配置Logger叫做“businessLog”, 然后配置到某一个log文件里
    - 在使用时, 先`LoggerFactory.getLogger("businessLog")`, 然后用这个logger来写日志

    - 因为走 AWS 原生 CloudWatch 免运维, 而且自带检索, 过滤器等功能

# 技术
1. `xxxLogger.info("")`和`LogUtil.log()`的区别
    - 想使用Logger必须提前定义, LogUtil可以直接用, 底层都是 SLF4J
    - Logger 带本类信息，LogUtil 简化代码但丢失类路径日志。
2. 敏感信息脱敏
    - 针对手机号、身份证号、邮箱、other(其他匹配不到时用的)，内置一种脱敏方式：password，表示完全脱敏，可用于 pattren 下的
    - 我们项目是不打印用户敏感信息, 如果想做脱敏的话可以自定义一个脱敏组件, 然后定义这几种模式, 匹配到时, 用xxx替代字符串中一些信息




# 代码
```java
// 业务代码
// 1. 日志注解 OperateLog
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface OperateLog {
    String success();
    String fail() default "";
    String bizNo();
}

// 2.AOP 切面
@Aspect
@Component
public class LogAspect {

    @Around("@annotation(log)")
    public Object logAround(ProceedingJoinPoint point, OperateLog log) throws Throwable {
        Object res;
        // 在这里解析SpEL表达式
        try {
            res = point.proceed();
            // 正常日志
            saveLog(log.bizNo(), log.success(), null);
        } catch (Exception e) {
            // 异常日志
            saveLog(log.bizNo(), log.fail(), e.getMessage());
            throw e;
        }
        return res;
    }
}

// 3. 具体使用
@Service
public class OrderService {
    // #{order.no} 动态取入参属性, 或者直接传入order对象
    @OperateLog(success = "下单成功:{#order.name}", bizNo = "#order.orderNo", fail = "下单异常:{#order.name}")
    public void createOrder(Order order){
    }
}
```
