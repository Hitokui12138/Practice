# 压力测试
1. 为什么压测
    1. 提前发现问题, 了解系统瓶颈
    2. 验证优化效果
2. 如何压测一个接口
    1. 确定压测目标
        1. 指标: 目标QPS(每秒请求数>200), 响应时间(P99 < 200ms), 错误率<1%
        2. 并发量级: 模拟多少用户同时访问
    2. 开发人员一般直接在本地测试
3. 压测工具
    1. JMeter
        - 本身也要占电脑资源, 因此可能导致本地测试测不准
    2. Postman
4. JMeter用法
    1. 创建一个`测试计划`
    2. 给测试计划添加`线程组`和`Ramp-up时间`(多少秒内启动所有线程)
        - 模拟多个用户
    3. 创建HTTP请求
        - 添加结果树, 用来看结果
        - 聚合报告, 吞吐量, 异常率, P99
    4. `JSON断言`,判断返回`业务结果`是否正确
    5. 指标解读
        1. QPS(Throughput): 每秒请求数, 越高越好
        2. 平均响应时间(Average): 平均耗时
        3. P99: 99%的响应时间在多少时间内, 比平均耗时更有参考价值
        4. 错误率: 通常要求<1%
5. 拿到指标之后
    1. 优化SQL查询语句, 用EXLAIN看看是否缺索引之类的
    2. 连接池不够
    3. 优化JVM
    4. 第三方接口慢的话加缓存或者异步处理
