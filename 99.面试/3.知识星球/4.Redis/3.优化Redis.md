# Reids事务有哪些缺陷
1. 在运行错误时, 除了执行过程中出现错误的命令以外, 其他的命令都会正常执行
2. Reids事务不支持回滚, 因此不支持原子性
## LUA脚本
- 将批量的Redis 命令 被提交到 Redis 服务器一次性执行完成
- 一段 Lua 脚本可以视作一条命令执行, 且执行期间阻塞主线程确保不会有其他命令执行
1. 与Pipeline的区别
    1. pipeline不适合执行 执行顺序前后有依赖关系的一批命令
    2. 如何需要判断上一条命令的结果来决定执行后一条命令的情况, 使用LUA脚本
## Redis性能优化
1. 减少网络传输 RTT
    1. 使用原生批处理操作 MSET, HMSET
    2. 不支持批处理的操作用 pipline

## BigKey问题
- 由于 Redis 执行命令是单线程处理，然后在操作(尤其是删除)大 key 时会比较耗时，那么就会阻塞 Redis
1. 怎样算是BigKey?
    1. String 类型的 value 超过 1MB
    2. 复合类型的value有5000个以上
2. 如何及时发现BigKey
    1. Redis自带
        1. redis-cli -p 6379 --bigkeys
        2. SCAN 命令 + STRLEN/HLEN/SCARD
    2. 开源工具, 云服务分析工具
3. 如何处理BigKey
    1. 分割 bigkey, 选用更合适的数据结构
    2. 手动清理
        - Redis 4.0+ 可以使用 UNLINK 命令来异步删除一个或多个指定的 key
    3. 开启`lazy-free 惰性删除`
        - 让 Redis 采用异步方式延迟释放 key 使用的内存, 避免阻塞主线程

## HotKey问题
- 例如在 Redis 实例的每秒处理请求达到 5000 次，而其中某个 key 的每秒访问量就高达 2000 次，那这个 key 就可以看作是 hotkey。
- 如重大的热搜事件、参与秒杀的商品。
1. 如何发现Hotkey
    1. 系统自带
        1. redis-cli -p 6379 --hotkeys
        2. MONITOR (性能消耗大, 不要长时间使用)
    2. 一些开源项目,云服务可以检查
2. 如何处理Hotkey
    1. 读写分离(主从复制)
        - 主节点处理写入请求, 从节点处理读取请求
    2. 使用Redis Cluster 
        - 提高上限

## 慢查询命令
- 常见阻塞原因: https://javaguide.cn/database/redis/redis-common-blocking-problems-summary.html
1. 可能引发慢查询的操作
    1. 有少部分 O(n) 时间复杂度的命令
        - KEYS *, HGETALL, LRANGE, SMEMBERS, 交并集
2. 如何查找慢查询命令
    1. Redis提供内置的慢查询日志(Slow Log)
        1. 先设置一个阈值 slowlog-log-slower-than
        2. 命令: SLOWLOG GET

## Redis内存管理
- 给缓存数据设置过期时间, 
- Redis 中除了字符串类型有自己独有设置过期时间的命令 setex 外，其他方法都需要依靠 expire 命令来设置过期时间 。另外，persist 命令可以移除一个键的过期时间
1. Redis的删除策略
    - 定期删除+惰性删除
    1. 定期删除
        - Redis 的定期删除过程是随机的（周期性地随机从设置了过期时间的 key 中抽查一批），所以并不保证所有过期键都会被立即删除
        - 定期删除的频率是由 hz 参数控制的
    2. 惰性删除
        - 只会在取出/查询 key 的时候才对数据进行过期检查。这种方式对 CPU 最友好
2. 大量key集中过期怎么办
    1. 设置过期时间时, 增加随机时间
    2. Redis有一个Lazy Free机制, 将 lazyfree-lazy-expire 参数设置为 yes
        - Redis 会在后台异步删除过期的 key，不会阻塞主线程的运行，从而降低对 Redis 性能的影响
