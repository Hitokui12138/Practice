# 索引
- 索引是一种特殊的文件, 是表空间的一个组成部分, 里面包含着数据表里所有记录的`引用指针`
- 常见的索引结构有：B 树、 B+ 树 和 Hash、红黑树。在 MySQL 中，无论是 Innodb 还是 MyISAM，都使用了 B+ 树作为索引结构。
## 索引的分类
### 1. 主键 PRIMARY KEY
- 是一种特殊的唯一索引, 一个表只能定义一条
1. 几种选择
    1. 自增id(推荐)
        - 插入B+树时, 不会引起之前的数据页分裂,提高性能
    2. 使用业务的`整形`字段, 分配给用户的key
    3. 使用UUID, 雪花算法生成字符串
2. `聚簇索引（Clustered Index）`即索引结构和数据一起存放的索引
    - 主键是一种 聚簇索引
    - 查询速度非常快, 
### 2. 二级索引 Secondary Key
#### 2.1 `非聚簇索引（Non-Clustered Index）`即索引结构和数据分开存放的索引
- 二级索引都是  非聚簇索引
- 非聚簇索引的叶子节点是不存放数据的
1. 可能会有二次查询(回表)
    - 当查到索引对应的指针或主键后，可能还需要根据指针或主键再到数据文件或表中查询。
    - 若此时`覆盖索引`了, 则不需要回表
#### 2.2. 唯一索引 UNIQUE
- 唯一索引可以作为数据合法性的验证手段
- 唯一索引可以有多个, 也允许一条数据为空
#### 2.1. 普通索引  (辅助索引)
- 由关键字KEY或INDEX定义, 对非主键进行索引
- 允许被索引的数据列包含重复的值, 但B+树上存的其实是主键值, 拿到后,再`回表`拿到该条数据
1. 唯一作用: 加快对数据的访问 
#### 2.5 前缀索引(Prefix)
- 只适用于字符串类型, 相比普通索引建立的数据更小

### 6. 覆盖索引和联合索引
#### 6.1. 覆盖索引
- 如果一个索引包含（或者说覆盖）所有需要查询的字段的值，我们就称之为 覆盖索引（Covering Index）。
- 覆盖索引即`需要查询的字段`正好是`索引的字段`，那么直接根据该索引，就可以查到数据了，而`无需回表`查询。
    - 如果一条 SQL 需要查询 name，name 字段正好有索引，那么直接根据这个索引就可以查到数据, 无需回表
1. 使用`EXPLAIN`分析SQL语句, 判断是否触发覆盖索引
    1. 查看 Extra列
        1. Using filesort, 表示没有用到索引
        2. Using indexing, 表示用到了索引
#### 2.4. 联合索引
- 索引可以覆盖多列 KEY/INDEX(columnA, columnB)
1. 当条件查询涉及多个字段时, 可以使用联合索引
2. 会根据列的先后顺序进行排序(优先按照columnA排序)
    - 利用这个原则, 可以使用`最左前缀匹配原则`优化SQL
3. 最左前缀匹配原则
    - 在使用联合索引时，MySQL 会根据索引中的字段顺序，从左到右依次匹配查询条件中的字段。
    - 如果查询条件与索引中的最左侧字段相匹配，那么 MySQL 就会使用索引来过滤数据，这样可以提高查询效率。
    1. 假如有一个联合索引 (c1, c2, c3), 相当于创建了三个索引
        1. (c1)
        2. (c1, c2)
        3. (c1, c2, c3)
    2. 情境题
        1. 查询 a=1 AND c=1：
            - 根据最左前缀匹配原则，查询可以使用索引的前缀部分。因此，该查询仅在 a=1 上使用索引，然后对结果进行 c=1 的过滤
        2. 查询 b=1 AND c=1 或者 c=1：
            - 由于查询中不包含最左列 a，根据最左前缀匹配原则，`整个索引都无法被使用`
        3. 查询 b=1 AND a=1 AND c=1:
            - 会将 b=1 和 a=1 的条件进行重排序，变成 a=1 AND b=1 AND c=1。

### 5. 索引建立的注意事项
- 
1. 什么字段适合加索引?
    1. `查询频率高`,`作为条件查询`的字段
    2. `选择率不高`的字段(重复率不高)
        - SELECT COUNT(DISTINCT(column))/count(*) FROM table;
        - 超过0.5就适合做索引, 越接近1就越适合做索引
    3. `排序,分组,联合查询` 的字段
    4. 有多个列时, 可以考虑联合索引
    5. 对于字符串类型的字段, 考虑使用前缀索引
2. 什么字段不适合加索引?
    1. 更新比查询更频繁的字段
    2. 单张表索引不超过 5 个

## 树的结构
### 1. 二叉树 Binary Tree / 二叉搜索树
1. 结构
    1. 每个节点最多有两个子节点（左子节点、右子节点）
    2. 左子节点的值 <父节点值，右子节点的值> 父节点值（二叉查找树 / 二叉搜索树，BST）
2. 查询逻辑
    1. 对比查找数据和根结点
    2. 比根结点小走左边
    3. 比根结点大走右边
3. `退化`问题, 极度不平衡
    - 如果插入的数据是递增的, 那么二叉树会变成一个链表
### 2. 平衡二叉树Balanced Binary Tree / AVL 树(严格自平衡)
- 关键约束：任意节点的左右子树高度差不超过 1（这个差值叫 “平衡因子”）；
1. 问题
    1. 二叉树本身一个节点只能存两个数据, 即使只有1000条数据,二叉树也有10层高
    2. 每一次分叉, 都需要读取一次硬盘数据, 这样一次查询就要10次IO操作
    3. 插入 / 删除时频繁旋转，开销大；

### 3. 红黑树 (弱平衡的二叉树)
- 插入和删除操作频繁的场景下, 红黑树调整成本更低
- 对于数据在内存中的这种情况来说，红黑树的表现是非常优异的。
1. 五条核心规则
    1. 每个节点都有颜色, 红色或黑色
    2. 根结点是黑色
    3. 所有NIL(哨兵节点)都是黑色
    4. 红色节点子节点为黑色(红色节点不会连续出现)
    5. `从任意节点到每个叶子的路径上,都包含相同数量的叶子节点`
        - 这确保了最长路径不会超过最短路径的两倍
        - 底层Nil高度为0, 节点到Nil节点每经过一个黑节点(包含Nil, 但不含自己), 高度+1
        1. 根结点(黑, 黑色高度为2 = 一个黑节点 + Nil)
            - 红(黑高2)
            - 黑(黑高1, 因为不含自己)
            - Nil(0)

### 3. B树 多路平衡查找树
- B + 树是 “多路”（一个节点能存几十 / 上百个值），层数仅 3-4 层，只需 3-4 次 IO，效率差一个量级；
1. 特点
    1. 一个节点存储多个数据, 且按序排列(按二分法快速定位)
    2. 一个节点有多个分叉
2. 问题
    1. 一些在叶子节点上的数据, 查询起来还是很慢
    2. 数据散落在不同节点上, 范围查找(`16<x<32`)的时候就需要在不同节点上进进出出

### 4. B+树
- 所有的数据全部放在叶子节点上, 根结点只存放指向其他节点的指针
- B+ 树每页最多存放两个节点?
1. 优点
    1. 解决了查询性能不稳定的问题
    2. 整个树更加扁平, 减少IO次数
    3. 叶子节点用指针连起来, 解决了范围查找的问题
