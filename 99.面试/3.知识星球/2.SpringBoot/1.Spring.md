# Spring
1. 概念
- Spring 是一款开源的轻量级 Java `开发框架`, 提供一系列开箱即用的功能
- Spring 提供的核心功能主要是提供 `IoC(依赖注入)` 和 `AOP(面向前面编程)` 的支持
2. IoC (Inversion of Control:控制反转)
    - 是一种思想不是一个技术实现, 不通过 new 关键字来创建对象，而是通过 Spring 框架提供的IoC 容器来帮助我们实例化对象
    2. 如果没有IoC
        1. Service 层想要使用 Dao 层的具体实现的话，需要通过 new 关键字在`UserServiceImpl` 中手动 new 出 IUserDao 的具体实现类 `UserDaoImpl`
        2. 但如果此时, 针对IUserDao 接口开发出另一个具体实现类, 那么就需要手动修改`UserServiceImpl`中new的对象
    3. `Bean` 代指的就是那些被 IoC 容器所管理的对象
3. AOP (Aspect-Oriented Programming:面向切面编程)
2. Spring, SpringMVC, SpringBoot
    1. SpringMVC 是Spring中一个`子模块`, 主要提供快速构建`MVC架构的Web程序`的支持
        - MVC 是模型(Model)、视图(View)、控制器(Controller)
        - 核心思想是通过将业务逻辑、数据、显示分离来组织代码。
    2. SpringBoot 是对`Spring/SpringMVC的封装`, 核心是`约定大于配置`, 简化了之前开发SpringMVC应用所需要的各种配置, 还提供很多开箱即用的功能
## 1.Bean
- Bean 代指的就是那些被 IoC 容器所管理的对象
1. @Component 和 @Bean的区别
    1. @Component 注解作用于`类`，而@Bean注解作用于`方法(返回对象的Supplier)`。
    2. 使用
        2. 需要先通过`@ComponentScan`定义扫描路径, 然后@Component通过扫描加入容器
        3. @Bean则是表示, 标有该注解的方法会`生成`这个Bean, 告诉Spring把这个返回结果加入容器
2. 注入Bean有三种方法
    1. 构造方法注入, 把该类所依赖的对象通过构造方法来设置
        - 这是最推荐的, 用于`必须依赖项`
        1. 确保所需依赖项在初始化时`一定会被注入`, 避免空指针, 也减少了潜在错误
        2. 不可变性: 有助于创建不可变的对象
        3. 测试便利性: 单元测试的时候, 不需要依赖Spring注入
    2. Setter注入, `@Autowired + setXXX(){...}`, @Autowired可以不写
        - 主要用于不适合全部初始化的 `可选依赖项`
    3. 字段Field注入,  直接在类所依赖的成员对象上面标注注解`@Autowire/@Resource`
### 1.1 Bean的作用域
- `singleton` : IoC 容器中只有`唯一的 bean 实例`。Spring 中的 bean 默认都是单例的，是对单例设计模式的应用。
- `prototype` : 每次获取都会创建一个新的 bean 实例。也就是说，连续 getBean() 两次，得到的是不同的 Bean 实例。
    - @Scope(value = ConfigurableBeanFactory.SCOPE_PROTOTYPE)
1. Bean是线程安全的吗?
    -  Bean 是否线程安全，取决于其作用域和状态
    1. 默认的singleton, 单例模式
        - IoC容器中只有`唯一的`Bean实例, 如果如果这个 bean 是`有状态`的话，那就存在线程安全问题
        - 有状态 Bean 是指包含`可变的成员变量的对象`, 比如里面包含`当前用户id`之类的信息时, 会在多线程的情况下被覆盖
    2. prototype, 每次获取都会创建一个新的 bean 实例，不存在资源竞争问题，所以不存在线程安全问题。
2. 如何确保单例模式下, Bean的线程安全?
    1. 核心原则: 设计`无状态`的Bean
        - 不要在Bean里面定义`可变的成员变量`, 这种情况下Bean就是线程安全的
    2. 对需要处理的`可变状态`(用户登录状态,请求上下文), 通过`线程隔离`的方法避免共享
        - 使用 `LocalThread`,为每个线程创建独立的变量副本
        - 然后配合 拦截器/过滤器, 在请求开始时设置、请求结束时`清除ThreadLocal数据`
    3. 对于`不可避免的共享资源`(数据库、Redis, 配置)
        1. 数据库
            1. 利用数据库`Spring的事务（@Transactional）`的 ACID 特性，隔离并发读写
            2. 针对并发更新, 使用乐观锁（如version, 时间戳）或悲观锁(FOR UPDATE, 强制锁定行/表)
                - 乐观锁：仅当version匹配时更新，避免并发覆盖
        2. 缓存方面(Redis)
            1. 使用 Redis 的`原子操作`（如incr、decr、setnx）替代 “查询 - 修改 - 更新” 的非原子操作
            2. 在分布式的情况下,用 `Redis分布式锁`（如 Redisson）保护临界资源
        3. 全局变量
            1. 全局配置 都使用`final`修饰
            2. 对于`可变的全局状态`, 使用安全的 `AtomicInteger`,`ConcurrentHashMap`
    4. 修改Bean的作用域, 通过@Scope修改作用域，避免单例共享
## 2. Spring AOP (Aspect-Oriented Programming:面向切面编程)
- 可以将(事务处理、日志管理、权限控制等)封装起来，便于减少系统的重复代码
1. SpringAOP 实现原理
    1. 如果 `目标类实现了某个接口`, 直接使用 `JDK Proxy` 创建代理对象
    2. 如果 `目标类没有实现接口`, 使用 `CGLib` 创建代理对象
2. 如何使用
    - 但`SpringAOP`功能相对较少, 一般用`AspectJ`的比较多
        - SpringAOP复用了AspectJ得注解
        - SpringAOP只能拦截Bean
        - AspectJ能拦截拦截静态方法 / 字段, 支持更多语法
    1. 添加相关依赖
        - `spring-boot-starter-aop`
        - 或者`org.aspectj`
    2. 创建切面类
        ```java
        @Aspect // 标记为切面类
        @Component // 交给Spring容器管理
        @Order(3) //可选, 如果有多个切面类的时候, 数字越小优先级越高
        public class XXXAdvice{

            @Pointcut("execution(* com.example.missyou..*.*(..))") //切入点表达式
            public void methodExecutePointcut() {
                // 切入点仅做标记，无业务逻辑
            }

            @Around("methodExecutePointcut()") //环绕通知：在方法执行前后执行
            public Object recordExecuteTime(ProceedingJoinPoint joinPoint) throws Throwable {
                //前
                try{
                    joinPoint.proceed();
                }finally{
                    //后
                }
            }
        }
        ```
3. 其他通知类型
    - @Around（前置逻辑）→ @Before → 目标方法执行 → @Around（返回/异常逻辑）→ @AfterReturning / @AfterThrowing → @After → @Around（finally逻辑）
    1. 选择
        1. 仅需 “前置操作”（日志、校验）→ 用@Before；
        2. 仅需 “正常返回后操作”（出参处理）→ 用@AfterReturning；
        3. 仅需 “异常处理”→ 用@AfterThrowing；
        4. 仅需 “收尾操作”→ 用@After；
        5. 需 “控制方法执行流程”（统计耗时、限流、修改返回值）

```java
@ResponseBody

      //......
    }

    //需要一个兜底异常（Exception.class）, 打印完整堆栈以供排查问题
}
```

## 4. Spring事务
- Spring 事务的底层是AOP，通过动态代理为目标方法织入事务逻辑
### 4.1 声明式事务(@Transactional)
- 通过@Transactional注解标记`方法/类` , Spring`自动为其管理事务`（开启、提交、回滚），无需手动编写事务代码，无侵入性
1. 需要注意
    1. @Transactional只能标注在`public方法`上,如果是类, 则只有public方法生效 (AOP仅能代理public方法)
    2. 内部调用问题, A调用B时, B的事务不生效(AOP 代理无法拦截内部调用)
    3. Spring需要`感知到异常`才会回滚, (如果catch了, 在里面要再抛出)
2. @Transactional的参数(8个最常用)
    1. `rollbackFor = Exception.class //所有类型的异常都回滚` 
        - 指定触发事务回滚的异常类型
        - Spring 默认仅对RuntimeException（运行时异常）和Error触发回滚，对Exception（检查型异常，如 IOException、SQLException）不回滚。
    2. `noRollbackFor = IllegalArgumentException.class`
        - 指定某些异常不要回滚
    3. `Propagation.REQUIRED //默认`
        - 事务传播行为（多方法调用时的事务规则）
    4. `Isolation.DEFAULT`
        - 事务隔离级别（解决脏读、不可重复读、幻读）
    5. `readOnly = true`
        - 是否为只读事务, 查询型方法可以用这个提高效率
    6. `timeout = 5`
        - 事务超时时间（秒），超时自动回滚
    7. `transactionManager = "mysqlTransactionManager"`
        - 指定事务管理器（存在多个数据源的时候）
    8. `label = {"order", "create"}`
        - 事务标签（用于监控 / 日志）
3. 内部调用失效 与 事务传播行为的区别
    1. 内部调用失效 (发生在`一个Service类`中)
        1. 一个Service类中, funcB上标注了事务注解
        2. 在同一个类中的funcA方法中, 使用`this.funcB`的话, funcB的事务会失效
            1. 原因: this指向原始对象，而非代理对象, 从而跳过了代理
        3. 解决方法是拆成多个Bean
    2. 事务的传播 (发生在`多个Service类`中)
        1. OrderService中有一个带事务的funcA, 最后需要提交log
            - 如果直接在里面提交Log, 那么回滚的时候日志的提交也会被回滚
        2. 做一个LogService, 提供一个带事务(`Propagation.REQUIRES_NEW`)的funcB
        3. 让funA中调用 `logService.funcB()`
        4. 具体执行流程:
            1. 调用funcA时, `开启主事务`
            2. 执行到log.funcB()时, `暂停主事务、新建独立事务`, 日志插入提交
            3. 恢复主事务, 订单插入提交
3. 事务传播行为 Propagation(重点有四个)
    - 解决业务层方法之间互相调用的事务问题, 当事务方法被另一个事务方法调用时，必须指定事务应该如何传播。
    1. `REQUIRED` (默认)
        - 有事务则加入，无则新建, 
        - 普通业务方法, 下单(主事务)+扣除库存(子事务), 要么都成功,要么都失败
    2. `REQUIRES_NEW`
        - 无论是否有事务，都新建独立事务（新事务与外层事务隔离）
        - 日志记录、消息发送(当主事务回滚时, 日志不随着一起回滚)
    3. `SUPPORTS`
        - 有事务则加入，无则以非事务执行
        - 通用查询方法（兼容事务 / 非事务场景）
            1. 如果调用方有事务（比如 “下单后立即查询订单”），则加入事务
            2. 如果调用方无事务（比如 “用户手动查询订单”），则以非事务方式执行（避免不必要的事务开销）
    4. `NOT_SUPPORTED`
        - 以非事务执行，有事务则挂起(耗时较长的非核心操作（避免占用事务）)
        1. 比如现在需要调用一个第三方的库, 可能需要5秒钟, 使用NOT_SUPPORTED可以让主事务暂时挂起
        - 这样在此期间, 主事务会暂时不占用数据库的连接, 在高并发的情况下很有用
4. 事务隔离级别 Isolation
    1. 数据库三大问题
        1. 脏读(Dirty Read)：读到了别的事务还`没提交的数据`。
            - 结果对方回滚了, 导致你读到这条数据无效
        2. 不可重复读(Non-repeatable Read)：同一事务内读同一行，`值`变了； 
            - 别的事务在你的事务执行时修改并提交了这行。
        3. 幻读(Phantom Read)：同一事务内读同一条件，`行数`变了
            - 别的事务新增 / 删除了数据，像 “幻觉” 一样
    2. Spring事务提供的参数(按方法需求来指定)
        1. `DEFAULT`, 根据数据库, 使用默认级别
            1. MySQL 默认`REPEATABLE_READ`, 可重复读
            2. Oracle 默认`READ_COMMITTED`, 读已提交
        2. `READ_UNCOMMITTED`, 读未提交, 几乎不用
        3. `READ_COMMITTED`, 读已提交, 仍存在不可重复读、幻读
            - 商品详情查询
        4. `REPEATABLE_READ`, 可重复读, 仍存在幻读
            - 金融转账, 保证可重复读即可
        5. `SERIALIZABLE`, 事务串行执行（完全禁止并发）
            - 账务清算, 要求绝对一致
     
### 4.2 编程式事务
- 通过`TransactionTemplate`或`PlatformTransactionManager`手动编写事务逻辑，适合需要精细控制事务（如条件回滚、多事务分支）的场景。
1. 推荐 TransactionTemplate
    ```java
    @Service
    public class OrderService {
        private final TransactionTemplate transactionTemplate; //依赖
        //注入
        public OrderService(TransactionTemplate transactionTemplate) {
            this.orderMapper = orderMapper;
            this.productMapper = productMapper;
            this.transactionTemplate = transactionTemplate;
        }

        // 
        public void createOrder(Long userId, Long productId, Integer num) {
            // 手动控制事务
            transactionTemplate.execute(status -> {
                try {
                    //库存不足时, 手动标记回滚
                    status.setRollbackOnly();
                    throw new RuntimeException("库存不足");

                    //没问题的话
                    return true; // 事务提交
                } catch(E e){
                    status.setRollbackOnly();
                    throw new RuntimeException("创建订单失败", e);
                }
            }
        }
    }
    ```
