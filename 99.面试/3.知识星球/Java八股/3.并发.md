## 1. 概念
### 1.1 进程, 线程, 协程
1. `进程`(车间), 系统运行程序的基本单位
    - CPU 密集用多进程
    - 进程是程序的一次执行过程
2. `线程`(工人), 一个进程包含多个线程, 是CPU调度的最小单元
    - 适合IO 密集型任务, `在同一时间需要完成多项任务时`就需要用到线程
    - 多个线程共享进程的堆和方法区资源
    - 每个线程有自己的程序计数器、虚拟机栈和本地方法栈
3. `协程`(任务清单)
    - 适合超高并发
    - 一个工人（线程）可以拿着多个任务清单
    - 执行与否, 顺序, 均由工人控制, 进程 / 线程由操作系统内核调度，协程由用户代码调度（更灵活）。
### 1.2 并行, 并发
- 描述执行多个任务的方式
1. `并行` Parallelism, 多个任务真正同时执行(真同时)
    - 必须多核 CPU, 比如多核计算密集型任务
    - 提高任务执行速度
2. `并发` Concurrency, 多个任务交替执行(假同时)
    - 单核 CPU 即可实现, 比如单线程处理多 IO 请求
    - 提高资源利用率
### 1.3 同步,异步
- 描述任务的执行方式和结果获取方式
1. `同步` Synchronous
    - 调用方 必须`等待` 被调用方 完成任务，期间不能做其他事。
2. `异步` Asynchronous
    - 调用方 发起任务后, 不用等待, 可以继续做别的事, 任务完成后通过`回调/事件`获取结果
### 1.4 阻塞（Blocking）vs 非阻塞（Non-blocking）
- 描述程序在等待某个操作完成时的状态, 挂起/非挂起
1. `阻塞` Blocking
2. `非阻塞` Non-blocking
3. 同步 / 异步 ≠ 阻塞 / 非阻塞
    1. 同步可以是阻塞（如普通 time.sleep），也可以是非阻塞（如轮询检查任务状态）；
    2. 异步通常是非阻塞的（如 asyncio.sleep）。

## 3. synchronized (隐式锁内置锁)
- 优点: 语法简洁、无需手动释放
### 3.1 synchronized 同步锁机制
- 同步锁是 “思想 / 概念”，synchronized 是 Java 中实现这种思想的具体工具
1. synchronized关键字
    - 同一时间只有一个线程执行这段代码
    1. synchronized可以修饰什么
        1. 同步代码块, `synchronized (同步锁){...}`
        2. 同步方法, `synchronized void func(){...}`
        3. 静态同步方法, `static synchronized void func(){...}`
    1. 哪些代码应该放入同步代码块?哪些不应该
        1. 不要将整个while循环放入同步代码块
        2. 可以将处理函数放入
2. 什么能作为同步锁
    - 同步监听对象/同步锁/同步监听器/互斥锁 都是同步锁
    - 同步代码块想用哪个都可以
    1. 对象类型
        1. new Student()
        2. new Object()
        3. this, 同步方法用的是这个
    2. 类 类型
        1. Student.class, 静态同步方法用的是这个
        2. Object.class
### 3.3 死锁
1. 概念
    - 多个线程`互相持有对方需要的锁`，且`都不肯释放自己的锁`，导致所有线程都陷入`永久阻塞`的状态。
2. 实现死锁的条件
    1. 两个线程分别持有不同的锁 
        - 两个类分别有两个静态同步方法(同步锁为 ClassA.class, ClassB.class)
    2. 两个持有不同锁的线程争夺对方的锁
        - 两个静态方法中(各自持有自己的锁)分别调用对方(争夺对方的锁)
### 3.4 synchronized的等待唤醒机制
- wait(), notify(), notifyAll()
1. Thread.sleep() 与 object.wait()
    1. Thread.sleep(), 静态方法, 让当前线程休眠指定时间，`不会释放锁`
        - 时间到自动唤醒, 唤醒后直接进入 RUNNABLE（就绪）状态
    2. this.wait(), 让线程进入`等待状态`，必须在`同步代码块中`调用，且会`释放锁`
        - `synchronized (this){ this.wait(); }`
        - 被 notify()/notifyAll() 唤醒；2. 超时自动唤醒; 需重新竞争锁
2. notify() `唤醒的是在锁上等待的线程`
    - 在main()方法中调用 task.notify()方法唤醒`单个线程`
        - 即使有多个线程, 也`只能唤醒一个线程`
    - 和wait()一样, 也需要写在同步代码块中
        - 上面的this表示`task实例`, 因此这里用task调用notify()
        - `synchronized (task){ task.notify(); }`
3. notifyAll()
    - 唤醒所有等待的线程
    - - `synchronized (task){ task.notify(); }`
### 3.5 生产者消费者模型 wait() notify()应用
1. 生产者线程 ,消费者线程
    1. 生产者生产数据时, 消费者等待
        - 以`data实例`作为同步锁
    2. 生产者生产完毕, 唤醒消费者进行消费, 随后生产者等待
        - `synchronized (data){ 生产; data.notify(); 然后data.wait()}`
    3. 消费者消费完毕后, 唤醒消费者线程, 如此反复
        - `synchronized (data){ 消费; data.notify(); 然后data.wait()}`

### 4.5 读锁, 写锁
- 顶层接口是 `ReadWriteLock`读写锁
1. 读锁 (共享锁)
    - 同一时刻, 每个线程都能拿到锁
    - 然后分别释放锁
2. 写锁 (独占锁)
    - 同一时刻, 只有一个线程能拿到锁
#### 4.5.1 读锁 (共享锁)
1. 使用
    1. 定义读写锁
        - `ReadWriteLock rwLock = new ReentrantReadWriteLock(true);`
    2. 用rwLock取得读锁
        - `Lock readLock = this.rwLock.readLock()`
    3. 后面用法就一样了
2. 执行效果
    - 多个线程`不会相互阻塞`, 因为读锁是共享锁, 多个线程都能拿到锁
#### 4.5.2 写锁 (独占锁)
1. 使用
    1. 定义读写锁
        - `ReadWriteLock rwLock = new ReentrantReadWriteLock(true);`
    2. 用rwLock取得读锁
        - `Lock writeLock = this.rwLock.writeLock()`
    3. 后面用法就一样了
2. 执行效果
    - 多个线程`会相互阻塞`, 因为写是独占锁, 多个线程依次拿到锁
#### 4.5.3 读写锁的应用(高并发容器)
1. 高并发容器
    - 键值对(HashMap), 读写锁, 存, 取
2. 写入数据, 同时只有一个线程
    1. get方法(读操作)
        1. r.lock()
        2. return m.get(key)
        3. finally r.unlock()
3. 读取数据, 同时多个线程获取数据
    1. set方法(写操作)
        1. w.lock()
        2. return m.put(k, v)
        3. finally w.unlock()

## 5. ThreadLocal 线程本地变量
1. ThreadLocal的定位
    - 这是一个操作线程属性的工具类
    - 为每个线程创建`独立的变量副本`，线程只能访问自己的副本，不同线程之间互不干扰。
    - `每个线程专属的储物柜,用完记得 “锁门（remove）”`
2. ThreadLocal与Thread的关系
    - Thread负责存储数据
    - ThreadLocal负责操作数据
3. `class ThreadLocal<T>{...}`
    1. 方法
        1. withInitial(Supplier<? extends S> supplier)
            - 创建ThreadLocal
        2. get(), 获取 ThreadLocal`在当前线程中保存的`变量副本
            - 数据不是保存在ThreadLocal里面
        3. set(), 设置
        4. remove(), 用完记得删除
    2. 属性(重要)
        1. static class ThreadLocalMap{...}
            - 这个内部类主要用于维护线程的本地变量, 定制化的 HashMap
            - 里面是一个Entry
### 5.1 ThreadLocal具体用法
1. 创建ThreadLocal
    - ThreadLocal<String> tl = new TreadLocal<>();
2. 重写Thread的run()方法
    - 设置ThreadLocal在`当前线程中`保存的`数据副本`
    - tl.set("Thread0")
3. 这个数据是不可能在其他线程中获得的
    - 只能在当前线程 tl.get()
4. 最后删除数据副本 tl.remove()
    - 重要! 否则可能发生内存泄露
### 5.2 线程间 如何共享ThreadLocal

## 6. volatile 关键字 `JMM`
- 用来解决`内存可见性`问题
- 是Java 提供的轻量级同步机制，核心作用是：保证变量的 “可见性” 和 “有序性”，但不保证原子性。 
1. 什么是内存可见性问题
    1. 两个线程
        - `static boolean isStop = false` 
        - 一个线程while(!isStop){...}
        - 另一个线程过一秒后修改 isStop为true
    2. 问题
        - 第一个线程并不知道isStop的值改变了,因此不会停下来
    3. 总结
        1. `内存可见`,多个线程共享值时, 一个线程修改, 另一个线程能及时拿到最新的值
        2. `内存不可见`,另一个线程无法及时得到最新的值
    4. Java内存不可见原理
        1. 内存分为 `主内存`, 各个线程自己的`工作内存`
        2. 两个线程一开始会把isStop缓存到`工作内存`中
        3. 其中一个线程修改后, 会改变`主内存`, 但是并没有主动告诉另一个线程
2. volatile 修饰一个变量
    - `static volatile boolean isStop = false`,即可
    - 这个关键字可以解决内存可见性问题
## 7. JUC 原子类
- 一个或多个操作是不可中断的, 要么全部成功, 要么全部失败
1. i++ 是原子操作吗?
    - 多线程测试发现 i++ 并不是原子操作
    1. 其实有三步, 每一步都有可能被其他线程修改
        1. stpe1: 从主内存读取变量i
        2. step2: 执行i++
        3. step3: 将变量i写入主内存
2. `volatile int i` 能解决这个问题吗?
    - 不能, 原子性要求 “操作不可被中断”，而 volatile 仅保证单变量读写的可见性 / 有序性，无法约束多步复合操作的完整性
    1. volatile能确保`单次读写的正确性`
        1. step1, 读取的一定是主内存最新值
        2. step3, 修改后立即反映到主内存
        3. 这三步的顺序一定争取
    2. volatile的边界:
        - 无法阻止其他线程在这三步之间插入操作
3. `synchroined (this){i++}` 能解决这个问题吗?
    - 可以
4. 还可以用`原子类`来确保原子性
    - `AtomicInteger i = new AtomicInteger(0)`
    - 然后i++改成`i.getAndIncrement()`
### 7.1 CAS技术
- Compare And Swap，比较并交换
- 这个`技术`能解决线程执行期间被其他线程影响的问题
1. CAS操作包含三个值
    1. 内存值
    2. 预期原值
    3. 新值
2. 如何使用
    1. 定义这个方法
        1. public static boolean compareAndSwap(三个参数)
            1. int oldValue, 内存值
            2. int expectedValue, 预期原值
            3. int newValue, 新值
            4. boolean返回值表示: 若设置成功则返回false
        2. 比较什么? 交换什么?
            1. if(内存值 == 预期原值) 内存值 = 新值, 返回true
            2. if(内存值 != 预期原值) 什么也不做, 返回false
    2. 在main()中使用
        1. 在线程中的run()方法中
            1. 一开始就 int oldValue = i
            2. 之前i+1的地方改成
                - reuslt = compareAndSwap(i, oldvalue, i+1)
            3. 若result为false, 则说明收到了其他线程的影响
3. 这个原理在原子类内部用的很多
4. CAS的`ABA问题`
    - 一个值一开始是A, 后来变成B, 然后又变成A
    - CAS会认为这值没变, 但实际上是变化了的
    - 解决思路是在变量前面追加上版本号或者时间戳。JDK 1.5 以后的`AtomicStampedReference` 类就是用来解决 ABA 问题的
