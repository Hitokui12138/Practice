# 项目2
● 项目名称: 云平台Kubernetes环境构建
● 项目介绍: 配合甲方Pega系统版本升级，推进部署流程标准化改造，将原有部署形态迁移至GCP/AWS容器化云平台，提升交付效率、环境一致性与运维可控性，支撑系统平稳升级上线。
● 涉及技术: Google Cloud（GKE/VPC/Firewall/Cloud Armor/DNS），AWS（EKS/VPC/Security Group/NACL/Route53），Docker,  Kubernetes, Helm
● 负责工作: 
  1. Kubernetes 云平台环境交付（GCP/AWS）
      1. 在 GCP 上搭建并配置 GKE 集群（节点池、权限、基础组件等），输出标准化部署与运维操作手册，支持项目交付与后续复用。
      2. 在 AWS 上搭建并配置 EKS 集群（网络、节点、访问控制等），沉淀一致化环境基线与部署规范，保障多环境一致性。
      3. 结合 Helm Chart 形成可重复部署的交付方式，提升部署效率并降低人工差错。
  2. 网络与安全架构设计
      1. 负责设计VPC 与子网划分、路由与访问边界，明确集群内外流量路径与隔离策略。
      2. 负责域名与 DNS 配置管理，打通对外访问与证书/解析策略，确保业务访问链路稳定。
      3. 实现并测试云安全策略：GCP 防火墙与 Cloud Armor、AWS Security Group 与 NACL 的规则设计与测试，满足最小权限与边界防护要求。
  3. 第三方服务部署
      1. 在 GKE/EKS 环境中部署并联调 Pega Constellation，完成关键组件验证与运行稳定性测试。
      2. 负责与 Pega 原厂沟通技术方案与疑难问题定位，推进问题修复与上线节奏对齐。

1) 入口与公网访问（必须）

路线A：云负载均衡直连 Service（不需要 Ingress）（最符合你现状）

Kubernetes Service type=LoadBalancer

云上会自动创建一个公网 LB（GCP/AWS），拿到公网 IP/域名入口

DNS 把你的域名解析到这个 LB

HTTPS：在云 LB 上配置证书（或在应用侧终止 TLS）

“我们用 Helm 把应用及其依赖的 K8s 资源模板化（Deployment/Service/ConfigMap/Secret），通过 values 区分不同环境，实现可重复部署与可回滚。”

测试环境我们通过域名走公网访问。集群侧用 Service LoadBalancer 暴露入口，由云厂商创建公网负载均衡，再将域名 DNS 解析到该入口；安全侧通过防火墙/安全组限制来源网段，并可叠加 WAF/Cloud Armor 做基础防护。部署采用 Helm 模板化，按环境 values 管理配置，实现快速部署、升级与回滚。
