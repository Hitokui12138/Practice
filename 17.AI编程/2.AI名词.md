# 闪客的核心论点整理
**闪客的核心论点**：所有概念都是“提示词工程”的变体
闪客用了一个非常巧妙的叙事方式——让你扮演老板，LLM是你的员工“小工”，然后一步步“压榨”它，每压榨出一个新能力，就**发明一个新名词**。

## 一、名词详解清单
| 新词 | 本质 | 闪客的吐槽 |
| :--- | :--- | :--- |
| LLM | 一个全文字接龙的模型，参数大了就涌现智能 | 就加了个大一字 |
| Prompt | 你跟小工说的话 | 起了个洋名气罢了 |
| Context | Prompt里的背景信息部分 | 拆出来单独起名 |
| Memory | 把历史对话塞进Context伪装多轮对话 | 小工本身不能追问，这是hack |
| Agent | 你和小工之间的一层代理程序 | 早期就是多加了一prompt，简直诈骗 |
| RAG | 用向量数据库把本地文档塞进Context | 检索增强生成，本质是上文塞信息 |
| Search | 联网搜索塞进Context | 和RAG一样，都是获取模型参数外的信息 |
| Function Calling | Agent和大模型之间约定的回复格式 | 就是个接口的定义 |
| MCP | Agent和工具服务之间的调用约定 | 也是个接口的定义，和FC完全不搭嘎 |
| Skill | 提前写好的说明文档/脚本，放在指定目录 | 新瓶装旧酒的prompt加载器 |
| Sub Agent | 子任务单独开上下文处理 | 本质就是上下文隔离 |
| Workflow | 低代码拖拽式任务编排 | LangChain的傻瓜版 |

## 二、最精华的洞察：刚性-柔性光谱
闪客给出了一条从**刚性**到**柔性**的技术演进线：
> LangChain（传统硬编） → Workflow（低代码拖拽） → Skill（说明文档/脚本） → Agent（完全自主）
> （灵活性不可控 ←————————————→ 灵活性不可控）

Skill处在中间位置——兼顾灵活性和稳定性，闪客认为它会逐渐淘汰MCP和Workflow，但Skill本身也是中间产物。

## 三、对“邪恶财团A”的吊打要点
闪客点出了几个很犀利的事实：
1. Agent≠所有不需要智能的部分构成的东西 —— 模糊分流交给大模型，确定逻辑交给程序，仅此而已
2. 所有技术本质上只做两件事：**往提示词里自动塞上下文** + **通过代理减少人和大模型的沟通次数**
3. Function Calling vs MCP：完全不是一个维度的东西，叫MCP（或者活化石）是无稽之谈
4. Skill vs MCP：也不冲突，但Skill确实可以把MCP的功能全包进去
5. Web3Bot为什么火？和其他Agent没有本质区别，就是因为它能让普通人一次就得“这像个智能体”而不是躺在电脑上的服务

## 四、闪客的预判
未来一定会有一个打包好的超级Agent，所有MCP、Skill等乱七八糟的东西都配置好了，普通人啥都不用配置就能直接用。提供便利的方向，就是趋势。
