1. SQL查询慢怎么办
    1. 最简单粗暴的就是建立一套缓存系统(Redis), 系统启动或者离线时预先把数据存在缓存中
        - 但缓存很贵, 维护也不便宜
        - 同步和一致性问题, (Redis雪崩)
            - 大量缓存同时失效 → 所有请求瞬间打向数据库 → 数据库扛不住 → 整个系统崩掉。
2. 关系性数据库内部的数据一致性 
    1. 事务
        1. 四大特性`ACID`
            - Atomicity原子性, Consistency一致性, Isolation隔离性, Durability永久性
        2. 隔离级别
            1. 读未提交（Read Uncommitted）
                - 最低级别，完全不隔离, 脏读、不可重复读、幻读
            2. 读已提交（Read Committed）
                - 只能读到别人已提交的数据, 解决脏读
            3. 可重复读（Repeatable Read） MySQL InnoDB 默认级别 
                - 同一个事务里，多次读取结果一致, 解决脏读、不可重复读
                - InnoDB一定程度上可以解决幻读
            4.  串行化（Serializable）
                - 最高级别，事务排队执行, 因此并发性能最差
        3. 由此引申各种问题
            1. 脏读：读到了别的事务还没提交的数据。(别人可能回滚)
            2. 不可重复读：同一行数据前后不一致 (别的事务修改并提交了这行。)
            3. 幻读：查询出来的行数变了 (别的事务新增 / 删除了数据，像 “幻觉” 一样)
        4. Mysql和Oracle的事务的区别
            - MySQL 默认：可重复读
            - Oracle 默认：读已提交
    2. 锁机制
        - InnoDB 会自动给 INSERT/UPDATE/DELETE 加排他锁（X 锁），给普通 SELECT 不加锁（快照读）。
        - 订单的库存归还
3. 索引
    1. 常用: 对外键, 或者频繁查询的项目上加索引
    2. 无效索引, 有时即使加了索引, 还是会执行全盘扫描
    3. 不同的索引
        1. FullText索引
        2. BTree索引
