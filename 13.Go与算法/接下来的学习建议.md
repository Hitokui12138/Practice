## 推荐学习路线（按优先级排序）

### 阶段一：补齐 Go 并发核心（2-3 周）

你的并发笔记只覆盖了 Goroutine 和 Channel 的基础，这是 Go 最区别于其他语言的领域，必须深入。

| 优先级 | 主题 | 学习目标 | 推荐资源 |
|--------|------|---------|---------|
| 🔴 必学 | **GPM 调度模型** | 理解 G/P/M 三级调度、工作窃取、抢占调度、系统调用处理 | 《Go 语言设计与实现》调度器章节 |
| 🔴 必学 | **sync 同步原语** | Mutex 正常模式/饥饿模式、RWMutex、atomic 无锁编程、sync.Pool、sync.Cond | 官方文档 + 源码阅读 |
| 🔴 必学 | **select 进阶** | nil channel 技巧、time.After 泄漏问题、fan-in/fan-out、or-done channel | Go Concurrency Patterns 演讲 |
| 🟡 建议 | **context 深入** | 超时层层传递、取消传播链、WithValue 只传请求范围数据、自定义 context | 官方 blog |
| 🟡 建议 | **并发模式** | Pipeline、扇出扇入、errgroup 错误传播、限流（rate.Limiter）、任务编排 | 《Concurrency in Go》 |

**练习项目**：
- 实现一个并发安全的 LRU 缓存（sync.Mutex + map + 链表）
- 用 channel 实现一个简单的 Pub/Sub 系统
- Worker Pool：N 个 worker 从 channel 消费任务，带优雅关闭

### 阶段六：算法 & 数据结构（长期穿插）

算法目录只有一个空文件和一个数组笔记。建议作为长期任务每周 3-5 题。

| 阶段 | 主题 | 建议题量 |
|------|------|---------|
| 基础 | 链表、栈、队列、哈希表 | 每种 5-8 题 |
| 核心 | 二叉树/二叉搜索树、堆（用 Go 的 container/heap） | 每种 5-10 题 |
| 重点 | 排序（快排/归并）、二分搜索、双指针、滑动窗口 | 每种 5-8 题 |
| 进阶 | 回溯（排列组合）、BFS/DFS 图遍历 | 每种 5 题 |
| 拔高 | 动态规划、Union-Find、单调栈、Trie | 视情况 |
| 实战 | LeetCode Hot 100 / 剑指 Offer | 100 题 |

**Go 特定注意**：
- Go 没有内置 Stack/Queue，用 slice 模拟或用 `container/list`
- 用 `container/heap` 实现优先队列（堆），而非自己写
- DFS 可用递归或显式栈，递归注意栈深度（Go 栈可增长，通常够用）
- 用 `math.MaxInt`/`math.MinInt` 做哨兵值

## 学习节奏建议

```
Week 1-3:   补齐并发（GPM/Mutex/select/context）
Week 4-6:   补齐工程化（testing/pprof/errgroup/项目结构）
Week 7-9:   补完社交媒体项目 + Web/数据库
Week 10-12: 消息队列/服务发现 + 微服务拆分
Week 13+:   源码阅读 + 算法（长期穿插，每次 30-60 分钟）
```

**核心原则**：
1. **以项目驱动学习** — 每学一个知识点就嵌入到项目中，不要孤立学习
2. **学习金字塔** — 读完文档后立刻写代码，然后教别人（写笔记/博客）
3. **二八原则** — 日常开发 80% 的场景只用到 20% 的知识，优先掌握高频场景
4. **源码即文档** — Go 标准库的源码本身就是最好的编程教材，遇到问题 Ctrl+Click 进去看

你的笔记质量很高，尤其是 Redis 部分对底层数据结构的理解深度超出了一般开发者。但有两个明显短板：
