## 一、Go 语言核心

### 1.1 变量、类型、控制流

| 知识点 | 要点 |
|--------|------|
| 变量声明 | `var` 声明零值初始化；`:=` 短声明（仅函数内）；`type` 定义新类型 |
| 基本类型 | `int`(平台相关)/`int64`/`float64`/`complex128`/`bool`/`string`；Go 无隐式类型转换 |
| 常量 | `const` 编译期确定值，`iota` 枚举自增 |
| 控制流 | `if` 可带初始化语句；`switch` 默认不穿透（无需 break）；`for` 是唯一循环关键字（可充当 while/C 风格 for/range） |
| 零值机制 | 每个类型都有零值（int=0, string="", pointer/map/slice/chan=nil），避免未初始化风险 |

### 1.2 函数 & 闭包

| 知识点 | 要点 |
|--------|------|
| 多返回值 | `func foo() (int, error)` — 常用于返回结果+错误 |
| 命名返回值 | `func foo() (n int, err error)` — 可 naked return（裸返回），建议只在短函数中使用 |
| 变参 | `func sum(nums ...int)` — 本质是切片 |
| 一等公民 | 函数可赋值给变量、作为参数传递、作为返回值 |
| 闭包 | 函数 + 其引用的外部变量 = 闭包；用途：计数器、缓存、中间件、数据库连接封装 |
| defer | LIFO 执行顺序，用于资源清理（文件关闭、锁释放）；**陷阱**：参数在 defer 声明时立即求值（非执行时）、nil 接收者方法调用不 panic |
| init 函数 | 每个包可有多个 `init()`，包导入时自动执行，不能手动调用 |

### 1.3 指针

| 知识点 | 要点 |
|--------|------|
| 本质 | 存储另一个变量的内存地址 |
| 运算符 | `&` 取地址，`*` 解引用 |
| 类型约束 | `*int` 只能指向 `int`，不能指向其他类型 |
| nil 指针 | 解引用 nil 指针会 panic |
| 使用场景 | ①避免大 struct 复制 ②函数内修改外部变量 ③构造链表/树等数据结构 |
| vs Java 引用 | Go 指针可做运算的受限替代（不直接支持指针运算），Java 引用是隐式的 |

### 1.4 数组 vs 切片（重点）

| | 数组 `[n]T` | 切片 `[]T` |
|-----|------------|-----------|
| 长度 | 固定，类型的一部分 | 动态 |
| 值/引用 | **值类型**（赋值=复制整个数组） | **引用类型**（header: ptr+len+cap） |
| 初始化 | `[3]int{1,2,3}` | `make([]int, len, cap)` |
| 扩容 | 不支持 | `append` 触发：<256 时翻倍，>=256 时增长约 12.5%（Go 1.18+，旧版 <1024 翻倍，>=1024 加 25%） |
| 切片表达式 | — | `s[low:high:max]` 可限制 cap，防止后续 append 覆盖底层数组 |
| 陷阱 | — | 多个切片共享底层数组，append 可能触发扩容分离；range 遍历的是副本 |

**补充（笔记未详述）**：
- `copy(dst, src)` 按 min(len(dst), len(src)) 复制
- 切片作为函数参数，修改元素会影响原切片，但 append 可能不会（取决于是否扩容）
- `nil` 切片 len/cap 为 0，但 `make([]int,0)` 返回的切片不是 nil（`data` 指针非 nil）

### 1.5 映射 Map

| 知识点 | 要点 |
|--------|------|
| 本质 | 哈希表，引用类型，**并发不安全**（并发写会 fatal error） |
| 初始化 | 必须 `make(map[K]V)` 或字面量 `{}`，nil map 写会 panic，读返回零值 |
| 操作 | `m[k] = v` 写；`v, ok := m[k]` 安全读（comma-ok 惯用法）；`delete(m, k)` 删除 |
| 无序性 | 遍历顺序随机（有意为之），防止依赖顺序 |
| 并发方案 | `sync.Mutex` + map 或 `sync.Map`（读多写少场景） |
| 不可比较 | map/slice/function 不能作为 key；struct 可作为 key 但字段必须可比较 |

**补充（笔记未详述）**：
- Go map 使用拉链法解决冲突，bucket 大小为 8
- 负载因子超过 6.5 或溢出桶过多时触发扩容（翻倍或等量迁移）
- 渐进式搬迁（evacuate），每次 map 操作迁移 1-2 个旧 bucket

### 1.6 结构体 & 方法

| 知识点 | 要点 |
|--------|------|
| 结构体 | 自定义复合类型，字段连续内存布局（可能有对齐填充） |
| 空结构体 | `struct{}{}` 不占内存（0 字节），常用于 map/set 的占位符或 channel 信号 |
| 方法 | `func (r Receiver) Method()` — 给类型添加行为，不能给内置类型/其他包的类型添加方法 |
| 值接收者 vs 指针接收者 | 值：操作副本，不修改原值，可并发安全；指针：修改原值，避免大 struct 拷贝；两者不可混用在同一方法集中（实践中通常统一用指针接收者） |
| new vs 字面量 | `new(T)` 返回 `*T`（零值）；`&T{...}` 更常用 |

**补充**：Go 方法集规则 — 类型 `T` 的方法集包含值接收者方法，类型 `*T` 的方法集包含值接收者和指针接收者方法。这影响接口实现判断。

### 1.7 接口 & 面向对象

| 知识点 | 要点 |
|--------|------|
| 接口定义 | 方法集合，**隐式实现**（duck typing）— 无需声明 implements |
| 组合优于继承 | Go 没有 `extends`，通过 struct 嵌入实现组合（has-a 模拟 is-a） |
| 方法提升 | 嵌入 struct，其导出方法自动"提升"到外层的同名方法集中 |
| 方法重定义 | 外层定义同名方法即"覆盖"内层（非真正的 override，内层方法仍可通过 `outer.Inner.Method()` 调用） |
| 接口组合 | `type ReadWriter interface { Reader; Writer }` |
| 空接口 | `interface{}`（Go 1.18+ 推荐用 `any`）可以表示任意类型，运行时需类型断言 |
| 类型断言 | `v, ok := x.(T)` — 安全断言；`switch v := x.(type)` — 类型分支 |

**补充（笔记未详述）**：
- 接口底层结构：`iface`（含方法的接口）= `tab`（类型信息+方法表指针）+ `data`（数据指针）
- `eface`（空接口）= `_type` + `data`
- **nil 接口陷阱**：一个接口值仅在 `tab` 和 `data` 都为 nil 时才等于 nil。`var p *T = nil; var i interface{} = p; i == nil` 为 `false`！

### 1.8 错误处理

| 知识点 | 要点 |
|--------|------|
| error 接口 | `type error interface { Error() string }` — 最简接口 |
| 处理模式 | `if err != nil { return err }` — 显式传播 |
| 错误包装 | `fmt.Errorf("context: %w", err)` + `errors.Unwrap()` / `errors.Is()` / `errors.As()` |
| panic/recover | panic 用于不可恢复错误（程序 bug）；recover 仅在 defer 中有效；禁止用作常规错误处理 |
| 哨兵错误 | `var ErrNotFound = errors.New("not found")` — 包级别导出错误变量，用 `errors.Is` 比较 |
| 自定义错误 | 实现 Error() 方法，可携带 Code、Message、Details 等上下文 |

### 1.9 泛型（Go 1.18+）

| 知识点 | 要点 |
|--------|------|
| 语法 | `func F[T constraint](a, b T) T` |
| 内置约束 | `any`（等价 `interface{}`）、`comparable`（可 == 比较的类型） |
| 标准约束 | `cmp.Ordered`（支持 < > 的有序类型）、`constraints` 包（已废弃，迁移至各子包） |
| 自定义约束 | `type Number interface { ~int | ~float64 }` — `~` 表示底层类型为该类型的派生类也算 |
| 类型推断 | 调用时可省略类型参数（由编译器推断） |
| 性能注意 | 泛型函数有轻微运行时开销（通过字典或单态化实现，Go 使用字典 GC 方案），与 interface{} 性能相当甚至更好 |

## 二、Go 并发编程

### 2.1 CSP 理论与 Goroutine

| 知识点 | 要点 |
|--------|------|
| CSP 哲学 | "Don't communicate by sharing memory; share memory by communicating" |
| Goroutine | 用户态轻量线程，初始栈 ~2KB（传统线程 1-2MB），由 Go 运行时 M:N 调度（调度器 GPM 模型） |
| vs 线程 | 创建/切换开销小 2-3 个数量级；一个 Go 程序可轻松运行数十万 Goroutine |
| sync.WaitGroup | 等待一组 goroutine 完成：`Add(n)`、`Done()`、`Wait()` |
| context.Context | 生命周期控制：取消传播（`WithCancel`）、超时控制（`WithTimeout`/`WithDeadline`）、值传递（`WithValue`，仅用于请求范围数据如 traceID） |
| goroutine 泄漏 | 因阻塞在 channel 或锁上永远无法退出的 goroutine — 用 context 和超时预防 |

**补充（笔记较薄弱 — GPM 调度模型）**：

```
G (Goroutine) — 用户态的轻量级任务
P (Processor)  — 逻辑处理器，数量 = GOMAXPROCS（默认 CPU 核数），每个 P 持有一个本地 runq
M (Machine)    — 操作系统线程，M 必须绑定 P 才能执行 G
```

调度流程：`G` 阻塞在系统调用 → `M` 挂起，`P` 绑定新 `M`；`G` 阻塞在 channel/锁 → `G` 移入等待队列，`M` 继续执行其他 `G`。工作窃取：当 `P` 的本地队列为空时，从其他 `P` 偷取一半的 `G`。

### 2.2 Channel

| 知识点 | 要点 |
|--------|------|
| 创建 | `make(chan T)` 无缓冲；`make(chan T, cap)` 有缓冲 |
| 无缓冲 vs 有缓冲 | 无缓冲：发送方阻塞直到接收方就绪（同步）；有缓冲：缓冲区满时发送阻塞，空时接收阻塞 |
| 操作 | `ch <- v` 发送；`v := <-ch` 接收；`close(ch)` 关闭 |
| 关闭后的行为 | 从已关闭 channel 接收：返回零值 + `ok=false`；向已关闭 channel 发送：**panic** |
| nil channel | 从 nil channel 收发会**永久阻塞**（可用于 select 中禁用某个 case） |
| select | 多路复用：随机选择就绪的 case；带 `default` 可非阻塞 |
| 单向 channel | `chan<- T`（只发送）、`<-chan T`（只接收）— 编译期保证 |
| 经典模式 | 生产者-消费者、扇出-扇入（fan-out/fan-in）、or-done channel、pipeline 模式 |

**补充（笔记未详述的 select 行为）**：
- 如果多个 case 同时就绪，**伪随机**选择一个（防止饥饿）
- 如果所有 case 都阻塞且有 `default`，执行 default
- 如果所有 case 都阻塞且无 `default`，整个 select 阻塞
- 空的 `select{}` 会永久阻塞，用于阻止主 goroutine 退出

### 2.3 同步原语（笔记缺失，此处补充）

| 原语 | 场景 | 关键注意 |
|------|------|----------|
| `sync.Mutex` | 临界区互斥 | Lock 后必须 Unlock（用 defer）；不可重入；复制会失效 |
| `sync.RWMutex` | 读多写少 | 读锁可并发，写锁互斥；写锁饥饿问题（写者等待时新读者会被阻塞） |
| `sync.WaitGroup` | 等待一组 goroutine | Add 必须在 goroutine 外完成（或确保在 Wait 之前） |
| `sync.Once` | 单次初始化 | Do 是阻塞的，内部函数 panic 后再次调用仍然执行 |
| `sync.Cond` | 条件变量/广播通知 | `Broadcast()` 唤醒所有等待者，`Signal()` 唤醒一个 |
| `sync/atomic` | 简单计数器/标志位无锁操作 | 仅适合简单值，复杂状态用锁；`atomic.Value` 存任意类型 |
| `sync.Map` | 读多写少/key 稳定 | 空间换时间，普通 map+Mutex 在写多场景更优 |
| `sync.Pool` | 临时对象复用 | 不保证对象存在（GC 时清理），适用于连接池、buffer 复用 |
| `errgroup` | 并发任务 + 错误传播 | `golang.org/x/sync/errgroup` — goroutine 中任一报错即取消全组 |

## 三、Go + Redis 核心知识

### 3.1 Redis 本质理解

| 维度 | 要点 |
|------|------|
| 定位 | 内存数据库，不是 DB 替代品，适合缓存/状态共享/计数/排行榜/限流/消息队列 |
| 单线程模型 | 一个 Redis 实例**主线程**同一时刻只执行一个命令（天然原子性，无需锁），但 6.0+ 网络 IO 可多线程 |
| 为什么快 | ①纯内存操作 ②单线程无锁上下文切换 ③IO 多路复用（epoll/kqueue）④高效的数据结构实现 |
| IO 多路复用 | 一个线程同时监听多个 socket，epoll 事件驱动：只有活跃连接才被处理（非轮询） |
| 避坑 | 禁止 `KEYS *`（O(N) 阻塞）、大 key（阻塞同线程其他请求）、大范围操作 |

### 3.2 五大核心数据结构及其底层

| 数据结构 | 用途 | 底层实现 | 关键设计 |
|----------|------|----------|----------|
| **String** | 缓存、计数、分布式锁 | **SDS**（Simple Dynamic String）：len+alloc+buf，O(1) 取长度，二进制安全，防溢出；编码优化（int/embstr/raw） | 与 C 字符串相比：不依赖 `\0`，可以存二进制；自动扩容，不会缓冲区溢出 |
| **Hash** | 对象存储、用户资料 | 小对象 → **listpack**（紧凑连续内存，无指针）；大对象 → **hashtable**（dict）+ 渐进式 rehash | 存对象比 String(JSON) 更省网络：可以只取单个字段；key 命名规范 `user:{id}` |
| **List** | 消息队列、时间线 | **QuickList**：listpack 链表，平衡内存连续性与插入灵活性 | BLPOP 实现阻塞队列（零轮询 CPU）；局限性：无 ACK、无消费者组、无持久点位 |
| **Set** | 标签、共同好友、去重 | 纯整数小集合 → **intset**（有序数组）；大集合/非整数 → **hashtable**（只用 key，value 固定） | SINTER（交集）、SUNION（并集）、SDIFF（差集）— 集合运算 |
| **Sorted Set** | 排行榜、延迟队列 | **dict**（O(1) 查分）+ **skiplist**（O(logN) 范围查询）；跳表通过多层索引加速 | Score 设计：`点赞*10 + 评论*50 + 浏览*1`；时间戳做 score 实现时间排序 |

### 3.3 Go 接入 Redis 最佳实践

| 知识点 | 要点 |
|--------|------|
| 客户端 | `go-redis/v9` — 连接池内置，并发安全 |
| 单例模式 | `sync.Once` 确保初始化一次：`once.Do(func() { rdb = redis.NewClient(...) })` |
| 连接池参数 | `PoolSize`（默认 10×CPU）、`MinIdleConns`（预热连接）、`PoolTimeout`（等连接超时）、`ConnMaxLifetime` |
| Pipeline | 批量打包命令，一次 RTT 发送，减少网络往返；非事务 |
| 错误处理 | `redis.Nil` — 判断 key 不存在（不是 error）；其他错误正常处理 |

### 3.4 高级特性速查

| 特性 | 核心要点 |
|------|----------|
| **Stream** | 持久化消息队列：`XADD`(追加)、`XREAD`(读取)、`XREADGROUP`(消费者组)、`XACK`(确认)、`XPENDING`(待处理重试) — 弥补 List 无 ACK 和 Pub/Sub 不持久 |
| **持久化** | **RDB**：fork 子进程定期全量快照（dump.rdb），恢复快但可能丢数据；**AOF**：追加每条写命令，更安全但文件大需 Rewrite；生产环境 **RDB+AOF** 混合 |
| **Lua** | 替代事务实现原子性：脚本执行期间服务器独占，保证原子性；但无回滚（部分成功仍提交） |
| **Pipeline** | 批量命令一次发送，非原子（中间可插入其他客户端命令） |
| **主从复制** | 读写分离：主写从读，异步复制，可能读到旧数据 |
| **Sentinel** | 高可用：监控主节点 + 自动故障转移（主 down → 选举新主） |
| **Cluster** | 水平扩展：16384 个 hash slot，数据分片，多主多从；Golang 客户端自动感知 slot 迁移 |
| **缓存三问题** | ①**雪崩**：大量 key 同时过期 → 随机化 TTL ± 抖动 ②**击穿**：热点 key 过期 → 分布式锁串行化加载 + 逻辑不过期 ③**穿透**：查不存在的数据 → 布隆过滤器 + 缓存空值（短 TTL） |
| **分布式锁** | 单节点：`SET nx ex` + Lua 解锁（先验证再删除）；RedLock：N 个独立节点多数原则；etcd：CP 一致性（Raft），适合金融/事务场景 |

### 3.5 社交媒体项目数据建模（笔记中的实战案例）

| 功能 | Redis 类型 | Key 设计 | 关键点 |
|------|-----------|----------|--------|
| 用户资料 | Hash | `user:{id}` | Hash 存对象比序列化 JSON 灵活 |
| 文章内容 | Hash | `article:{id}` | 同上 |
| 点赞（谁点了哪篇） | Set | `article:{id}:likes` | SISMEMBER 判断是否点过 |
| 点赞计数 | String + INCR | `article:{id}:likes_count` | 原子自增，无竞态 |
| 关注列表 | Set | `user:{id}:following` | 我关注的人 |
| 粉丝列表 | Set | `user:{id}:followers` | 关注我的人 |
| 共同关注 | Set 运算 | `SINTER u1:following u2:following` | 交集 |
| 热门排行 | Sorted Set | `ranking:daily` | 加权 Score 公式 |
| DAU | Bitmap | `dau:2026-04-29` | 12MB 存 1 亿用户 |
| UV | HyperLogLog | `uv:article:{id}` | 12KB 固定内存，0.81% 误差 |

### 4.2 包管理与可见性

| 规则 | 说明 |
|------|------|
| 导出 | **大写字母开头** = 包外可见（public）；小写 = 包内私有 |
| 导入 | `import "fmt"` 标准库；`import "github.com/..."` 第三方 |
| 包名 | 与目录名一致，推荐简短、小写、单数 |
| internal | `internal/` 目录下的包仅父目录及子目录可导入（Go 的可见性控制） |
| 循环依赖 | 编译期禁止，需重构（提取接口 + 依赖反转 或 合并包） |
| go mod | `go.mod` 声明模块路径和依赖版本；`go.sum` 锁定校验和；`go mod tidy` 清理未使用的依赖 |

## 五、算法基础

### 5.1 数组（笔记中唯一涉及的内容）

| 知识点 | 要点 |
|--------|------|
| 静态数组 | 连续内存，`arr[i]` = `base_addr + i * sizeof(T)`（指针算术），O(1) 随机访问 |
| 动态数组 | 底层封装静态数组 + 自动扩容 + 越界检查；插入/删除中间 O(N)；
扩容 O(N)（分配新空间 + 拷贝全量数据），*均摊* O(1) |
| Go slice 扩容 | 类似动态数组；`append` 自动扩容，容量 <256 时翻倍，>=256 时增长 ~12.5% |
