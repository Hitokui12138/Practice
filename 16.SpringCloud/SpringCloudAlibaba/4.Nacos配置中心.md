# 问题
1. 现在各个service的配置分别放在两个application文件中不方便使用
2. 使用nacos配置中心统一配置
    - 配置管理 -》 配置列表 -〉创建配置
3. 然后在每一个服务中引入, 修改后, 可以实时把修改后的配置推送给每一个微服务
    - 优点在于无需停机


# 配置
1. 创建一个 order-server 专用的`nacos数据集`
    1. Data ID: order-server.yaml
    2. 配置格式: yaml
    3. 配置内容:...
2. 给order引入新依赖, 这是另一个依赖:
    - `spring-cloud-starter-alibaba-nacos-config`
3. 在order的yaml文件中指定config的位置
    - spring.cloud.naocs.config.server-addr, 这是nacos的地址
    - spring.config.import=nacos:order-server.yaml, 这是要从nacos取得的数据集名字
    - spring.cloud.nacos.config.import-check.enabled=false, 禁用导入检查
4. 读取数据
    1. 然后就可以用 `@Value("${author}") + @RefreshScope`读取配置文件了
    2. 配置特别多时也能用`@ConfigurationProperties(prefix="order")`, 这个自带自动刷新
    3. `NacosConfigManager`监听配置变化, 希望随时检查配置是否发生变化
        1. 在启动类中使用`ApplicationRunner`来启动一个一次性任务
        2. ConfigService cs = ncm.getConfigService();
        3. cs.addListener
        4. ....一旦变化, 就发邮件


# 配置中心的数据隔离
1. 在nacos中, 用`命名空间`和`分组`区分
    1. 命名空间NameSpace: dev, prod, 用于区分不同环境
    2. 分组Group: 订单, 库存, 用于区分不同微服务
    3. 数据集Data-id
2. 在SpringBoot中, 让不同环境绑定不同NameSpace, 然后激活指定配置
```yaml
spring:
    cloud:
        nacos:
            server-address: xxx
            config:
                namespace: dev # 要在指定加上NameSpace
    config:
        import:
            - nacos:commom.properties # 默认导入public空间default分组
            - nacos:db.properties?group=GROUP_DEV # 分组的导入方法

----
# 另一种写法
spring:
    profiles:
        active: test # 在这里指定环境类型
    config:
        import:
            - nacos:commom.properties # 默认导入public空间default分组
            - nacos:db.properties?group=GROUP_DEV # 分组的导入方法
        activate:
            on-profile: test #仅在test环境下启用
```
