# Seata
- 主要用来处理分布式事务

# 之前的Spring声明式事务 @Transactional
- 只能确保一个服务下面的事务一致性, 现在需要跨服务实现

# 整合Seata
1. 同时在 order 和 stock 中添加seata依赖
    - spring-cloud-starter-alibaba-seata
2. 在之前的业务方法上加注解
    1. @GlobalTrasactional
        - 放在最外面的order方法上
3. 还需要配置seata的服务端
    - TansactionMnaager 事务协调者, 二阶段提交
    - 两个服务执行数据库操作, 操作结果传给协调者
    1. 若两个操作都成功, 则协调者通知两个服务分别提交的指令
    2. 若一个操作失败了, 则通知每个服务回滚命令
4. 给两个服务添加相关配置

# Seata的模式
- file, db, redis
1. file模式, 单机模式, 将事务信息保存在内存中, 然后异步持久化到一个本地文件root.data中
    - 但这个是单机模式, 不支持seata集群
2. db模式, 高可用模式, 信息通过db共享, 可以用于集群
3. redis
