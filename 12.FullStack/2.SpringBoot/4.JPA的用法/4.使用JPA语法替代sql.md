# 用JPA实现SQL
- ORM允许不写SQL语句来完成查询
- 用导航属性替代join
1. 建一个新包repository
    - 用于衔接repository和service的,定义一个interface
    - 需要`继承JpaRepository<Banner, 主键类型>`
    - 只要定义的`方法名`符合格式,就不需要定义方法的实现,自动生成sql语句完成数据库的查询
    ```java
    public interface BannerRepository extends JpaRepository<Banner, Long> {
        //只要定义一个方法签名就行
        Banner findOneById(Long i);
        Banner findOneByName(String name);
    }

    //然后在ServiceImpl里面调用
    ```
2. 懒加载,急加载
    1. 默认是需要用BannerItem时, 才会查询BannerItem
        - 也就是默认懒加载, 节约一次SQL查询次数
    2. 如何验证确实是查询了数据库呢?
        1. 在数据库里面加数据
        2. 直接在控制台里可以显示SQL语句
            ```yml
            spring:
                jpa:
                    properties:
                        hibernate:
                            show_sql: true
                            format_sql: true
            ```
    3. 有时需要查询bannerItem,有时只需要banner的数据就可以了
        - JPA默认就是`懒加载`,可以改成`急加载`,不过不建议
        - `@OneToMany(fetch = FetchType.EAGER) `

# 单向一对多与双向一对多
1. 单向一对多
    - 只在任意一方有导航属性
    1. 现在在Banner里面定义List<BannerItem>是`单向一对多`
        - 这个List被称为`导航属性`
            - 作用是我们只需要查询banner,就能通过导航属性拿到这个Banner所对应的的一组bannerItem
        ```java
        //单向一对多
        //Banner
        @OneToMany
        @JoinColumn(name = "bannerId")
        private List<BannerItem> items;

        //BannerItem
        //@ManyToOne
        //@JoinColumn(name = "bannerId")//应该打在关系维护端这边
        //private Banner banner;//不需要导航属性
        ```
    2. 也可以在BannerItem里定义List<Banner>以实现另一个方向的单向一对多
2. 双向一对多(用的不多,了解即可)
    0. 双向一对多的作用
        - 有时候业务需要`单独查询BannerItem`,同时想知道这个BannerItem对应的Banner
        - 此时需要双向一对多,两个类都需要导航属性
    1. 同时在两个表里定义List则是`双向一对多`,注意三点
        1. 双方都要有导航属性
        2. JoinColum要设置在关系维护端
            - 但是双向关系会生成外键,因此@JoinColumn可以不加
            - 但@JoinColumn还有别的作用
                - 这里是用entity创建表,因此可以自动生成外键
                - entity除了创建表之外还有表示数据结构的功能,此时就需要@JoinColumn了
        4. 关系维护端的bannerId要注释掉
        3. 一方的OneToMany,`关系被维护端`需要再加上一个(`mappedBy` = 多方的导航属性)
    2. 两者的关系
        1. Banner是一方,BannerItem是多方
        2. 对于双向关系,还有一种新关系
            - `关系维护端`,`多方`是关系的维护端
            - `关系被维护端`,一方
    ```java
    /*
        Banner类
        1. 关系的被维护端需要mappedby = "对方的导航属性"
    */
    @OneToMany(mappedby = "banner")//1. 这个参数是banneritem的导航属性的名字
    //@JoinColumn(name = "bannerId")// 这个打在关系维护方,多端
    private List<BannerItem> items;

    /*
        BannerItem类
        2. 关联的外键打在关系维护端
    */
    @ManyToOne
    @JoinColumn(name = "bannerId")//2. 应该打在关系维护端这边
    private Banner banner;//1. 导航属性
    //3. 如果是双向关系的话,bannerId会自动生成,单向时保留
    //private long bannerId;
    ```
# 多对多,也是一个双向关系
- 主题theme和商品spu就是多对多的关系
1. 多对多可以看作是`两个一对多`
    1. theme -> 第三张表
    2. spu -> 第三张表

## 单向多对多配置
- 再次提醒JPA会生成物理外键
1. 配置
    - 需要从theme中读取spu
    ```java
    /*
        Theme 类 作为主控方时
    */
    @id
    private Long id;
    @ManyToMany
    @JoinTable( //主要用于修改默认规则, 用于规范第三张表的命名
        name = "theme_spu", //规范第三张表表名,以及两个外键名
        joinColumns = @JoinColumn(name = "theme_id"),
        inverseJoinColumns = @JoinColumn(name = "spu_id"))
    private List<Spu> spuList;

    /*
        Spu 类
    */
    @id
    private Long id;
    //@ManyToMany 单项多对多不用写这个
    //private List<Theme> themeList;

    ```
3. 为什么是JoinColumn`s`?
    - 有时可能有多外键,联合主键的情况,但用的不多,不推荐
4. 要不要给第三张表建model?
    - 取决于这张表是否有业务上的需求
## 双向多对多(可以先设置单向,有需要时再设置双向)
- 既需要在theme中读取spu, 又需要从spu中读取theme
- 一般先做单项的, 有需要时再改成双向
- 需要在`关系被维护端(一端)`上添加(mappedBy)
    ```java
    /*
        Theme 类 作为主控方时
    */
    @id
    private Long id;
    @ManyToMany
    @JoinTable( //主要用于修改默认生成规则, 用于规范第三张表的命名
        name = "theme_spu", //规范第三张表表名,以及两个外键名
        joinColumns = @JoinColumn(name = "theme_id"),
        inverseJoinColumns = @JoinColumn(name = "spu_id"))
    private List<Spu> spuList;

    /*
        Spu 类
        关系被维护端总是有mappedBy
    */
    @id
    private Long id;
    @ManyToMany(mappedBy = "spuList") //双向多对多需要写这个
    private List<Theme> themeList;

    ```
    - 多对多的数据维护关系可以颠倒
# 关系维护段和被维护端有什么用?
- 查询时没有影响,都一样的
- 对于更新和删除操作有意义,但不推荐使用JPA进行更新删除操作
    1. 孤子?去孤子?
    2. 涉及级联操作
    3. 不过现在一般不会物理删除一条数据,不用担心

# 禁止JPA生成物理外键
- 还是不要使用实体生成数据表了,不好用
1. 在Banner使用一个被弃用的注解
    - 看索引,发现没有生成五里外键
    ```java
        @OneToMany(mappedBy = "banner")  //默认是懒加载
        //@JoinColumn(name = "bannerId")
        @org.hibernate.annotations.ForeignKey(name = "null")
        private List<BannerItem> items;
    ```
2. 在BannerItem中
    ```java
    @ManyToOne
    @JoinColumn(name = "bannerId",
                foreignKey = @ForeignKey(value = ConstraintMode.NO_CONSTRAINT))
    private Banner banner;
    ```
3. 通过重写JPA对MySQl的方言(dialect)来实现不生成外键
