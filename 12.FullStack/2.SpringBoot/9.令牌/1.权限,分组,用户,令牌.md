# 权限问题
1. 对于小程序，只需要单令牌即可。但是对于其他的Web引用和App，可能需要双令牌（令牌本身和一个刷新令牌）。
2. 之前写的都是公共API, 即不需要登陆就可以使用
    - 下订单肯定要登录的
3. 权限方面最复杂的是`权限是否需要动态扩展`这一方面
4. C端权限的定义: 是否能访问API
    1. C端通常没有管理员的区分
        - 除非有VIP系统, 这时需要分组的划分
## 分组,用户,权限
1. 权限:是否能访问`API`
    - 粒度: 能访问,但部分`字段`可能因权限不足而不给看
        - 不过现在只做到API级别
        - 字段: 使用动态sql,或者直接多写几个API? 3,4阶段再解决
2. 建议: 用户不和权限有关, 分组和权限有关
    - 用户必须有一个分组
    - 应该讨论: 分组是否有访问某API的权限
    - 分组能不能创建其子分组? 能不能给子分组赋权?
        - 权限的赋予与回收
        - A->B->C, A回收了B的权限, C是否还拥有权限?
        - A能不能跨级直接撤销C的权限?
    - RBAC?
## C端权限具体使用
1. 实现机制
    - Java多用`注解`, Python多用装饰器
2. 如果直接往API上面标记@Admin@User的话, 每个都要打, 很麻烦
    - 考虑给API`分级`, 定义@ScopeLevel(8)
    - 然后定义VIP之类的分组的Level
    - API -> ScopeLevel -> Group -> User
3. CMS与C端权限的区别
    1. CMS那边涉及权限的新增删除频繁变动
    2. C端的权限几乎不变
4. 需求分析
    1. 需要创建@ScopeLevel的注解
    2. 只有用户登录后才知道分组, 因此需要做登陆相关的东西

# 用户登录
1. 账号,密码
    1. 账号
        - 自定义用户名, 邮箱, 手机号
    2. 密码, 第三方登录
        - 看似不用密码, 其实是之前已经登陆过了, 即密码已经保存在系统里了
        - 验证码也是密码
2. 微信小程序的静默登录
    - 没有登录界面, 登录微信已经验证过了
    1. 原理
        - 小程序Code码->发送给我们的API->调用微信的服务器
3. 用户的票据
    1. 传统网页会在用户登录后生成一个`票据`,保存在`cookie`里
        - 这样只要有这个票据就能免登录
    2. 前后端分离的程序使用`令牌`(`JWT`居多) VUE, APP, 小程序
        - 其实就是一个字符串
            1. 可以是随机字符串方式, 存储在Redis缓存中, 对应一个用户的id号
            2. JWT, 用户id号会直接写在JWT字符串里, 还包含其他信息, 具有实效性
4. 无感知二次登录
    - 原则上令牌过期后, 应该重新输入账号密码
    1. 假如有效期是7天
        1. 超过7天未登录, 则失效
        2. 若在6天23时59分发送消息, 由于调用微信功能时令牌过期, 则应当跳转登录界面
            - 这样会打断用户使用
    2. 特长有效期的令牌是不安全的, 不应该太长, 建议2小时
        1. 可以把当前用户的IP,设备号等信息也写入JWT中, 从而提高安全性
            - 用户常用IP地址表, IP一旦改变,就应该要求重新登录或者验证以获得新的令牌
    3. 无感知二次登录
        - 小程序不存在这个问题
        - 普通网站如何实现?(lin_CMS)
            - 单一的JWT不够, 可能需要双令牌机制
                - access_token, refresh_token
        - 每次操作后,只要令牌还在有效期内, 就延长令牌有效期
