## getCouponByCategory 原生SQL, 多对多查询, JPQL的写法
1. 对于多对多查询, 传统SQL写法
    - 至少两次Join, Join属于笛卡尔积运算, 非常消耗性能
    - 如果想在@Query里写原生SQL, 需要把nativeQuery设置成true
    ```sql
    SELECT * FROM Coupon t1
    JOIN coupon_category t3 ON coupon_id = t3.coupon_id
    JOIN Activity t2 ON t1.activity_id = t2.activity_Id
    WHERE t2.id = {#cid}...
    ```
2. 如果写成JPQL
    1. JPQL
        - join导航属性, 这样就不需要手动操作第三张表了
        - `:cid`参数
        ```sql
        select c from Coupon c
        join c.categoryList ca
        join Activity a on a.id = c.activityId
        where ca.id = :cid
        and a.startTime < :now
        and a.endTime > :now
        ```
    2. java
        ```java
        /**
         * 自定义SQL, 写JPQL语句, 多对多查询, 第三张表
         * coupon_id category_id 第三张表
         * @param cid
         * @return
         */
        @Query("select c from Coupon c\n" +
                "join c.categoryList ca\n" +
                "join Activity a on a.id = c.activityId\n" +
                "where ca.id = :cid\n" +
                "and a.startTime < :now\n" +
                "and a.endTime > :now")
        List<Coupon> findByCategory(Long cid, Date now);
        ```

## SQL与JPQL
0. 是操作实体属性, 而不是操作表
1. 导航属性
    - 导航属性不影响数据表的实体关系, 是非常灵活的, 只是用于快速查询数据
    - 下面的JPQL中, 也可以把Activity做成一个导航属性
```sql
select c from Coupon c
join c.categoryList ca
join Activity a on a.id = c.activityId
where ca.id = :cid
and a.startTime < :now
and a.endTime > :now
```
2. 单表查询与连表查询
    1. 单表插叙
        - 不使用Join, 查一次Coupon, 再查一次Activity
        - 优点在于, SELECT的查询速度很快, Java代码是在内存进行运算的, 速度也很快
            - JPA也非常适合做单表查询
                - 微服务也降低了业务复杂度, 降低了JOIN的使用
        - 缺点在于查出来的结果不是想要的, 还需要Java代码去过滤, Java代码要写很多
            - 跨多个表, 分页等等功能实现起来就更难了, 数据库的机制更好
        - ElasticSearch(二期)会更好
    2. 连表查询
        - Ali规范要求不要超过三次Join
        - 好处是逻辑简单
    3. 使用JPQL的优势在于：
        1. 类型安全，易于重构
        2. 可以利用Hibernate的二级缓存（如果配置了缓存）
        3. 面向对象，不用写复杂的SQL
    4. 底层仍是SQL：JPQL最终会被JPA提供者（如Hibernate）转换为SQL执行, JPQL并不会自动提高性能
