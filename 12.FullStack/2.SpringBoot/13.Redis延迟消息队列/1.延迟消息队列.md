## 延迟消息队列
- 主要作用: 定时器
1. 项目中与`过期`相关的
    1. Coupon的有效期
        - 不做延迟消息队列, 也不显示定义Coupon的Status
        - 只在查询的时候计算优惠券的有效期
            - 主要原因是过期这个事情不是由用户触发的, 因此不实用延迟消息队列
    2. Order支付的有效期
        - 使用延迟消息队列
        - 涉及一个库存的问题, 由于现在是预扣除库存, 因此希望支付过期后归还库存
2. 三个问题
    1. 如何归还库存
    2. 什么时候归还库存
    3. 谁来触发归还库存的操作?
        1. 定时器,主动轮循(使用SpringBoot或者其他软件)
            - 不够精确, 网络调用和数据库操作都需要时间
            - 浪费性能, 需要频繁扫描数据库
            1. 在java中,可以开启一个线程, 使用Timer来做轮循
            2. Linux的Corntab可以做定时任务
            3. 一些定时任务框架 Quartz
        2. 被动触发
            - 让一个类似用户的角色来触发
            - 时间到了后,通知系统去更新状态
3. 消息队列
- 先进先出
    - 先加入队列的任务先完成, 时间到了后, 队列`主动`完成这个任务
    - 关键在于队列要主动通知系统
- RocketMQ, RabbitMQ, Kafka
4. 延迟消息队列
- Redis, RocketMQ 有原生延迟消息队列支持
    1. Redis, 比较轻量, `键名通知`,但不能保证百分百送达消息
    2. RocketMQ, 更精准,更可靠 但是内存消耗大
- 但是必须要明白任何队列都`不能100%`确定能送达消息, 因此在系统的查询中必须做比较时间等等操作

## redis键空间通知 
- keyspace notification
- 当redis收到影响(删除key或者过期expired)的时候, redis就会发布一个通知
- 类似于pub/sub 发布/订阅的功能
1. 两种可订阅的类型
    1. key-space
        1. 假如执行了一个删除操作, key-space就会返回一个del操作类型(操作的名称)
    2. key-event
        2. 返回被删除的key的名称
2. 有哪些事件?
    1. 删除del,操作列表l,操作集合s
    2. 过期expired(x)
    3. 不同的操作有不同的缩写
3. 开启键空间通知
    1. 需要修改配置文件, 启动键空间通知
    ```
    brew list redis

    cd /opt/homebrew/etc/redis.conf

    find / -name redis.conf

    notify-keyspace-events Ex
    # E表示key名
    ```
    2. 重新启动redis, 并且指定配置文件
        - redis-server /opt/homebrew/etc/redis.conf

    2. 订阅通知
    ```redis
    redis-cli

    # 切换数据库 0~15
    select 0

    # 订阅keyevent
    # 使用#0号数据库, 一共16个
    # 都是双下划线
    # 监听expired
    psubscribe __keyevent@0__:expired
    ```

    3. 验证
    ```
    # 添加一个key,指定一个过期时间 10s
    setex name 10 hitokui
    ```
