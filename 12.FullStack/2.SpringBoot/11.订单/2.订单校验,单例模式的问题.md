## 不同舍入模式如何导入容器?
- SpringBoot默认注入单例模式所带来的额问题
1. IMoneyDiscount 做了个interface
    1. HalfUpRound
    2. HalfEvenRound实现这个接口来写不同的方法
2. 现在想在CouponChecker类中注入这个interface
    - 那么需要把CouponChecker上面也加一个@Service以变成一个模块, 这样才能注入其他模块
    ```java
    @Service
    public class CouponChecker {
        // 其他非@Autowired私有成员变量如何处理?
        private Coupon coupon;
        private UserCoupon userCoupon;
        // IMoneyDiscount的确是单例的
        @Autowired
        IMoneyDiscount iMoneyDiscount;
        //....
    }
    ```
3. 这样做带来的问题
    1. 全局只有一个XXXService, 那么下面的XXXDao也只有一个, 这样本身是没问题的
    2. 假如说现在同时有十个订单, 那么就应该创建10个CouponChecker来分别处理各个订单
        - 因此必须使用`多例模式`
    3. `单例模式可以看作是static静态的`, 全局只有一个
    4. 如果给一个类加上`@Bean`, 那就是让Ioc去管理, 而不应该自己去new这个对象
    5. 但如果考虑不创建CouponChecker类, 的确能规避这个单例问题, 但这变成了面向过程编程
## 在SpringBoot中解决单例问题
1. 解决方法1
    - 就把这个类当作普通的Java类, 不要使用SpringBoot的注解
    1. 保持原来的`new CouponChecker()`
    2. 去掉@Service和@Autowired
    3. 这样做带来的问题
        1. 如果需要读取配置文件, 那就无法使用@Value,@PropertySource
        2. 这些注解需要依赖SpringBoot
    ```java
    //解决方法1
    @Service
    public class OrderService {
        @Autowired
        IMoneyDiscount iMoneyDiscount;
        new CouponChecker(coupon, userCoupon, iMoneyDiscount);
    }
    public class CouponChecker {
        private IMoneyDiscount iMoneyDiscount; 
    }
    ```
2. 解决方法2
    1. 使用@Scope(“prototype”)来开启多例模式

## 思考
1. 像是之前的@Controller@Service的单例模式
    1. `行为上与静态类相同`
    2. 而且这些类的构造方法都是无参的
    3. 一个Service类里面上千行代码
        1. 然后就算想拆成小类, 也可能遇到上面单例模式问题
2. 考虑到面向对象,也就是不使用@Service1
    1. 用面向对象的思想, 把OrderChecker和CouponChecker拆成两个类里面
    2. 普通Java类的问题
        1. Orderchecker很难去去读取配置文件
        2. 读取数据库也需要repository, 也需要注入
    3. 解决方法
        1. 方法1: 所有需要的东西, 配置文件的参数, dao对象, 都通过构造函数传递进来
        2. 方法2: 使用@Scope(“prototype”)+@Service来开启多例模式
## @Scope(“prototype”)+@Service的问题
1. 所有有参构造器被标红了
    1. 原因是Bean对象不能有有参构造函数, 这与面向对象思想相违背
2. 如何让Spring实例化这些对象的时候,可以传递参数?
    1. 必须让这些参数也被SpringBoot托管,就像之前的`@Autowired`一样
    2. 使用`@Configuration+@Bean`, 自己控制实例化的过程
        1. 在配置类中传好参数
        2. 然后使用`@Bean`传递给IoC容器
    3. 笨方法
        1. 不要使用@Service, 就把所有参数当作普通Java类那样通过有参构造器传递进去
