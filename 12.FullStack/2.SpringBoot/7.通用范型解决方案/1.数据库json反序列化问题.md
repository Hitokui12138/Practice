## 问题
1. 获取sku详细的API返回的spec
    ```json
    "specs": "[{\"key\": \"颜色\", \"value\": \"青蓝色\", \"key_id\": 1, \"value_id\": 1}, {\"key\": \"尺寸\", \"value\": \"7英寸\", \"key_id\": 2, \"value_id\": 5}]"
    ```
    - 返回给前端的本身就应该是个json对象, 而不是现在这样用字符串的格式表达
2. 而数据库本身的存储
    - spec的类型是`json`
    ```
    [{"key": "颜色", "value": "青蓝色", "key_id": 1, "value_id": 1}, {"key": "尺寸", "value": "7英寸", "key_id": 2, "value_id": 5}]
    ```
3. 原因在于java那边本来定义的就是String
    - `private String  specs;`
    - 考虑可以直接使用Object替代String, Object在序列化之后是json格式的
    - java Tips: 尽量不要直接使用Object类型, 因为会有拆箱装箱的过程,影响运行效率
        1. 要么定义这个类型
            - `private List<Spec> specs;`
            - 但被`@Entity`标记的类,要求成员变量都必须是特定的能和数据库类型一一对应的属性, List不行
                - 之前的`导航属性`仅表示关系,而不是映射
        2. 要么使用范型
