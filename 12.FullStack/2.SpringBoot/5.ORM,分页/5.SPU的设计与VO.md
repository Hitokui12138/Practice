# 复习JPA为什么不用写SQL
1. Controller -> Service -> repository
    - Repository extends JpaRepository<Banner, Long>
    - 甚至即使不在Repository定义, 也能使用一些基础的接口
    - JPA 命名查询(Method Name Query) 是一种根据方法名自动生成数据库查询语句的功能。通过遵循特定的命名规则，开发者可以省略手动编写JPQL 或SQL 语句，简化代码，提高开发效率。
    - findByUsername(String username): 根据用户名查找用户。
    - findByUsernameContaining(String username): 查找用户名包含特定字符串的用户。
    - findByAgeBetween(int startAge, int endAge): 根据年龄段查找用户。
    - countByActive(boolean active): 统计状态为active 的用户数量。
    - deleteByEmail(String email): 根据邮箱删除用户。
    - existsByUsername(String username): 检查是否存在指定用户名的用户。

## 优化数据的属性数量, VO,视图层
- 如何不让这三个导航属性返回前端?
- 利用`LAZY加载`, `不要直接序列化SKU`
1. 创建一个VO, 需要什么属性,就往里面加上哪些属性
    - 最好给每个业务都单独做一个VO
    - 把SKU的属性复制到VO里面
2. 关于复制的方法
    1. 一个一个设置
    ```java
    public SpuSimplifyVO getimplifySpu(@PathVariable @Positive Long id){
        Spu spu = this.spuService.getSpu(id);
        SpuSimplifyVO vo = new SpuSimplifyVO();
        vo.setTitle(spu.getTitle());
        return vo;
    }
    ```
    2. 使用Java的工具集
        - `BeanUtils.copyProperties(spu, vo);`
        - 要求属性名需要相同
        - 单独一个spu时好用, 但如果是List<SPU>就得循环了
    3. 处理List<SPU>的属性复制
        - 引入依赖`DozerMapper`, 但还是需要循环处理
        ```java
        @GetMapping("/latest")
        public List<SpuSimplifyVO> getLatestSpuList(){
            //return this.spuService.getLatestPagingSpu();
            Mapper mapper = DozerBeanMapperBuilder.buildDefault();
            List<Spu> spuList =  this.spuService.getLatestPagingSpu();
            List<SpuSimplifyVO> vos = new ArrayList<>();
            spuList.forEach(s->{
                //需要数据源和目标数据的类
            SpuSimplifyVO vo = mapper.map(s, SpuSimplifyVO.class);
            vos.add(vo);
            });
            return vos;
        }
        ```
    4. `DozerMapper`的优势
        1. 可以进行`生Copy`
            - 对于SPU下面的`SKU属性`, SKU本身里面还有一些基本属性
            - 此时不能直接Copy, 需要用DozerMapper来复制
        2. DozerMapper有复制名称不同的属性的方法
