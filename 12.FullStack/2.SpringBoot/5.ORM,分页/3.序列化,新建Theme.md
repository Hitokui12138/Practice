1. createTime等三个共同属性也返回到前端了,而且值为null
    - js和python比较容易修改
    - 让`序列化`时,不要读取这三个属性
2. 当前返回的JSON中,属性名字(`Key`)是驼峰(createTime)
    - `JSON的Key`应该是Snake?下划线连接(create_time)
    - 通过配置`序列化库`,修改返回的变量名
        - JPA自带一个`jackson`一个序列化库
        - 也可以更改,改成阿里的`fastJSON`
3. 命名配置了懒加载,为什么JSON中还是有BannerItem?
    - 因为序列化时还是触发了加载
# 解决问题
1. 父类BaseEntity属性为null的问题
    1. 子类有@Entity,所以可以映射到JSON
        - @Entity表示这个类对应数据库一张表
        - 显然父类没有,但也不应该打上@Entity
    2. 这里应该使用`@MappedSuperclass`, 表示这个类是映射里的父类
        ```java
        @Getter
        @Setter
        @MappedSuperclass   //表示这个类是映射里的父类,让JPA不要生成表
        public abstract class BaseEntity {...}
        ```
2. 驼峰问题
    - 使用jackson进行序列化
# jackson, fastjson 
1. 驼峰变下划线问题
    1. 顺便把传给前端的时间从可读的`UTC格式`改成`时间戳`的格式
        - 13位毫秒, 10位秒, 秒和毫秒换算单位是1000
    ```yml
    spring:  
      jackson:
          jackson:
            property-naming-strategy: SNAKE_CASE
            serialization:
            WRITE_DATES_AS_TIMESTAMPS: true
    ```
2. 不想返回共同字段
    ```java
    @JsonIgnore //序列化时忽略这个字段
    private Date createTime;
    ```
    1. 但这个方法不是很灵活,如果有时需要返回时间该怎么办?(常用)
        - 创建一个VO,把Entity的属性复制进去
        - 然后返回这个`VO的序列化`而不是Entity

# JPA的序列化
1. 通常数据库每个字段存储的都是简单数据，比如一个字符串，一个数字。但是有时候数据库的字段也可能会存储一个对象
2. 那么如何在数据库中存储对象呢？这可能就需要首先将对象进行序列化，并序列化成字符串，再写入数据库
3. 同时，当查询数据库时，不应当查询出字符串，而应当查询出一个Java对象来。

# 数据库的拓展
- 表的字段不够用?
1. 额外使用一些extend字段
    - 防御型编程,反范式
- 关系型数据库的特点:
    - 表的`字段(列)`本身不具有扩展性,只有`记录(行)`有扩展性
2. 假如一个theme有多个name
    1. 可以再建一个新表用来扩展其他多个表(即`Code Master`)
        - 这就相当于列被转换成了行
        | id | name | value | table_name |
        | --- | --- | --- | --- |
        |1|color1|red|theme表用|
        |2|public|1|banner表用|
    2. Key Config
        - Theme有一些`限制性属性`,比如一个Theme`最多有`多少个SPU?
        - 这是一种`配置`,可以单独做一个Conifg表
            - 也就是说从事面向对象的角度来讲,这些本身就是一个实体,名字叫做config
        | id | name | max_config | min_config | table_name |
        | --- | --- | --- | --- | --- |
        |1|SPU|0|3| theme表用 |
3. max_spu, min_spu
    - 从面向对象的角度
4. 另一种方式: 用一个tag字段,然后里面用逗号分隔开
    - 优点: 查询时少一次Join
    - 缺点: 更新起来很麻烦
