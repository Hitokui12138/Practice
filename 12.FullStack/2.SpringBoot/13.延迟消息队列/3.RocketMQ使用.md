# RocketMQ
1. 下载Binary文件
2. 进入bin目录, 启动`Name Server`和`Broker`
# 启动`Name Server`和`Broker`
1. 用sh命令启动, 或者用后台的方式启动
    ```sh
    # 直接启动
    sh mqnamesrv

    # 后台启动

    ```
2. 如果报错, 可能需要修改配置文件`runserver.sh`
3. 还使用docker-compose启动吧
```sh
docker-compose up -d
docker ps
docker logs -f rmqbroker
docker-compose donw
```

4. 验证是否成功
```sh
# 进入Broker容器
docker exec -it rmqbroker bash
# 使用内置工具生产者发送测试消息
sh tools.sh org.apache.rocketmq.example.quickstartProducer
# 在另一个终端，使用内置工具消费者接收消息
sh tools.sh org.apache.rocketmq.example.quickstartConsumer
```
## 基本原理
1. 有一个生产者和一个消费者
    1. 生产者来生产消息
        - 下单后, 会产生一个Order Message, 加入到队列Queue中
    2. 消费者来消费消息
        - 消费者取得这个Message, 修改订单的状态
2. 延迟消息队列
    1. 生产者生产消息后, 延迟加入队列
    2. 30分钟后, 消息加入队列
    3. 但RocketMQ不支持任意时间设置, 只有有一组时间可以选择
        - messageDelayLevel = 1s,5s...30min, 1h,2h...1day
        - 在配置文件配置好后, 选择
3. 还有哪些可能用到延迟消息队列的功能?
    1. 定期的脚本, 定期清理数据库清理日志

## SpringBoot
1. 安装依赖
    ```xml
    <dependency>
        <groupId>org.apache.rocketmq</groupId>
        <artifactId>rocketmq-client-java</artifactId>
        <version>5.1.0</version>
    </dependency> 
    ```
2. 原理
    1. Redis键空间通知
        - 原理: 当redis受到影响(`删除key或者过期expired`)的时候, 触发redis就会`发布一个通知`
    2. RocketMQ 延迟消息队列
        - 就是利用生产者和消费者的关系, 然后延迟消息进入队列的时间
