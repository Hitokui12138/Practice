# CMS系统
- CMS是Content Management System的缩写，意为"内容管理系统"。
- 二阶段的数据库的数据基本上都是在`直接在数据库中添加的`
- 运维人员不能直接操作数据库, 应该通过CMS来操作
- 而且数据库中没有定义`物理外键`, 会造成数据错误, 直接操作数据库是不安全的
1. 一个增加优惠券的例子
    1. 新增活动
    2. 新增优惠券
    3. 优惠券和活动做关联
    4. 优惠券模版
2. CMS是能更好表达数据库的结构的工具
3. To C的产品: 小程序前端
4. To B的产品: CMS系统(涉及权限更加复杂, 且是动态的)
## lin CMS
- lin CMS: https://doc.cms.talelin.com/
- demo: http://sleeve.talelin.com/#/about
1. 核心优点(已经提供的通用功能)
    1. 动态权限分配(内置权限管理系统), 最必要
        1. CMS角色(分组), 各自可操作的系统是不同的
            - 运营人员, 产品, HR, 财务
            - 将来可能有更多的角色
        2. 管理员应该可以任意指定分组, 并且为其分配特定权限
    2. 图片上传, 日志管理(运行时异常, 操作/行为 日志) 
2. Lin CMS提供三种机制用于自定义功能的实现
    1. 插件
        - 通过配置功能, 实现文件上传功能
    2. 模块
    3. 扩展
3. 如果自己做一个功能: 文件/图片 上传功能
    1. 新建文件表, model/service/controller
    2. 文件存储在什么地方
        - 服务器本身, 云端OSS, git的代码托管服务器上
    3. 文件拓展名做限制, 不能上传exe.dmg
    4. 文件体积限制
    5. 会不会上传同一张图片? 不应该有多个副本
4. `单页面应用程序`, 前后端分离, 体验很好
    - 像是 `VUE和React` `这种SPA工具`都是用来开发单页面应用程序的
    - 缺陷:
        - 对`SEO(搜索引擎优化)`的支持很差, 最好不要用单页面APP开发, 应该使用传统的模版渲染的方式开发
    1. 不需要SEO的应用
        - 使用VUE和React这样的SPA框架来开发
        - `CMS系统也不需要支持SEO`, 因此`VUE和React就是专门用来发开CMS前端或者WebAPP的`, 小程序也能开发
        - 像是`淘宝, 京东`这样的传统网站, 对SEO支持要求高, 因此他们用的是`服务端模版渲染`(FLUSK, NODE.js的KOA)
    2. 服务端模板渲染（SSR：Server-Side Rendering）是什么？
        - HTML 页面在服务器端动态生成后，完整发送给浏览器直接渲染。

## SDK 与 Demo
1. LinUI是一个纯粹的库, SDK库
    -  Software Development Kit，软件开发工具包，简单说就是：别人给你打包好的一套工具，让你能快速调用某个平台 / 服务的功能，不用自己从零写底层代码。
2. LinCMS是 `工程 + SDK`
    1. 为什么不直接做成DEMO?
        - SDK是抽象的, 可复用的, 因此成为是一个开发框架
        - 另一方面, 全DEMO会造成难以升级
            - 如果是LinUI那种纯SDK库, 可以随意使用任意版本的代码
            - LinCMS做不到无缝升级(因为有一部分工程化的代码)
                - 因此应该使用固定版本的LinCMS
3. LinCMS依赖的东西
    1. `lin-cms-spring-boot-starter`
        - 这个Starter就是一个SDK, 用来把一些`公用的, 没有必要向用户开开放`的`库或者功能`

## LinCMS的三种机制
- 提高复用性, 其他人也可以用
- 把一些Service当作扩展去编写
1. extension 扩展
    - 小的拓展, 比如文件上传
2. module 模块
    - 大的功能模块增强, 提供一个支持WebSocket的类库
3. plugin 插件
    - 一些包含业务的, 可能还需要有操作数据库的功能
