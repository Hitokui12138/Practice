# 容器解决的问题
- 可移植, 可拓展, 更高效
1. 资源隔离
    - 可以在一台虚拟机上运行多个容器, 每个容器都有自己的一组资源
    - CPU 磁盘 网络
2. 跨平台移植性
    - 只需要编译一次, 就可以在其他平台使用
3. 具体应用
    1. 微服务架构
        - 涉及多个容器
    2. 容器编排技术
        - 一台主机上部署多个容器
        - 多台主机多个容器
# Docker与K8S
1. Docker
    1. 基于单机
        - docker-compose, 一台机器一次运行多个容器
    2. 操作`容器运行时``containerd`, 是一种server
    3. 基于容器运行规范`Open Container Initative(OCI)`来运行
2. K8S
    1. 基于集群
    2. 通过`K8S的API``Container Runtime Interface`来操作`containerd`或者`CRI-O(另一种容器运行时)`
    3. 基于OCI运行
# Docker与虚拟机
1. 全虚拟化
    - 硬件层->Host OS->虚拟化软件
        - 虚拟硬件层->Guest OS->APP
    - 速度分钟级,性能有损失,磁盘占用大,最多几十台,系统级别
    - 支持几乎所有操作系统,有完整的操作系统
2. 半虚拟化
    - 硬件层->Host OS->虚拟层(Docker)
        - Host OS(只包含物理操作系统的库文件Bins和依赖包libs)->APP
    - 进程级别, 仅支持Linux, 共享主机的内核

# 容器,镜像,仓库
- Docker是一个`容器引擎`,用来管理容器的生命周期
- 开发源代码,打包成镜像(基于镜像创建容器)
- 上传到代码/镜像仓库
1. 镜像(是一个类)
    - 描述如何创建一个实例
    - 设计图,模型,源代码,安装包等等打包成镜像
        - 容器的配置信息等等
    - 软件运行起来:产生一个服务(进程)
    - 那么运行起来之前,是这个软件的安装包
2. (镜像)仓库
    1. 代码仓库
        - 用于管理源代码
        - gitlab,github,gitee ,dockerhub
    2. 镜像仓库 Registry,注册
3. Docker容器(是一个实例)
    - 真正的
    - 装产品的`集装箱`,就是容器,可以看作是运行起来的软件
    - `产品`指的是开发好的APP(Java,JVM)
    - 运输集装箱还需要`货轮/货车`,这个就是Docker
    - 而且容器里面提前安装好的一系列依赖
