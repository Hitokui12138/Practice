3. 服务引入

## Dubbo原理
### 1.服务调用原理
1. 服务消费者在调用服务时, 至少需要四个信息
    1. 接口名
    2. 方法名
    3. 方法参数类型列表
    4. 方法参数值列表
2. 上面这四个信息应该封装成一个对象 `Invocation`
    1. 为了让消费者可以传输这个对象, Dubbo应该 implemements SerSerializable
    2. 为了让提供者取得这个对象后, Dubbo应该反序列化
        - JDK自带, JSON, Dubbo自带Hession, grpc用的protobuf
        ```java
        // 自带的
        new ObjectInputStream(req.getInputStream()readOnject())
        ```
    3. 从Invocation对象中可以取得接口名, 但是如何取得实现类名?
        - 哪个接口, 对应哪个实现类, 这是一个`映射关系`, 可以在provider启动时就储存到Map里, 这个过程叫`本地注册`
### 2.服务注册原理
4. `本地注册` LocalRegister类
    - 提供 Map<接口名, 实现类>, provider启动时就调用这个进行注册
    - 多个实现类的时候, 需要制定具体使用哪个类; 如果多个都想提供, 那么提供一个`版本号`, Map<接口名+版本号, 实现类>
    - 或者用`注解`也可以实现版本控制
    - Dubbo在有多个实现类的时候就需要提供一个版本号 
5. 这样就拿到这个类了, 使用`反射`执行类中的方法
    - method = classImpl.invoke(classImpl.newInstance(), invocation.getParam()), 拿到方法
    - method.invoke(...), 执行方法
6. 这样Consumer发送请求后, 就能拿到一个执行结果
    - 可以用 HttpClient进行测试
    - 目前服务提供者还没有用到动态代理

### 3.代理
1. 目前的问题, 调用后取得一个Invocation结果对象, 但其实想要的是实现类的对象
    ```java
    // 目标:
    HelloService service = ?;
    service.hello();

    //目前:
    new Invocation(HelloService.class.getName(), hello, class[], param[])
    result = httpClient(url, invocation);
    ```
2. 这里的`?`应该是接口的`代理对象`
    1. 创建代理对象有多种方式
        - JDK自带, sijilive?, Dubbo内部也有自己的一套
    ```java
    getProxy(){
        Proxy.newProxyInstance(当前类.class.getClassLoader(), interfaceClass, new invoktionHandler){
            @Override
            involk(...){...}
        }
    }
    ``` 
    2. 这样 `?`可以写成 getProxy() 了, 得到一个代理方法
        - 代理对象执行方法后, 会进入invoke()中去,在这里执行相应的方法
