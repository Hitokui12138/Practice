# minikube和kubectl
1. minikube
    1. 可以搭建一个单节点集群,用于开发测试
    2. 使用`kubectl config view`可以看到当前环境上下文是minikube
2. kubectl工具
    1. 用于与搭建好的kubectl集群进行交互
3. 安装minikube需要Docker或者虚拟机
4. - brew install minikube
    - 自动安装kubectl
5. 
    - minikube start --container-runtime=containerd
6. 使用下面的命令产看名词一览的各个东西
    - kubectl get pod -A
7. 使用`minikube ssh`进入容器中
    - `systemctl status kubelet`,查看kubelet的状态
8. 虽然默认是单节点，但 Minikube 也可以配置多节点：
    - minikube 节点：Master + Worker（控制平面+工作负载）
    - minikube-m02 节点：纯 Worker 节点
    ```sh
    # 1. 停止当前集群
    minikube stop

    # 2. 删除当前集群
    minikube delete

    # 3. 启动一个多节点集群（2个节点）
    minikube start --nodes=2

    # 4. 查看节点
    kubectl get nodes

    # 输出示例：
    # NAME           STATUS   ROLES                  AGE   VERSION
    # minikube       Ready    control-plane,master   30s   v1.27.3
    # minikube-m02   Ready    <none>                 15s   v1.27.3

    # 5. 给第二个节点添加角色标签
    kubectl label node minikube-m02 node-role.kubernetes.io/worker=
    ```



# 如何在任意节点使用kubectl?
1. master节点中的 /etc/kubenetes/admin.conf,需要拷贝到其他节点的/etc/etc/kubenetes,,目录中
    - scp /etc/kubenetes/admin.conf roo@k8s-node1:/etc/kubenetes
2. 在其他节点配置环境变量 



# 常用命令
```ssh
minikube start
kubectl get nodes

//一般不会直接创建Pod
//这样可以`拉取最新的nginx镜像`
kubectl create deployment test-dep --image=nginx

//Ready没有显示1/1说明还没有启动
----
kubectl get deploy
NAME       READY   UP-TO-DATE   AVAILABLE   AGE
test-dep   0/1     1            0           16s
----

//Pod和deployment之间还有一个ReplicaSet,副本
//带个--watch可以动态查看pod的生成过程
----
kubectl get rs --watch
NAME                  DESIRED   CURRENT   READY   AGE
test-dep-5f74859d77   1         1         1       2m17s
----

//恢复之前的镜像,查看之前部署的版本
kubectl rollout history deploy/nginx-deploy


//可以发现Pod的命名规律 deploy-replicaset-pod
----
kubectl get pod
NAME                        READY   STATUS    RESTARTS   AGE
test-dep-5f74859d77-z8prs   1/1     Running   0          91s
----

```
