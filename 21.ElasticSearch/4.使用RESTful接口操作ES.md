# 语法
1. GET请求
    - GET请求的参数只能放在路径上
    1. 查询索引信息
        - `GET http://ip:port/index`
    2. 查询文档信息
        - `GET http://ip:port/index/type/doc_id`
2. POST请求
    1. 也能用于查询, 主要是由复杂查询条件的请求
        - `POST http://ip:port/index/type/_search`
        - 可以在请求体中添加JSON来表示请求条件
    2. 修改
        - `POST http://ip:port/index/type/doc_id/_update`
        - 在请求体中指定修改信息
3. PUT请求, 居然是用于创建
    1. 创建一个索引
        - `PUT http://ip:port/index`
        - 请求体中需要有分片个数等等信息
    2. 创建index时指定type, 以及里面的属性信息
        - `PUT http://ip:port/index/type/_mappings`
4. DELETE请求
    - 删库跑路

# 创建索引, 同时指定数据结构
- 新版本已经没有`表type`的概念了, 取而代之的是`嵌套JSON类型object`
```JSON
PUT /book
{
    "settings":{
        "number_of_shards":5,
        "number_of_replicas":1
    },
    "mappings": {
        "properties": { # 必须
            "novel": {  # object
                "type": "object",
                "properties": {
                    "book_name": {
                        "type": "text",
                        "analyzer": "ik_max_word",
                        "index": true, # 默认true, 当前Field可作为查询条件
                        "store": false # 默认false, 不需要额外存储
                    },
                    "count": {
                        "type": "long"
                    },
                    "onSale": {
                        "type": "date",
                        "format": "yyyy-MM-dd||epoch_millis"
                    }
                }
            }
        }
    }
}
```

# 文档操作(数据操作)
- 如何操作一条数据
1. 每个文档的元数据
    1. _id：文档唯一 ID
    2. _index：所属索引
    3. _source：原始文档 JSON 内容
    4. _score：搜索相关性得分
2. 添加文档
- 注意: 由于没有了index, 因此现在用“_doc”代替
- 可以在`/_doc/[id]`指定id
```JSON
POST /book/_doc
{
  "novel": {
    "book_name": "三国演义",
    "count": 98,
    "onSale": "2026-05-20"
  }
}
```
3. 覆盖式修改
    - 直接指定相同id进行POST即可
```JSON
# 覆盖式修改
PUT /book/_doc/1
{
  "novel": {
    "book_name": "西游记（修订版）",
    "count": 150,
    "onSale": "2026-06-02"
  }
}
```
4. 推荐: doc修改
```JSON
# 仅修改一个属性
POST /book/_update/1
{
  "doc": {
    "novel": {
      "count": 180
    }
  }
}
```
