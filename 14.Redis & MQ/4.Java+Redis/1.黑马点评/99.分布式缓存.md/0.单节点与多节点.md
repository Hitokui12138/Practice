# 单节点与多节点
## 1. 单节点问题
1. 单节点问题
    1. 数据丢失问题
        - Redis是内存存储, 服务重启会导致丢失数据
        - 解决: 数据`持久化`
    2. 并发能力问题
        - 虽然Redis并发能力强, 但是单节点最多也就三五万
        - 解决: 搭建`主从集群`,实现读写分离,提高并发能力
    3. 故障恢复
        - 一旦故障, 对整个微服务架构的影响非常大, 需要有自动故障恢复手段
        - 解决: `哨兵机制`, 实现健康监测和自动恢复
    4. 存储问题
        - 内存是有上限的, 单节点Redis难以满足需求
        - 解决: 参照ElasticSearch, 将数据`分片保存`, 搭建分片集群, 利用`插槽机制`实现`动态扩容`
