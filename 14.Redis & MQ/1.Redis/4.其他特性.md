# Redis支持事务
- 一次性执行多个命令
```
MULTI //开启一个事务
  SET
  LPUSH
  SADD
EXEC  //开始执行命令
```
1. 注意!
    - Redis所谓的事务并没有原子性, 不保证所有命令都成功
    1. 可以保证
        1. 在EXEC之前, 所有命令会被放入队列中缓存起来, 不会立即执行
        2. 即使中间有一条执行失败了, 其他命令依然会执行
        3. 其他客户端插入的命令, 不会被插入到命令序列中

# 持久化
1. 主要有两种方式
  1. RDB (Redis Database)
    1. 在制定时间间隔内, 将内存中的数据写入磁盘, 是某个时间点数据的副本
      - vi redis.conf , 配置文件里面加上下面这个
      - save 3600 1 , 1表示修改次数, 意思是5分钟内, 只要出现一次修改, 就进行一次快照
        - 根据服务器负载情况来修改这个配置
    2. 还可以手动触发快照
      1. save
        - 缺点: 如果宕机了, 在快照之后的内容都会丢失
        - 因此RDB常用于备份
        - 另外save一次会持续较长时间, redis在此期间会阻塞
      2. bgsave
        - 开辟一个新进程来保存, 还是会卡一下
  2. AOF (Append Only File)
    1. 类似于日志, 会把命令存在AOF文件中, 若宕机, 则启动后重新执行AOF命令来重建数据库
    2. 开启AOF
      - vi redis.conf
      - appendonly yes
# 主从复制
- 把唯一一个主节点的数据复制到多个从节点上
- 一般来说, 主节点只负责写操作, 从节点负责读取操作
- role , 查看当前节点角色
1. 配置
  1. 修改配置文件
    1. 主节点 redis.conf 不需要修改
    2. 从节点 复制一份主节点文件命名为 redis-6380.conf
      1. 修改 port 6379 -> 6380
      2. 修改 pidport redis_6379 -> redis_6380
      3. dbfilename dump -> dump_6380
      4. replicaof 127.0.0.1 6379 , 表示当前节点是6379的从节点  
- 主节点的数据会自动同步到从节点上

# 哨兵模式 Sentinel
- 如果主节点宕机了, 我们需要手动把一台子节点提升为主节点
1. 哨兵模式可以实现
  1. 监控, 通过不断发送命令来检查各个节点情况
  2. 通知, 如果其中一个宕机了, 哨兵会发布通知来告诉其他节点
  3. 自动故障转移, 把一个从节点升级为主节点, 并把其他从节点重新指向这个新的节点
