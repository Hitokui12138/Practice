# 接口性能优化
1. 数据库 + 缓存 + 接口逻辑 + 连接池 + 事务太大、锁等待
    - 社交平台最常见：慢查询 + 没分页 + 没缓存
2. 最简单做法
    1. 给每个接口打日志：接口总耗时、DB 耗时、Redis 耗时
    2. 用 top、iftop、iotop 看服务器负载
    3. 看 MySQL 的 Slow Query Log 

# 1.缓存
- 读多写少：Redis 缓存
    - 用户信息,帖子/评论列表,关注/粉丝数
# 2. 慢SQL
1. select *, 没加limit, join太多
2. 没有索引/索引失效的
    - 给 where、order by、join 字段建索引
3. 列表类全部 分页/滚动 加载
# 3. Mysql和Redis的 连接池配置
1. 推荐至少
    1. MySQL 最大连接：20~50（看服务器配置）
    2. Redis 最大连接：10~30
# 4. 异步处理（别让接口等无关逻辑）
1. 以下操作不要同步做
    1. 发送通知
    2. 记录日志
    3. 统计计数
    4. 图片上传处理
