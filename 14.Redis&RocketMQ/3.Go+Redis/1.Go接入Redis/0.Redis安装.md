# Redis
1. Redis的职责
    1. 高频读取, 缓存数据
    2. 状态共享, 共享token记录登录状态
    3. 实时计数, 这个人密码输错几次
    4. 排名计算, SortedMap
    5. 限流控制, 分布式API网关可能会用Redis来
2. Redis做不到:
    1. 数据库的替代品
    2. 永久数据中心
3. Redis的`执行模型`是一个`单线程模型`
    1. 同一时间只执行一个命令,剩下的会在请求队列中等待
        - 不会有线程切换
    2. 无锁, 不会有锁的竞争
    3. 单线程, 因此天然原子性, 延迟稳定
4. Redis为什么这么快
    1. 内存操作, 本身就很快
    2. 单线程无锁, 不会卡住
    3. IO多路复用, 内存操作本身就很快, IO是瓶颈, 现在用epoll很快
    4. 原子指令执行
5. IO多路复用模型(epoll)
    - Redis的执行模型是单线程, 但却能同时监听多个 socket / 连接，哪个有数据就处理哪个
    1. 多个客户端发送请求
    2. IO监听器检测`事件`
    3. 加入执行队列 
    4. 主线程依次执行(内存处理极快, 性能瓶颈在IO上面)
6. 什么样的行为会拖慢Redis
    - 本质上是阻塞了主线程
    1. 因此有一些操作应该避免(在配置中禁用)
        1. `KEYS *`, 成百上千万个
        2. 大集合全量扫描, 超大RANGE
            - 一个有一百万数据的Set, 你想一次全取出来
        3. 大KEY
            - 内存也是有瓶颈的
