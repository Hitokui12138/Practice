# 不常用数据结构
## 统计场景下的两个数据结构
## BitMap
- 签到、登录状态、用户行为标记、连续天数统计
- 精准知道每个个体的状态, 
1. 就是一串二进制位（0/1），
    1. 每一位对应一个 “唯一标识”（比如用户 ID）
    2. 用 0/1 表示这个标识的 “某个二值状态”（比如 “是否登录”“是否点击”“是否签到”）。
2. 比如统计 1 亿用户签到，需～12MB
## HyperLogLog
- 概率丢失精度, 但是非常省内存, 高效估算海量数据的基数
- 能接受 0.81% 的误差
1. 一种 “概率算法”，不存储具体数据，只记录统计的 “特征值”，最终估算出一个集合中 “不重复元素的数量”（基数（`不重复元素数量`））。
    - Redis 专属的概率数据结构，底层是字符串 + 哈希表
2. 无论数据量多大，仅需～12KB
