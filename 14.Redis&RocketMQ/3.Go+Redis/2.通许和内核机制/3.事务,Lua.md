# Redis的事务
## Redis的事务机制
1. 注意 Redis 的事务`不是数据库事务`
    - 只是`批量顺序 执行命令`
    - 只能保证`命令执行期间不会插入其他命令`
    1. 做不到:
        -  `全部成功`,`回滚`,`隔离级别`
        - 即使其中一条执行失败了, 其他也会继续执行
2. 不推荐使用`WATCH`
    - WATCH 可以监控某个KEY, 若KEY变化则触发逻辑
    - 实现这样的功能最好用消息队列
## `LUA脚本`替代 Redis 原生事务、实现复杂原子操作
1. 优点
    - lua可以实现原子逻辑, 不依赖连接, 不会出现重试风暴
    - Redis 执行 Lua 脚本时，会`独占整个 Redis 服务器`
        -执行期间不处理其他任何命令
2. 缺点
    - 但lua也不能保证`某条指令失败了回滚`
