# 使用Airflow
- 进程启动模式（Bash/KubernetesPodOperator）：独立 JAR 进程，解耦、隔离，生产最常用
1. SpringBoot+Batch 内置 `CommandLineJobRunner`，启动时指定 Job 名称与参数：
    ```shell
    java -jar batch.jar \
    --spring.batch.job.name=syncUserJob \
    runDate=20260705 env=prod
    ```
    - runDate=20260705 会自动转为 JobParameters
2. 在Airlow DAG中定义
    ```python
    from datetime import datetime, timedelta
    from airflow import DAG
    from airflow.operators.bash import BashOperator

    default_args = {
        "owner": "batch",
        "start_date": datetime(2026, 7, 1),
        "retries": 2,
        "retry_delay": timedelta(minutes=3),
        "execution_timeout": timedelta(hours=3),
        "email_on_failure": True
    }

    with DAG(
        dag_id="daily_user_sync_batch",
        default_args=default_args,
        schedule_interval="0 2 * * *",  # 每日凌晨2点
        catchup=False,
        tags=["springbatch", "sync"]
    ) as dag:

        batch_task = BashOperator(
            task_id="run_sync_user_job",
            bash_command="""
            java -jar /opt/batch/app.jar \
            --spring.batch.job.name=syncUserJob \
            runDate={{ ds_nodash }} env=prod
            """,
            # 输出日志到Airflow，方便查看失败详情
            do_xcom_push=False
        )

    batch_task
    ```

3. 进程启动模式的优点
    - 进程隔离，崩溃不影响 Airflow；OOM、GC 问题只杀死当前批任务
    - 资源可控，大数据批可单独分配内存 CPU
    - 无需改造 SpringBoot 服务，打包即可运行
    - 每个 Job 独立元数据表，互不干扰，独立 JVM，互不影响

4. SpringBatch + GitLab CI/CD + AWS Airflow 完整串联流程（极简落地版）
    - 整体链路：代码提交 → GitLab CI 打包镜像 → 推送 AWS 镜像仓库（AWS ECR） → AWS Airflow 调度（该镜像的临时容器） Pod 运行 SpringBatch
    1. 开发提交代码到 GitLab 仓库
    2. GitLab CI 自动执行流水线：Maven 打包 → 构建 Docker 镜像 → 推送到 AWS ECR 镜像仓库
    3. AWS MWAA（Airflow）DAG 代码同步到 `S3 DAG 桶`
    4. Airflow 定时 / 手动触发 KubernetesPodOperator，拉取 ECR 内 SpringBatch 镜像启动批处理
    5. 批任务运行日志存入 CloudWatch，失败触发告警；支持历史数据回填
