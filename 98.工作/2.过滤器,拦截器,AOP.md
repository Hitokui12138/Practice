#
##
1. 执行顺序
    1. Filter.doFilter() 前置逻辑
        2. Interceptor.preHandle()
            3. AOP @Before（Controller方法）
                4. Controller方法执行
            5. AOP @After（Controller方法）
            6. AOP @AfterReturning（如有返回值）
        7. Interceptor.postHandle()
        8. Interceptor.afterCompletion()（视图渲染后）
    9. Filter.doFilter() 后置逻辑
2. 区别
    1. Filter
        0. 对所有 Web 请求生效
        1. Servlet 容器（Tomcat/Jetty）
        2. 请求进入 Servlet 容器后、DispatcherServlet 前
        3. HttpServletRequest/Response
    2. Interceptor
        0. 对Spring MVC 接管的请求(映射到 Controller 的请求)
        1. Spring MVC 层, 依赖Spring框架
        2. DispatcherServlet 后、Controller 方法前后
        3. Handler（Controller 方法）
    3. AOP
        0. 精准拦截指定包 / 类 / 方法
        1. 方法执行层（Spring Bean）
        2. Spring AOP/AspectJ, 代理
        3. 方法（参数、返回值、异常）
3. 典型使用场景
    1. Filter
        1. 全局跨域处理、请求`编码设置`
        2. 静态资源拦截、请求限流
    2. Interceptor
        1. `登录验证`、接口权限控制（基于 URL）
        2. Controller 方法参数校验、接口耗时统计
    3. AOP
        1. 事务管理、Service 层`日志 / 监控`
        2. 特定方法的异常统一处理

## HTTP请求与Servlet
1. 客户端发送HTTP请求
2. Tomcat创建 `HttpServletRequest`,封装所有请求信息
3. Filter拦截, 操作HttpServletRequest
4. DispatcherServlet接收到请求
5. HandlerMapper 匹配URL, 找到对应的Controller方法, 封装成`HandlerMethod`
6. Intercepter.preHanler取得 `HttpServletRequest`和`HandlerMethod`
7. 执行 HandlerMethod 的Controller方法
8. Controller调用业务方法, 返回JSON结果
9. Intercepter.postHandle
10. Intercepter.afterCompletion
11. Filter后置逻辑, HttpServletResponse
12. Tomcat将相应返回给客户端
