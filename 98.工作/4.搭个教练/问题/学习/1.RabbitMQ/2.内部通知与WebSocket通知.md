# 如何通知
1. 业务服务创建/变更通知后，不直接把 eventKey 发给前端，而是先发 RabbitMQ 消息
2. 发送时机是事务提交后（afterCommit），避免“事务回滚但消息已发”问题，
3. MQ 消息由 NotificationRabbitMQListener#onMessage 消费，按 eventKey switch 分发
4. 分发后才真正调用 WebSocketPushService.pushToUser(...) 推前端事件
5. 有幂等去重（创建类24h、未读变更2s）避免重复推送
6. 如果 MQ 关闭（skillup.notifications.enabled=false），服务层会走直推 WebSocket 的兜底路径，

# 通知什么（6个 eventKey 语义）
1. INTERACTION_NOTIFICATION_CREATED：有新的互动通知明细（点赞/评论/回复等）
2. INTERACTION_UNREAD_CHANGED：互动未读数发生变化
3. COURSE_NOTIFICATION_CREATED：有新的课程通知明细（下单/开课/结课等）
4. COURSE_UNREAD_CHANGED：课程未读数发生变化
5. SYSTEM_NOTIFICATION_CREATED：有新的系统通知明细（如审核结果/广播）
6. SYSTEM_UNREAD_CHANGED：系统未读数发生变化

# 收到后做什么（后端动作 + 前端应对）
1. 后端收到 *_CREATED：查库组装 DTO，然后推送明细事件（如 COURSE_NOTIFICATION），见 src/main/java/com/dgjl/skillup/component/mq/NotificationRabbitMQListener.java:197
2. 后端收到 *_UNREAD_CHANGED：重新计算未读数，然后推送未读事件（如 COURSE_UNREAD_COUNT），见 src/main/java/com/dgjl/skillup/component/mq/NotificationRabbitMQListener.java:223
前端收到“明细事件”建议：插入消息列表顶部（或按时间排序）并展示 toast/红点
前端收到“未读事件”建议：只更新 badge/unread 状态，避免每次全量拉列表
你关心的两个：
COURSE_NOTIFICATION_CREATED -> 前端收到 COURSE_NOTIFICATION
COURSE_UNREAD_CHANGED -> 前端收到 COURSE_UNREAD_COUNT
