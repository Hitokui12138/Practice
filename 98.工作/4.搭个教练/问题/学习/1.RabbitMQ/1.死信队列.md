# 死信队列 「延迟队列 + 死信机制」模拟实现定时功能
0. 一套配置队列
    1. skillup.queue.group.timeout.check.delay， 配合超时检查，用于延迟投递消息（比如延迟 N 分钟后再检查Group状态），同样带死信配置
        - D，DLX，DLK
        - 只是个延迟触发器
        - 首先会投递到 delay 队列，这个队列`没有消费者`（关键！），消息设 TTL、到期转死信到 check 队列
        - 消息在 delay 队列中超时后，会自动变成死信，通过绑定的 skillup.exchange.group.dlx 转发到 `check 队列`。
    2. skillup.queue.group.timeout.check, 超时检查
        - D，DLX，DLK
        - `有消费者`、处理超时检查逻辑、处理失败则进 dlq
        - 消费者监听到 check 队列的消息，只是说明 “消息在 delay 队列中`达到了预设的 TTL 时长`”
        - 此时做业务校验，判断业务上是否超时
    3. skillup.queue.group.timeout.check.dlq， 专门接收 check 和 delay 队列中变成死信的消息，用于超时异常排查、重试或告警。
        - D
        - dlq 是 check 队列的兜底
    4. skillup.queue.group.timeout.refund， 组超时后触发自动退款业务，带死信机制保证退款消息不丢失
        - D，DLX，DLK
    5. skillup.queue.group.timeout.refund.dlq， 处理退款失败的消息，用于退款异常补偿
        - D
0. 一套配置交换机
    - 最佳实践： 1 个主业务交换机 + 按模块拆分死信交换机
    1. skillup.exchange
    2. skillup.exchange.group.dlx， 专门处理「组超时检查」和「组超时退款」相关的死信消息。
        - 不同模块的死信消息路由到不同 DLX，方便后续排查和监控。
    3. skillup.exchange.notification.dlx， 通知业务的死信交换机（DLX），专门处理「消息推送」相关的死信消息。
1. 队列的Features
    1. D：Durable（持久化），队列会在 RabbitMQ 重启后自动恢复
    2. DLX：Dead Letter Exchange（死信交换机），消息过期 / 被拒绝 / 队列满时会转发到死信交换机
    3. DLK：Dead Letter Routing Key（死信路由键），配合 DLX 使用，指定死信消息的路由键
2. 消息变成 “死信” 的三种场景
    1. 消息`被拒绝`：消费者调用 basic.reject 或 basic.nack，并且 requeue=false（不重新入队）
    2. 消息`过期`：消息设置了 TTL（Time To Live），超时后未被消费
    3. 队列达到最大长度：队列满了，新消息或旧消息被丢弃（取决于配置）
    ```plaintext
    生产者 → check.delay队列（设置TTL，消息暂存）
          ↓（消息到期变成死信）
      组死信交换机（skillup.exchange.group.dlx）
          ↓（按DLK路由）
      check队列（真正的业务处理队列）
          ↓（处理失败/再次超时）
      dlq队列（最终的死信兜底队列）
    ```
