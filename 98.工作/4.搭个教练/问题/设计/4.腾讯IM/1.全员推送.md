3. 方案三：批量下发单聊系统消息 `服务端单聊`  希望用户进入`聊天列表`看到“系统通知”会话？ 请选 方案三。
如果您希望以“系统客服”的名义给每个用户单独发一条消息，使其出现在用户的私聊列表中。

- 实现方式：调用服务端 REST API：批量发单聊消息。
- 注意：单次请求最多支持 500 人，若全站用户量巨大，需要通过后台程序分批循环调用。

私密性：这些消息涉及个人订单隐私，只能发给对应的 UserID。
可触达性：用户打开 App/小程序后，能在消息列表的第一页看到“系统通知”或“商城助手”的会话窗口。
专业展示：支持使用自定义消息（Custom Message），将通知包装成精美的“卡片”样式（包含商品图、订单号、物流单号、点击跳转按钮等）。

1. 方案一：全员推送（覆盖全量用户，含离线）需要`手机通知栏`提醒？ 请选 方案一。
这是实现全站通知最标准的方式，适用于向 App 的所有注册用户发送系统公告或活动通知。

实现方式：调用服务端 REST API：发起全员/标签推送。
特点：
支持离线推送（需集成推送 SDK，如 TIMPush）。
无需创建群组，直接面向全量 UserID。
适合低频、高权重的全局公告。

2. 方案二：直播大群/系统通知群（覆盖`在线用户`）  类似直播间的全局弹幕/广播？ 请选 方案二。
如果您的通知主要面向当前在线的用户，或者希望用户在聊天列表中看到一个名为“系统公告”的会话。

实现方式：
创建一个 直播大群（AVChatRoom） 或公共群组。
将所有用户（或让用户自动）加入该群。
管理员通过 REST API 发送群组消息。
特点：
低成本：直播大群支持人数无上限。
实时性高：在线用户能即时收到回调。
会话感强：用户可以在群聊中查看历史记录。

4. 方案四：Web/小程序端 UI 通知 (TUINotification)
如果您是在网页或小程序中，希望实现类似`屏幕顶部弹出红条`的效果：

实现方式：使用 SDK 提供的 TUINotification 组件或监听 newMessageList。
逻辑：在客户端代码中监听来自特定 Admin 账号的消息，一旦收到，触发自定义的全局弹窗 UI。



# 方案3具体实现：
1. 服务端下发消息 (REST API)
由您的业务后端在`订单状态变更时`，调用 IM 的 sendmsg 接口。

发送者：建议设置一个固定的 Admin 账号（如 shop_manager）。
接收者：对应下单用户的 UserID。
消息类型：TIMCustomElem（自定义消息）。

2. 小程序端 UI 渲染
在您当前正在查看的 微信小程序 SDK 中：

监听消息接收回调。
判断消息的 type。如果是 order_status，则在聊天页面或消息列表中渲染出一个`带图标和按钮的卡片`，而不是普通的文本。

3. 离线通知（可选但重要）
如果用户此时没有打开小程序：

方案 A（IM 推送）：如果您有 App，可以配合 TIMPush 弹出手机通知栏消息。
方案 B（微信订阅消息）：由于您在做微信小程序，通常会配合微信原生订阅消息（微信外弹框提示）+ IM 消息（进入小程序后的记录展示）一起使用，体验最佳。



## 更具体
1. 准备管理员账号：系统通知必须由 App 管理员（Identifier）发起。您可以在 IM 控制台 > 基础配置 中查看或添加管理员。
2. 获取 UserSig：在服务端计算管理员账号的 UserSig（用于接口鉴权）。

构造 REST API 请求：
URL 格式：
https://console.tim.qq.com/v4/{接口路径}?sdkappid={AppID}&identifier={管理员}&usersig={UserSig}&random={随机数}&contenttype=json
https://xxxxxx/v4/timpush/batch?usersig=xxx&identifier=admin&sdkappid=88888888&random=99999999&contenttype=json
消息内容：推荐使用 TIMCustomElem（自定义消息类型），方便客户端解析展示不同的通知样式。
客户端接收：客户端通过监听 onRecvNewMessage (SDK) 接收消息并弹出系统提醒。


在腾讯云 IM 中实现系统通知功能，建议优先使用`单聊消息`（通过 App 管理员账号发送），而非纯粹的“单发推送”。
