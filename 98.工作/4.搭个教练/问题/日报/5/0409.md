这次“阅读量”相关我一共改了两条主线：**detail 实时计数** + **列表曝光异步计数**，并配了 **12h 回写 DB**。

- **detail 接口改为 Redis 实时 +1**
  - 在 `src/main/java/com/dgjl/skillup/service/impl/MomentQueryServiceImpl.java` 里，`/moments/detail` 命中缓存和未命中两条路径都会给 Redis 计数 `+1`
  - 使用 key：`su:moment:view:count:m{momentId}`
  - 同时写脏集合：`su:moment:view:dirty`

- **新增阅读量 key 定义**
  - `src/main/java/com/dgjl/skillup/component/cache/CacheKeys.java`
  - 新增了 `momentViewCount(momentId)` 和 `momentViewCountDirtySet()`

- **新增 12 小时回写任务（Redis -> DB）**
  - `src/main/java/com/dgjl/skillup/task/MomentViewCountFlushScheduledTask.java`
  - 默认 cron：`0 0 */12 * * ?`
  - 定时读取 `su:moment:view:dirty`，把对应 Redis 阅读量写回 `moments.view_count`
  - 回写成功后从脏集合移除

- **Repository 增加覆盖写方法**
  - `src/main/java/com/dgjl/skillup/mapper/MomentRepository.java`
  - 新增 `updateViewCount(id, viewCount)` 用于定时任务回写

- **Redis 工具能力补充**
  - `src/main/java/com/dgjl/skillup/component/cache/RedisCacheHelper.java`
  - 新增 `removeStringSetMembers(...)`，用于回写后清理脏集合成员

- **去掉原先 DTO 的“显示补偿 +1”**
  - `src/main/java/com/dgjl/skillup/service/impl/MomentAssemblerImpl.java`
  - 删除 `viewCount + 1` 的展示补偿，避免和真实计数叠加

- **列表接口增加“异步曝光+1”**
  - 生产端：
    - `src/main/java/com/dgjl/skillup/service/RabbitMQProducerService.java`
    - 新增消息类型 `MOMENT_LIST_VIEW_INCREMENT` 和发送方法 `sendMomentListViewIncrement(momentIds)`
  - 消费端：
    - `src/main/java/com/dgjl/skillup/service/RabbitMQConsumerService.java`
    - 收到该事件后遍历 `momentIds`，逐个执行：
      - `INCR su:moment:view:count:m{momentId}`
      - `SADD su:moment:view:dirty {momentId}`
