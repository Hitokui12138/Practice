    ```JSON

        "code": 200,
        "msg": "success",
        "data": {
            "userId": "123",
            "avatar": "https://example.com/avatar.jpg",

            "followingCount": 20,
            "followerCount": 30,
            "totalVisitors": 100,
            "starPoints": 88,
            "walletAvailableBalance": 199
        }
    }
    ```
    1. 优化方案
        1. 之前三个用户关系Count是分三次查询，现在用一个聚合查询只查一次
        2. 之前鉴权需要查询数据库users表，现在鉴权优先使用 token，缺失时回退查库
        3. 之前用一个TTL只有30秒的redisKey保存用户信息，现在延长到30天，仅在一些情况下更新这个Key
    1. redis用一个聚合属性保存这些数据
        - su:user:my:summary:u{userId}
    2. 以下情况需要及时更新baseline这个Key
        1. 用户更新个人资料
        2. 增加粉丝，减少粉丝（与此同时计算好友关系以及三个count字段）
        3. 星璇，钱包余额发生变化时更新
    3. totalVisistors数量不需要精确，单独维护一个hyperLogLog
        - su:user:visit:baseline:u{userId}（Long，首次从 DB countDistinct 写入）
        - su:user:visit:hll:u{userId}（HLL，后续 PFADD visitorId）
