# 接口概览
- 接口用途：返回“星球动态推荐流”，支持游标分页，返回 `list + hasMore + nextMomentId`。
- HTTP 方法：`POST`（只开放 POST，GET 会被判 405）。
- 路径：`/moments/recommended`（安全配置同时放行 `/api/moments/recommended`，常用于网关前缀场景）。
- 鉴权：可匿名访问（登录用户会获得个性化推荐与点赞态补全）。
- 代码入口：`src/main/java/com/dgjl/skillup/controller/MomentController.java:180`。

# 核心处理流程
- 实现在 `src/main/java/com/dgjl/skillup/service/impl/MomentRecommendationServiceImpl.java:107`
1. 一级分流：
  - `userId == null` 或全站动态总数 `< 50`：走“最新可见动态”策略
  - 否则优先尝试 LibRec 候选池（Redis）
2. LibRec 候选池：
  - key：`moment_librec_rec` + `su:rec:moment:librec:u{userId}`
  - 为空时可触发按需构建（受配置开关、最小交互行数限制）
3. 可见性过滤：
  - 最终会按“可见范围 + 黑名单关系 + 性别/关系条件”过滤（`MOMENT_SCOPE_RULE`）
  - 涉及范围：`PUBLIC/BUDDY_ONLY/STRANGER_ONLY/FEMALE_ONLY/ANONYMOUS`
  - 规则定义见 `src/main/java/com/dgjl/skillup/mapper/MomentRepository.java:23`
4. scope 混排：
  - 每页会尝试混入特殊 scope（搭子/陌生人/女性/匿名）后再补公共内容，避免全是同类内容
  - 用一个缓存key保存已经混排过的动态， 确保用户短时间内不会被同一个动态霸屏

# LibRec 候选池 原理详解
1. LibRec ItemKNN推荐算法
    1. 从下面这些表汇总数据，生成LibRec可读的UIR 文件（所有用户与所有动态之间的关系）
        - 项目第一次启动后执行一次，然后每隔24小时执行一次
        1. 评分规则
            1. （+1分）moment_view_history， 浏览动态（系统会跳过用户看自己动态的浏览记录）
            2. （+3分）moment_likes， 点赞动态
            3. （+5分）moment_comments， 评论/回复动态
            4. （+2分）moment_comment_likes， 点赞评论
            5. （-4分）moment_reports，举报动态则扣分
            6. （+2分）moment，user_interest_categories，用户感兴趣的话题
        2. 生成UIR文件
            - tmp/librec/moments-uirt-20260403134607.tsv
    2. 读取UIR文件，然后为每一个用户生成推荐列表（候选推荐池）
        - 每隔12小时更新一次
        - 缓存在 `su:rec:moment:librec:u{userId}` 里面
        1. 优先推荐评分>0的
        2. 若评分>0的不足，则用最新的动态填充
