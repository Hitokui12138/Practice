# ItemKNN = Item-based K-Nearest Neighbors
1. 基于物品的 K 近邻协同过滤
    1. UserKNN：找相似的人
    2. ItemKNN：找相似的内容

# 算法使用 LibRec 
## 1. LibRec 实现 ItemKNN 的 5 个核心步骤
1. 用户ID → 点击 → 动态ID (加载用户行为数据，生成UIR文件，读取UIR文件（还是说从缓存读取？）)
    - LibRec 会把它变成一个纯 Java 内存矩阵
    ```plaintext
        动态1  动态2  动态3  动态4
    用户1    1     1     0     0
    用户2    1     0     1     0
    用户3    0     1     0     1
    ```
2. 为了实现 ItemKNN (矩阵转置（变成 动态->用户）)
    - 把矩阵转成「动态 - 用户」矩阵
    ```plaintext
            用户1  用户2  用户3
    动态1    1     1     0
    动态2    1     0     1
    动态3    0     1     0
    动态4    0     0     1
    ```
    - 现在每一行 = 一个动态的用户点击分布用来计算：`两个动态有多像`
    - 两个动态被同一批用户点击得越多，相似度越高
3. 计算动态之间的相似度（核心）(计算所有动态两两相似度)
    - LibRec 用你配置的公式：
        - 余弦相似度（默认）
        - 皮尔逊相关系数
        - Jaccard 相似度
    - 生成一个`相似度矩阵`
4. 为每个动态找 K 个最相似的邻居( 对每个动态取 Top K 相似动态)
    - K是设置的 `conf.set("rec.neighbors.num", "50");`找50个
    - 比如 K=3：
        - 动态 1 的相似邻居：动态 2、动态 5、动态 9
        - 动态 2 的相似邻居：动态 1、动态 7、动态 10
    - LibRec 自动把每个动态的 Top K 相似动态 存到`内存`。
5. 给用户做推荐（最终生成结果）(为用户打分、排序、推荐)
    - 用户点击过：动态 1、动态 2
    - LibRec 做：
        1. 取出动态 1 的相似动态
        2. 取出动态 2 的相似动态
        3. 把所有相似动态加权分数累加
        4. `去掉用户已经看过的`
        5. 按分数从高到低排序
        6. 返回 Top N 推荐列表
        7. 分数越高 → 推荐越靠前

## UIR文本
- UIR 文本就是 LibRec 标准的「用户 - 物品 - 评分」纯文本数据格式，全称 User-Item-Rating，是推荐系统最基础的输入数据格式。
- 格式： 用户ID 物品ID 评分 时间戳
1. 评分规则
点击 = 1 （弱交互）
评论 = 3 （中交互）
转发 = 5 （强交互）
```
1001 2001 4 1712345678
1001 2005 1 1712345680
```

## 项目中记录用户行为的操作
1. （1分）moment_view_history， 浏览动态（系统会跳过用户看自己动态的浏览记录）
    - viewCount
    - viewedAt
    - lastViewedAt
    - viewSource （没用上）， 浏览来源：home-首页推荐，search-搜索结果，profile-个人主页，topic-话题页，other-其他
2. （3分）moment_likes， 点赞动态
3. （5分）moment_comments， 评论/回复动态
4. （2分）moment_comment_likes， 点赞评论
5. （-4分）moment_reports，举报动态则扣分

0. moment_interactions， 聚合互动状态（非自己互动自己）
    - 一条记录唯一对应一个 (moment_id, user_id)（唯一约束），用于记录该用户对该动态是否点过赞、是否评过论，以及汇总值 interaction_count
